**不可推断的坑（改转换器前必读）**
- PowerPoint 与浏览器首行竖向位置差随行高变：行高比 1.4 时重合，偏离越多差越大（实测标定 0.56/0.73×fs×(比−1.4)），已写进 `text()`；改字体或行距逻辑后要重标定。
- add_shape 自带 `<p:style>` 会带主题阴影，须删。
- 祖先 overflow:hidden 裁切 PPT 不认：超出的圆形/圆角纯图形改截图贴回，矩形直接裁几何。
- 单行文字按实际字位定位时首行缩进已含在 x 里，不能再设 indent（否则缩进翻倍）。
- 源图不缩会到 18MB：按显示宽 1.5 倍缩、透明图量化 256 色。
- PowerPoint 标点压缩使每行多容一两字，偶有「浏览器折两行、PPT 一行」，同框内分块的红字会留空隙（P21 旁批），属已知外观差。
- 点击分组：HTML 元素写 `data-anim="N"`（按详案师话序）→ 转换时出 `-动画分组.json` → inspect＋audit 后 `--merge-anim` 并入工作单 → animate 注入；审查闸门照旧生效。两栏页按「先左栏后右栏」必然回跳，须改上下排或同 top 并列（P19/P27/P7 实例）。
