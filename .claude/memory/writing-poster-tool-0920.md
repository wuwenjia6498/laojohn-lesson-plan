**四项用户拍板（改方案前先看这四条）**

2. 毛笔标题字＝下载 **OFL「Ma Shan Zheng」入库** `assets/fonts/`（一次性联网取工具件，用户授权；**以 woff2 存**——ttf 5.7MB 过不了 pre-commit 的 5MB 软拦，读取需 fontTools+brotli）；渲染时 fontTools 子集化只嵌标题几个字（html 0.8MB 而非 7.8MB）。**title 须避开全角 `＿＿`**，该字体无此字。

4. **独立 skill**（2026-07 用户定「写作课配套独立于读书会重设计」，course-poster 写作模式当时已删、不重开），只借 `_jpg_render.py` 同一条 JPG 引擎；**先出三上二一份样张验收，过关再批量**。

**Why（不可从代码推断的几条）**
- 文字层能全自动，是因为 `lesson-structure.md` §四 把首页/课时/环节结构锁死；24 份实测两个课时 H2 全恒定，但第 1 课时环节名各不相同（「打开思路」只在《写日记》），所以卡③第 1 行不能写死，只许 AI 用环节名短语微调。
- 副标题不在固定行号（11 份第 2 行、13 份第 3 行）、4 份无括号文体、1 份无空格——抽取按内容匹配不按行号。
- `.gitignore` 不能写 `写作课海报输出/**/*.jpg`，会把 `-插画.jpg` 一起吞掉；现用 `*-习作海报.jpg` + `*.候选.jpg` 两条。
- 本机 Git Bash 的 quoted heredoc 会把 `\` 折成 `\`，超长 heredoc 静默截断——脚本里的反斜杠用 chr(92) 或分两段写。

**⚠ 0922 再加一道工序：出图前先立意推敲（工序级 · 影响余下 17 份）**。四上五《生活万花筒》首版把题目里的比喻**当实体画**了——孩子举巨型万花筒、筒口喷彩色色块；用户拿外部评审意见反馈，判「理解得太实，视觉上对应题目，却把理解带到了『物品万花筒』，反而弱化了『生活』」。**根子不在画面写得好不好，在拿到题目直接写画面去生图、中间没有一道解题。** 现行工序＝**AI 先解题意、给 2–3 个画面方向（各带立意·画风编号·风险）并推荐一个，用户拍板后才写 subject 生图**（六上五那次其实已经这么走过一遍，这次写成规则）。三问（关键词是实指还是比喻／本课能力点是什么／遮住题目只看图家长会说这是在教什么）＋四条硬线（比喻题禁把喻体画成实体主体、主体对得上能力点、至少一卡能指认画面、遮题测试答出「一件物品」即作废）落在 `references/illustration-prompt.md`「出图前的立意推敲」节，**含一张作废台账**（否掉一个方向补一行，下次换图先看它）。留痕 `illustration._brief`：⚠ **必须嵌在 `illustration` 下**——`extract_fields.py` 重跑只拷回 `title/subtitle/cards/cta/illustration` 五个顶层键，顶层新键会被静默冲掉（**同一处顺带修了存量隐患：`theme_hue` 是顶层键、此前不在白名单，六上五手填的 18 重跑就会丢，已把它加进白名单**）。`_` 开头 ⇒ `_common._walk` 任意层级跳过，机检不扫。**脚本不加闸门、不加 `--candidates`**——立意错时生 N 张就是 N 张错图，方向筛选放在文字层零成本。⚠ **连带改顺序**：此前是「先定画风、再写画面」，现在是**立意 → 画风 → 画面**（画风为选定的立意服务：#258 擅长一个大场面，与「四处小场景散开」不合，才换 #128）。

**⚠ 文案母版 0921 再改版：三卡＝递进三层（现行）**。用户给《写日记》示例定盘：卡①**写作难点 · 教法**（痛点与教法合并，「不少孩子…」＋「教会孩子…」两段）→ 卡②**能力收获**（「告别…」起句）→ 卡③**成长收获**。形态同时从碎行短语改成**书面连贯整句**（`lines` 是整段数组、浏览器自动折行，禁手工断行），`head` ≤10 字（模板按字数自动缩字号保证单行）、每卡正文 ≤60 字。**卡③是唯一放宽口**：允许「这份真切，是成长里无可替代的宝藏」这类价值判断式表述、不必逐句反查详案；卡①卡② 仍句句来自详案。三上一/二/三/四四份已按新母版重写重渲，余 59 份沿用。

**卡③ 0921 晚改通栏独立块**（用户：「成长收获独立于前面二条，是精神生长升华类信息」）：卡①② 并列上排、保持纯色卡面；**现行＝三条竖排，均为「左标题｜竖分隔线｜右正文」横排**，第三条同结构异外观。⚠ **异外观不能靠换一种底色**——先做的「前两条色块＋第三条白底」被判「不协调」；**现行（0922 定）＝三条同一底色 + 无阴影**：`--tone-a`（明度 .83，由取色注入，缺省 #EEDAB8），三条一律**去 box-shadow、纯色平铺**（底部橙色报名条的阴影保留，它是行动点）。第三条**不靠底色区分**，只靠左缘 6px 橙条＋橙调栏目名带短横线＋标题不挂深棕竖条＋多 12px 间距。⚠ **底色分档这条路走过三轮全被否**：白底（不协调）→ 三档递进（.855/.815/.775）→ 两档略深（.83/.785）→ 同色。**别再提议用底色深浅区分层级。**左栏统一定宽 380px（**三条竖线靠它对齐，改定宽就错位**），标题 36px 封顶按 374px 自动缩，正文 24px 排右栏、每条 ≤70 字。

⚠ **版式走过三版，后两版都是被高度逼出来的**：① 三卡并列（4928px）→ ② 两卡并列＋卡③ 竖排居中通栏，用户否「太占位置、海报被拉长不少、也不紧凑」（5554px）→ ③ 卡③ 改横排（5138px）→ ④ 用户定「前两张也做成这个样式，三张竖下来，第三张做出区别」＝现行（5024px）。**结论：横排比竖排省，三条同构比混排还省**，别再回竖排居中。**判据是层级不同，不是好看**——前两张答「怎么教／学会什么」，卡③ 答「为什么值得学」。JS 按 `kind === 'spirit'` 分流外观，**改 kind 命名会让第三条掉回纯色卡样式**。

**版式 0921 同步改：卡片叠压插画**（用户给初版海报截图作参考——插画与卡片连成一块，不是上下两段）。落法＝插画基准高 720→920px、`.cards` `margin-top:-140px` + `z-index:2` + 加重阴影；无图时 `.illu.empty + .cards` 回落 4px 不重叠。（图钉圆点试过一版，用户否掉，已删。）**插画须同时放大，压一截才有意义**——新增可选字段 `illustration.zoom`（缺省 1＝920px，JS 覆盖容器高；`object-fit:cover` 下容器越高图越大、左右微裁）与 `illustration.focus`（object-position）。**实测区间 1.05–1.2**：三上一 1.2／三上二 1.15／三上三 1.05／三上四 1.1；**1.25 会把画面裁到页边、水彩淡出边被切出硬边**（三上四实测，已回调）。定值判据＝四周留白多的调大、满幅到边的调小。**连带约束：`illustration.subject` 的画面主体要落在上 2/3**，下缘 140px 会被卡片遮住；主体被盖的正确动作是改 subject 重生图，**不是改模板重叠量**（63 张统一版式）。

**底色 0921 改「浅淡呼应」**（用户问底色能否跟插画走）。**主底奶油 `#FFF6E3` 不动**——插画生图背景写死同色，一换整页底色插画就露出色块，要换得连插画一起重生，已否；改的只是装饰层：两处径向光晕 + 牛皮纸卡色相，由 `render_writing_poster.py` 的 `illu_hues()` 从插画自动取色注入（`/*__THEME__*/` 覆盖 `:root`）。⚠ **自动取色区分度实测很弱**：取的是面积最大的高饱和色，常落在皮肤／木头／砖墙上，四张插画自动结果全在 24–35° 暖橙，摆一起几乎看不出差别。**顶层 `theme_hue`（0–360）手填才拉得开**，实测童话菜园 85 绿、教室场景 205 蓝明显更贴画面，已落这两张；另两张（三上一/二）本就是暖调，留自动。取色带排除逻辑（`0.055≤h≤0.17 且 s<.62 且 v>.72` 的纸底木色带排除），改它前先想到这条，否则又平均成同一个橙。

## 0922 六上五《围绕中心意思写》出图（第 5 张，也是第一张六年级）

用户流程与前四张不同：**先让 AI 给几个插画场景选项、用户挑定，再由用户指定风格编号**。四选项来自详案（示范文关键一刻／示范文结尾／审题辨析正例／四人轮读），用户选了示范文详写段那一刻；风格指定 **#105 Fast Family-Essay Sketch**（よこみねさやか，家庭 essay·快速线稿），一次判读通过，参考图 `105.webp` 首次使用、已入库。

**文案改了两轮，两轮的病不同，都值得记：**

1. **第一轮「AI 腔」**——用户只说四个字，实际命中五处：卡① 抄了三上二的「悉数记录」（跨课同构）；卡② 「告别三件事一样长」是课内生造搭配；卡③ 「先立主帅，再点兵」对仗梗＋「这份取舍的定力」名词化升华；副题与三上一「不写名字，也让人猜出他是谁」同句型；CTA 里「中心明确」当时被我当术语砍掉了。

**⚠ 编号风格首次「没画对」的三连修（0922，改的是 `gen_illustration.py` 的编号分支，影响此后所有带编号的图）**：

用户说「风格和选定的不一致，也没画出忙碌的表情，背景淡黄不好看」，查下来是**三层叠加**，一次只改一层会来回打摆子（实测摆了三版）：

1. **编号分支的人物约束压平风格**：`FIXED_CONSTRAINTS` 里那句「形象简洁亲切、**不夸张**」把风格库的人物类特征（脸型／头身比例／表情自成一套）直接抹平，出来是通用精修水彩脸。同时风格特征里那半句「避免回落为统一的标准 Q 版表情」被 `_positive_traits` 按含「避免」滤掉——两头一夹，编号形同虚设。**改法**：拆出 `STYLED_CONSTRAINTS`，编号分支改说「脸型／头身比例／手脚形状／表情一律服从上述风格特征，不要回落成通用写实画法」。
2. **编号分支根本没有「要上色」这条**：通用分支的「水彩平涂」写在 `STYLE_PREFIX` 里，编号分支不经过它。#105 特征带「快速线稿」，没有颜色约束兜着就直接出**黑白单色线稿**，放进暖色卡片的海报里整张发灰。**改法**：新增 `_COLOR_STYLED`「整幅为彩色……不要黑白线稿、素描或单色画面」，只加在编号分支。凡特征带「线稿／速写／素描」的编号都吃这一条。
3. ⚠ **我自己补的负面词反向踩雷**：第 1 条里我一度照抄风格库原话写了「不要回落成……统一的标准 Q 版表情」，而 #105 的参考图本身就是**圆脸可爱那一路**，这句话把它推去了写实苦脸（龇牙出汗）。**教训：风格库那句 Q 版负面词是通用措辞，对可爱系编号是反向的，不要原样搬进本工具的固定约束。**

**表情别用「眉头皱着」描述忙碌**：写进 subject 就出痛苦相，招生件不能用。改成动作叠加（手机夹肩＋两手扎头发＋眼睛瞟着锅里）＋一句「一脸忙不过来的神情」，出来才是忙而不惨。

**⚠ 「页面上半发黄」不是插画的事，也不是 `punch` 的事（0922 用户纠正）**：我第一反应去调 `punch` 把插画调淡，方向错了。页面上半那片黄来自 `#page` 的**两个 radial 光晕层**（左上 8%/4%、右上 92%/22%），底色渐变本身只是奶油。**改法＝压光晕**：渲染脚本 `_hsl(hue,.78,.80,".50")`／`(.70,.88,".42")` → `(.68,.89,".26")`／`(.60,.93,".22")`，模板缺省 `--glow-a/b` 同步压淡。主底奶油 `#FFF6E3` 一律不动——它要和插画烘焙进去的底色对齐，动了就出接缝。**再想更白只剩基底渐变第一个色标，但那会和插画的 `#FFF6E3` 露边，别动。** 这是母版级改动，24 张通用；已出的 4 张重渲即可跟上（html/jpg 本就 gitignore、从 json 重生）。
