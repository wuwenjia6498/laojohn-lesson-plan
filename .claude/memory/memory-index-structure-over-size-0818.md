2026-08-18 用户问「MEMORY.md 太大是不是影响生成质量」，实测后重构。**结论：影响存在，但瓶颈不是体量，是结构倒挂。**

**实测数字（重构前）**：MEMORY.md 18,520 字符 / 155 行 / 180 条链接 ≈ 13k tokens；CLAUDE.md 15,134 字符；常驻合计 ≈ 25k tokens = **1M 窗口的 2.5%**。memory 目录 178 文件 / 644KB（按需加载，不占常驻）。索引↔文件一致性良好（零真孤儿），坏账仅 9 处已作废标记。

**三个真病灶**：① **预算与频率倒挂**——单课次/单本书的一次性状态占索引 **64.6%**（84 条，单条命中率 <5%），而每会话都生效的「用户偏好+跨技能硬约束+架构速览」只占 **8.6%**；② **「必读」通胀**——55 处「…前必读」，一半以上条目都标，等于没有优先级；③ **增速**——[[context-engineering-slimdown-0727]] 记录 0727 瘦身后是 9,847 字符，21 天后 18,520，**涨 88%**。

**最值钱的发现：横向通则正埋在单课次状态条目里。** 扫 `通则|照此办|可照搬|已升通则` 抓出 12 条（开场姿态别编懊恼、把限制变成设定、当场换人试装、示范文逐字比对、只点一种＝默认款、禁拼贴涂胶、示范例文念两版、人人开口须数、结果词与牙齿、五官返工回生成端、左右改位置式、全角＿＿认领失败）。**它们只有「改这课前必读」时才读得到，而本该在写任何同类课次时就生效。** 这是当前索引最实在的质量损耗，比体量严重得多。

**⚠ 反直觉的实测结果：分层重构后字符数不降反增。** 18,520 → **19,356（+4.5%）**，行数 155 → 152。原因是通则上浮（+2.2k）、区头必读行（+0.6k）、未决事项区（+0.6k）合计是**有意的净投入**，大于状态条目压缩省下的量（39 条压成 5 个聚合行，省约 2.9k）。计划里定的「降到 13k」目标是错的，已作废。

**Why:** 索引里 115 条规则型条目（约 12.4k 字符）的钩子已不是纯指针，而是压缩过的规则正文（如「半角 `____` 会被 docx 引擎当加粗标记静默吃掉」）。这违反 memory 规范，但**有真实收益——不打开文件就守住了规则**。要到 13k 必须砍这部分，而那只省 0.3% 的窗口，却直接损失防复发能力。**病灶是「坏」和「乱」，不是「大」**（与 0727 那次的判断一致）。

**How to apply:**
1. **不要再拿字符数当 MEMORY.md 的优化目标**。真要评估，看三件事：单课次状态占比、「必读」是否泛滥、通则有没有被埋在状态条目里。
2. **新发现的横向通则一律写进各线「跨课次通则」块，不要埋进课次状态条目**——判据是「这条经验换一个课次还成不成立」，成立就是通则。
3. 新增课次/单本书状态直接进末尾「已交付归档」聚合行，钩子 ≤20 字，不单独占行；未决/交付风险进「未决事项」块，做完即删。
4. 行内不标「必读」，优先级集中在各区头那一行（现 6 个区头，行内残留 4 处）。
5. **改索引后必跑四项验证**：字符/链接对账、通则不丢 grep 对账、孤儿与死链差集、5 个高频开工场景抽样（后者是唯一真正的功能测试）。本次 12/12 通则在、零孤儿零死链、177 文件全覆盖、5/5 场景命中。
6. 顺带修掉的坏账：神笔马良曾有两条索引行指向同一文件（已合并）；`scratchpad` 里的备份会被临时目录清理，**别依赖它做回滚凭据**。

## 同日续：CLAUDE.md 按同一套思路审了一遍（结果相反——真能降）

**15,014 → 13,182 字符（降 12.2%）**，120 行不变，只碰 3 个文件（CLAUDE.md / README.md / laojohn-ppt/SKILL.md）。同样是倒挂：§3「共享资产」一节占 **39.9%**，装的是改某个脚本时才需要的实现细节，而每次动笔必读的 §4+§5+§8 只占 26.5%。压完 §3 降到 34.1%。

**⚠ 最值钱的判据（以后每次都用得上）：共享脚本的 docstring 才是实现细则的天然唯一源，比 references/ 更好。** 实测 `insert_images_docx.py`、`style_front_page.py`、`profile_meta.py`、`_jpg_render.py`、`_a4_render.py`、`helpers.py` 的头注释**都已完整覆盖** CLAUDE.md 里的对应细节，而且反向写着「见 CLAUDE.md §3」；`writing-materials/SKILL.md` L52 的 Type3 红线比 CLAUDE.md 那格还详细。所以那些内容是**纯重复、可直接删**，根本不需要新建 references 文件搬家——**零埋雷风险，因为改脚本时 docstring 就在眼前，而 references 未必会被加载**。下沉前先 `head -20` 看一眼目标脚本，别急着建新文件。

**同理先验证覆盖再删**：CLAUDE.md 那段 600 字符的 PPT profile 说明，对 `laojohn-ppt/references/architecture.md` 逐条核对是 **9/9 全覆盖**（纯双写，压成指针）；1,700 字符的写作课 PPT 链对 `laojohn-ppt/SKILL.md` 是 **14/16**，缺的两条（「写作课停用 build_ppt」「读书会线不适用」只是隐含、无显式声明）**先补进 SKILL.md 再压 CLAUDE.md**——这两步顺序不能反。

**修掉的坏账**：① `templates\` 实际在 reading-sheet **skill 根目录**下，CLAUDE.md §3 写成了 `scripts\` 下（硬错误）；② **README ↔ CLAUDE.md §7 双向循环指针**——README 写「见 CLAUDE.md §7」、CLAUDE.md 写「权威表见 README」，两边互指对方是权威；已定分工＝README 管完整对照表、§7 只留「命名错了下游会静默失效」的硬约束；③ 历史沿革混在硬约束里（四维改制三段沿革、Playwright 病史），压成现行结论一句。

**验证法（四项，与上半条同构）**：19 条红线逐条 grep 对账全在、19 条路径复验零缺失、分节占比重算、`git diff --stat` 确认改动范围。**红线宁可多留**——本次因保守保留红线，降幅从预估 25% 收到 12.2%，这个取舍是对的。

其余验证通过、无需再查的：46 条脚本/references 路径除 templates 外全有效；11 个顶层目录与描述一致；「写作课件讲稿输出\」确实已撤；§3 尾注称仍在的 3 处历史副本确实都在；§6「俗世奇人下五份 json」准确（那里 6 份，第 6 份反馈话术不走那三条共享渲染链路）；与 MEMORY.md 现行口径抽查 5 处无冲突。
