2026-08-18 立项，为减轻加盟商老师批改负担。**当前进度（0820）：Phase 0 物料待发；Phase 1 稿纸改造已完；Phase 3 网页前后端骨架已完成、mock 全流程跑通，但真实模型调用一次都没跑过。**

## 三条不可推翻的判断（方案地基）

1. **批改判据不用造，详案里现成**：`〔三档标准·教师掌握〕`、`〔修改符号说明〕`、`〔教师示范·…〕` 都是固定标签可机器定位；最有用的是第2课时评改环节师话里那句「改之前，我们先看三条」——**学生当堂听过，批语可直接引用原话**。这是相对通用 AI 批改工具的唯一护城河（能说「你没做到今天课上讲的那一招」）。故架构＝总部离线出**标准包 JSON**，加盟商端只消费 JSON、**不接触详案全文**。
2. **输入端受控是技术命门，改稿纸比调模型有效**：学生写在总部统一版式的 18 列格子稿纸上，是受控表单不是自由版面。已据此加姓名栏与备用续页（见 [[writing-materials-pages-trimmed-0803]]）。
3. **错别字层原理上不能做，且必须写进产品说明**：多模态读手写稿会**自动纠正错别字**（「高心」→「高兴」）、把看不清处脑补通顺，这不是调参能解决的。字词/标点/卷面归老师，内容与技法归工具。同族风险＝批语评价的是脑补出的作文，与仓库既有「伪摘录禁令」同类，硬防是转写稿回显给老师核对。

**手写识别不用再测**（用户 0819 拍板：此前已有相关尝试、没有问题）。注意区分两件事：**「识别准」≠「错别字保真」**——模型能正确读出内容（已验），但学生写「高心」它会读成「高兴」、读出来反而更通顺，这类错**看起来不像错**。好在产品本来就不批错别字，风险已被设计规避，故结论成立、不必再验。**据此已简化流程：不再要求把整篇转写贴给老师核对**（老师手上有原稿，看打字版是浪费时间），只在①有字看不清、②引用原句时才要求贴原文。

## 已定的形态与栈

- **不能是 skill**（用户 0818 明确否掉）——面向全国加盟商分发。不做小程序（教育类目审核＋发版周期）。
- **PWA 的正确拆法（0819 修正，此前一刀切说「不做 PWA」是错的）**：PWA 不是 H5 的替代品，它就是网页＋三样东西，要**拆开判**——① `manifest.json`（桌面图标／全屏／`display:standalone`）是**纯声明的填空表、成本几乎为零，要做**，换来的「像个 App」对加盟商观感有实际价值；② HTTPS 本来就要有；③ **service worker 先不做**——离线对批改毫无意义（必须联网调模型），而它的缓存会让**老师一直看到旧版本**，恰恰撞上上线初期频繁改文案的场景，且对非技术用户根本没法远程排查；产品稳定后随时可补。
- **微信内置浏览器不给 PWA 安装入口**，这条属实，但只影响第一次：说明里写「右上角 → 在浏览器中打开 → 添加到主屏幕」。**安卓会主动弹安装提示，iOS 必须手动点分享 → 添加到主屏幕**（iOS 的 PWA 支持整体弱一档，但我们只要「添加到主屏幕＋全屏」这两样，是稳的），iOS 那步要配截图。
- 前端单页 HTML＋原生 JS 不引构建工具；后端单文件服务放国内轻量服务器（**密钥绝不能进前端**）；模型复用 AiHubMix 网关；**MVP 不留存作文原图与全文**（未成年人数据责任，不存就没有）。
- **二维码已论证不做**：老师批一个班是同一课，选一次即可，不需要每张照片自动识课。
- 关键路径最长的一环是**域名 ICP 备案**，与开发并行推进。

## 已产出（`作文批改工具/`，源入库、生成件 gitignore）

`build_prompt.py`（标准包 JSON → 可直接粘进任意 AI 的提示词）＋ `Phase0试用包/_批改提示词模板.md` ＋ 两课标准包（三上第一单元猜猜他是谁／第二单元写日记）＋ 给加盟商的试用说明 ＋ `效果样例_猜猜他是谁.md`（三篇**模拟**习作与对应批改输出，已显著标注非真实学生作品；兼作老师判断「有没有跑偏」的对照物）。

**schema 已验出的三个坑**：《写日记》三条判据的第一条是「日期星期天气写齐没有」——是格式，却属本课要教的技法，与「不判格式」边界直接打架。已加 `not_in_scope.exceptions` 字段，提示词渲染成醒目的「但这一项要判」。**后续凡含格式类技法的课次（书信、倡议书、研究报告）都会撞上。**

② **模板里绝不能写死课次特有内容**（0819 自测抓到）：第 2 步「对着三条判据判断」当初照《猜猜他是谁》把三条写进了模板，于是《写日记》那份的上半段是日记判据（格式／一件事／心情）、下半段却是写人判据（特点／换名字测试），**两套自相矛盾且 AI 大概率照错的那套走**。已改为「按上面第二节列出的那三条判断」，判据只从标准包渲染一次。**新增任何模板文案前先问：这句话换一课还成立吗。**

③ **判据之间可能有依赖**：《猜猜他是谁》第②条「围绕这一处写具体」以第①条「特点抓着没有」成立为前提——主特点都没有时②无从判起。标准包加了 `depends_on` 字段，渲染成「须第 N 条先成立；不成立则本条记「不适用」」，模板配通用兜底规则（改进方向落回第 N 条）。**依赖是课次特有的**，《写日记》三条各自独立、无依赖，不要照抄。

## Phase 3 网页应用（0820 建，代码在 `作文批改工具/web/`）

单文件 FastAPI + 单页原生 JS，闭环＝选课 → 连拍 → 逐份出结果 → 改批语 → canvas 出点评卡图 → 班级诊断。红线与用法见其 `README.md`，此处只记**不看代码就想不到的三条**：

- **判据渲染 importlib 复用 `build_prompt.py` 的 `render_pack()`**，与 Phase 0 共用一份——全仓「真源＋薄壳」的老做法。改判据改标准包 JSON，改措辞改那个函数，**服务端不许再长出第二处判据**。
- **逐份串行、且把已生成的点评卡开头喂给下一份（`prev_heads`）**——这是防同质化的机制载体。改成并发这道防线就静默失效了，而它失效不会报错、只在三十份发出去以后被家长看出来。
- **前端下发的是精简版标准包**（只有三条判据的题目、档位名、不判项），完整判据文本留服务端——加盟商侧不接触详案全文这条在代码层落了实。

**批的是四层，别只批判据（0820 二改）**：只对着三条判据批，会漏掉整篇的完整性、逻辑、流畅度，也看不见学生自己用得好的词句——**三十篇批出三十条一个样**。现在是：

| 层 | 干什么 | 进档位 |
|---|---|---|
| 三条判据 | 这次课教的学会没有（护城河） | **是，档位只由它定** |
| 整篇三项（完整性／顺序／读不读得通） | 更底下的地基：半截停住、前后跳、句子绕不出来 | 否 |
| 亮点 | 他自己用得准的词、有意思的句式、别人想不到的观察 | 否，是点评卡原料 |
| focus | 这一篇最值得说的一件事，决定点评卡从哪切入 | 否 |

**真正治模式化的是 focus 不是加维度**——原先每篇都从第一条判据说起，那才是根源。配套三条约束缺一不可：① 亮点**允许一条都没有**（硬凑是假话，家长看得出，与「写得弱的不要硬夸」同源）；② 整篇三项**不进档位、也不直接跟家长说**（「你孩子逻辑乱」不是能发群里的话）；③ 点评卡**只说 focus 那一件事**——多了维度就往里塞，面面俱到本身是另一种模式化。

**判断规则已收成共用件**：原本 Phase 0 模板与服务端 `GRADE_RULES` 各写一份措辞，改一处不改另一处必然分叉且不报错。现抽成 `build_prompt.py` 的 `judging_rules(pack)` / `parent_card_rules()`，两条线 importlib 共用，与 `render_pack()` 同一做法。**边界：只放跨课次通用规则，课次特有的一律走标准包 JSON**——往里塞任何一课的具体内容，就是重蹈「模板写死《猜猜他是谁》三条判据」那次的覆辙。

**真实链路已验（0820）**，用效果样例三篇模拟习作渲成格子稿纸当基准，gpt-4o 与 gemini-2.5-flash 各跑数轮。五条经验：

1. **引用一字不差不能靠模型自觉**——两个模型**都**在复述时改写原句（漏字「可是过了一会儿」→「可是一会儿」、加字「说：」→「他说：」、全角逗号写成半角、用省略号把相隔很远的两处拼成一句）。提示词按不住，这是复述本能。**解法是工程手段**：模型先输出整篇 `transcript`，服务端 `fix_quotes()` 拿它当基准把每处引用对回原文，省略号跨接与查无此句一律拒绝并标 `_suspect`、前端显红。判据是 `cover`（总匹配率）+`span`（区间长度）两道门槛，**偏保守是有意的——宁可多标可疑，也不能错误校正成原文里的另一处**。`transcript` 只用于校验、不下发。
2. **thinking 模型的思考 token 计入 completion**：gemini-2.5-flash 实测正文 1390、思考另占 1785，max_tokens 1600 会让 JSON 从中间断掉，而报错是「没有返回可解析的 JSON」——**会让人往提示词上找错**。已提到 8000 并让 `call_model` 认 `finish_reason=="length"` 明说是截断。
3. **「跟家长说话」这条要连着防模板化一起写**：只说「跟家长说」，flash 立刻变成每篇「××家长您好」、gpt-4o 变成每篇「孩子写到…」——**约束一收紧，模型就找一个新模板躲进去**。
4. **判据的 judge_by 要给量化门槛**：原先只问「有没有画面」，两个模型都把「只有一处、一两句带过」判成达成。已加「几处／展没展开」并明确**什么不算一件事**（「她笑起来很好看」是评价不是画面）。`judge_by` 是操作化说明可改，`three_checks[].text` 逐字取自详案师话不可改。
5. **模型选 gpt-4o**：引用准确率与点评卡口气明显优于 gemini-2.5-flash（后者转写漏字、标点半角、对着学生说话）。flash 唯一强项是姓名 3/3 读对，但**姓名前端可手改，引用错不了才要紧**。

**回归工具已固化**：`make_test_sheets.py`（三张基准稿纸，产物 gitignore、可重生成）+ `run_regression.py`（自动核引用逐字／判据方向／`depends_on`／起头撞不撞／有没有越界提错别字）。**改提示词、换模型必跑。** ⚠ 素材里埋的错别字「经长」模型必然读成「经常」，脚本 `TYPO_READ` 会先规范化再比对——**那是预期行为，别当 bug 修**。

**选课页按数量自动变形（0820）**：63 课 8 册规模下平铺没法用，但两课摆折叠面板是给自己加戏——所以 `renderLessons()` 按课次数量切形态（≤6 课或单册＝平铺；更多＝按年级册折叠；≥8 课出搜索框；搜索时平铺）。配「最近用过」置顶（localStorage，老师批一个班是同一课）。三个坑：① **排序绝不能用文件名**——`sorted(glob)` 会让「第十单元」排到「第二单元」前，改用 `lesson_id`（`3a-u1`）解析出的三元组；② **从批改页返回必须重渲选课列表**，否则刚选的课要等下次冷启动才进最近区；③ **只显示有标准包的课**，不要从 course-map 读全 63 课再标「未接入」——老师看到 63 课其中 61 课点不动，是糟糕的体验。

**剩余**：OCR 偶发漏字与姓名读错（模型能力，fix_quotes 救不了，影响面是少数几处标可疑）。为此写了 `server/smoke_real.py`，配好密钥后拿一张真稿纸直接打模型，自动核「三条判据齐不齐／点评卡有没有真引那一句／字数／姓名读不到时是否留空」，并列出机器判不了须人眼看的三条。**这是 Phase 3 的第一件事。**

mock 全流程用 Playwright 按 iPhone 视口跑过并逐屏截图核对，抓出四个真 bug（`hidden` 被 `display:flex` 覆盖导致整页点不动、`font` 简写里塞 `inherit` 使输入框掉回等宽字体、档位配色语义倒置、点评卡换行缺中文避头尾）。**教训：这类 bug 静态读代码全看不出来，移动端页面必须真跑一遍看图。**

## 铺课到 9 课 + 抽取固化（0821）

**起因是一个假 bug**：选课页看着还是流水式两条。前端没坏——`renderLessons()` 的 `flat = kw || 课次≤6 || 只有一册` 是 0820 定的设计，两课同册必然平铺。**真缺口在数据侧**：详案有 14 篇、标准包只抽了 2 份。凡再遇到「首页形态不对」，先数 `标准包/` 里有几个 json，别去读前端。

**现状**：**14 课全覆盖**（3a5／3b1／4a4／5a3／5b1），5 个年级册。排序、折叠分组、搜索框、最近用过均实测生效。全部 `verified_by_human: false`——**已定：先不核**，Phase 0 只发《猜猜他是谁》，等 judge_by 定稿再一次性核（text 那层逐字来自详案、不会因反馈变动）。

**新增两件，抽下一课直接照做**：`作文批改工具\标准包抽取规程.md`（判断）+ `validate_packs.py`（机检，跑到 0 失败才算完）。每课另出一份 `标准包核对清单\<课次>-核对清单.md`。**不做成 skill 是有意的**——最难的部分是判断不是流程，写进 skill 会被当成已自动化而不再复核。

**四条踩出来的坑**：
1. **「三条」在不同详案里不是同一样东西**——《这儿真美》《我和＿＿过一天》的「三条」指档位表，四上「三条标准」是档位、「三处内容」才是判据。固定串「先看三条」9 篇里只有 1 篇命中。**只能通读第2课时判，写不了自动抽取脚本**，机器只能做事后逐字命中比对。
2. **四上的修改收束普遍是反面条件式**（「如果段落里只有…」），砍掉动作后判据方向就反了，模型必判反。解法：去详案另找同义正面原话，`〖PPT · 自由写作〗`下的「盯住这几样」师话是最好用的第二锚点（学生动笔前刚听过、正面陈述）。已连撞三课。
3. **bands 键名必须归一到 `基础过关/良好达标/优秀进阶`**：四上各课档名是自创的（写成了／写得让人想去／人设贴合），而前端 `bands.indexOf(r.band)` 是精确匹配，对不上则汇总页**三档全计 0 且不报错**。档位文字仍逐字照抄，原档名记进 notes。
4. **一个包 JSON 语法坏掉，整个服务起不来**（`load_packs()` 直接抛异常，不是跳过那一课），且报的是 traceback 指向 main.py。`validate_packs.py` 已先逐包解析再载服务端，能指出是哪个包。**改完 JSON 必须重启服务**——`--reload` 只监听 .py 不监听 .json。

**新课不进 `run_regression.py`**：它硬绑 `3a-u1`，那三张基准稿纸是为《猜猜他是谁》刻意设计的。分层＝模型回归只跑 3a-u1 当哨兵，新课覆盖面由 validate 的 render_pack 冒烟承担。


## 真机实测与上线前补洞（0821 续）

**实测方式**：`smoke_real.py` **不绑课**，传 lesson_id 就能跑任意一课，只吃一张图、一次调用。新课**不要**动 `run_regression.py`（它硬绑 3a-u1，EXPECT/TYPO_READ 都是为《猜猜他是谁》设计的）。造模拟稿纸用新写的 `make_sheet.py`（importlib 载入 make_test_sheets 后在本进程内改 PIECES/TITLE，**不改原脚本**——改了会毁掉那三张回归稿纸）。素材写在 SHEETS 里跟着仓走，实测结论只有连着素材看才有意义。

**judge_by 立了两条写法通则**（拿《写观察日记》埋三处实测出来的，已进规程第二节）：
1. **放宽类条款必须前置到判定最开头**。「第一则没有对比对象、不要按缺对比扣它」写在末尾的「什么不算」段里，模型**100% 读不到**——它读到中间的三级门槛就下判断了。提到最前面写成独立分支后，同一张稿纸重跑立刻改口。**收紧类（X 不算达成）放末尾没问题，放宽类（X 不扣分）必须前置**，两类别一锅端。
2. **判「逐项齐不齐」要先让模型把各项抄出来再数**。不写这句时它笼统答「第一则和第二则没标天气」，而第一则明明写着「晴」——**这条错直接进了家长点评卡**。笼统判断出的事实错比判错档位更伤：档位错老师看得出，事实错会被当成真的转给家长。

`smoke_real.py` **不跑 fix_quotes**，它偶报「点评卡没引到那一句」不代表真实链路有问题（`/api/grade` 有兜底）。三次实测里出现一次。

**14 课抽下来的形态规律**：四上三课、五上前两课的修改收束都是动作式／条件式，判据要去**自由写作前那段「盯住这几样」**取（Tier A 第二锚点）；但五上《缩写故事》的修改收束是问句式可直接用——**不要预设某一册都是同一种写法**。另有三种别课没有的形态：链式 depends_on（三下）、反向问句判据（《缩写故事》第②条，达成＝没有）、档位表从好到差排（《缩写故事》，归一化要倒序映射）。

**上线前补了三处代码**（`部署说明.md` 是新写的，仓里原先没有任何部署文件）：
- **无密钥静默进 mock 是最危险的一处**——忘配密钥服务照常起、发结构完整的假批语、不报错。现加 `LJ_ENV=prod`，生产模式无密钥拒绝启动；本地不设该变量行为不变。
- `/api/diagnose` 原先**完全没有限额**（它也是真实模型调用），现与 grade 共用一个桶。
- 反代下 `request.client.host` 会变成反代 IP、全站共用一个桶，新增 `_client_ip()`：默认只信直连，显式配 `trust_proxy` 才读 XFF 最左一跳（该头可伪造，没反代时开它等于敞开限额）。
- **限额仍是内存版，所以只能单进程跑**；按校区账号计额度仍未做。


## 本机暂存 IndexedDB（0821 加 · 隐私口径由此拆成两层）

**起因**：帮助面板那句「批完不留底，图和作文都不存」自相矛盾（同一面板上一条还说点评卡长按保存），查下来更要紧的是 `S.items` 是纯内存的——**批一半被打断，三十份全部重来**。

**三个让方案变简单的事实**（都是探查出来的，不查就会做成另一个样子）：
1. 前端**早就有 `shrink()`**（长边 1600、q0.82），压缩产物却用完即弃。存它而不是原图：200–500KB vs 4–5MB，**而且它正是实际传给模型批的那一张**，重批输入完全一致。
2. **一份批完（ok）之后连压缩图也丢掉**。照片只对重批和缩略图有用，而重批只对 err 项开放——稳态占用只剩「还没批完那几份」（≤5 张 ≈2MB），配额风险归零。
3. `makeCard()` 只依赖 `result`、不碰照片。所以「批语在、照片丢」老师能做的事一件不少。**优先级写死：result 必存、blob 尽力。**

**四个不显然的设计**（细节在 `web/README.md` 新增的「本机暂存」一节）：
- 主键 `sid+"#"+id`：`id` 不全局唯一，更要紧的是**残留记录自带身份**，不依赖上次 clear 有没有跑完；
- **24h 按 `created` 硬顶不滑动**，否则连批三天的老师会让暂存永不过期，界面上「最多 24 小时」就成假话；
- **恢复前必须校验 `mock`**：`makeCard()` 读的是当前 `S.mock`，拿演示草稿在真实模式下出图，点评卡会少掉「非真实批改」水印却带品牌落款——**能发进家长群的对外事故**；
- **`S.seq` 恢复时取 `max(id)` 不能用 `length`**：幽灵项被丢弃后 length 偏小，新拍的照片会拿到已存在的 id，`renderQueue` 按 `data-id` 反查就点开另一个学生的批语 → 把 A 的点评卡发给 B 的家长。**这是唯一会造成对外事故的 bug，且不报错。**

**探测与降级**：不能只判 `"indexedDB" in window`——微信 WKWebView 的失败形态是**挂住不返回**。⚠ **超时取 3 秒不是 1.5 秒**：页面刚加载时事件循环最忙，IDB 回调和 setTimeout 一起被推迟，`idb-probe.html` 实测本机 Chrome 在页面自动跑时 open 报 3520ms、**手动 console 调只要 38ms**——太紧会把「慢」误判成「坏」。配额两级降级（先只停图、再全停），且**`QuotaExceededError` 落在 `tx.onabort` 上不是同步抛的**，只 catch 同步异常连降级都不触发。

**新增诊断页 `/idb-probe.html`**：独立一页，测真实往返（含「写得进读出 undefined」这种坏 WebView 症状 + 一张 300KB Blob）。**0821 微信实测已过**（iPhone · iOS 26.2 · 微信 8.0.75）：六步全过、全流程 21ms（打开库 15ms）。**原先担心的「微信 WKWebView 有 IDB bug」在这个组合上不成立**，暂存功能真的可用；也反证本机那个 3520ms 纯是自动化环境开销、真机快 200 倍。⚠ 两点没覆盖：**安卓微信是 X5 内核**不是 WKWebView，结果不能外推；**iOS 问不到配额**（`navigator.storage.estimate()` 不实现），所以配额只能靠 `QuotaExceededError` 被动发现——**两级降级不是保险、是必需**。⚠ 另：**微信打不开「内网 IP + 非标准端口 + http」是常态**，普通浏览器能开、微信不能时先别怀疑代码；换个网络或用域名就好了。

**隐私口径从此是两层，别再混成一句「什么都不存」**：服务端仍然一张不留（`main.py:9` 那条硬约束不松动，只加了注脚）；前端另说——压缩图与批语在老师自己手机上暂存 24 小时、过期自动清、换课清、帮助面板可手动清、不回传。文案 7 处已同步（`index.html` 帮助面板、`试用说明_给加盟商.md`、`README` ×3、`app.js` ×2）。⚠ 试用说明里**特意没写**「遮名字这条到正式版就不用了」——正式版是主动读姓名填点评卡的，那会是新的一句假话。
