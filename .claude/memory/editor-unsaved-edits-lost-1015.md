2026-10-15《孤独的小螃蟹》详案：用户在 Cursor 里手动删句、改稿但没保存，我用 python 脚本从磁盘读→写回改目录并提交，用户的修改全丢（磁盘与三次提交里都从没出现过那些修改）。我只能看到磁盘，看不到编辑器未保存的缓冲区。

**Why:** 用户的手改是接力生产的一部分，丢了等于白干，且事后无从恢复。

**How to apply:**
- 已在 `%APPDATA%\Cursor\User\settings.json` 开 `files.autoSave: afterDelay`（1 秒）。若发现该设置被关，先提醒用户。
- 用户刚在 IDE 打开/选中过某文件、又让我改它时，动手前一句话提醒「先保存编辑器里的修改」；改完后 git diff 看一眼有无用户手改混入，并在汇报里点出。
- docx 被 WPS 锁＝用户可能在 docx 里改稿：重渲前先比对 docx 正文与 md，有差异停下问，不直接覆盖。同族：[[external-docx-backfill-0902]]

**反方向（2026-10-28《万物成长的故事》详案）**：Cursor 里从前一晚就开着这份详案（缓冲区停在 85e6411 版），其间我两次提交了新版（669292b 加了「快点长大，慢慢长大」整个环节并顺延页标，2adab55 补了 p133）；用户第二天在那个旧缓冲区里手改了几处，自动保存一触发，磁盘被整篇盖回旧版——新环节、时长调整、我刚提交的修订全没了，用户看到的反而是「详案没同步 PPT」。**判据**：工作区比 HEAD 少了刚提交的内容、行尾从 CRLF 变成 LF、diff 里出现「撤销上一提交」形状的大块删除。**处置**：先备份工作区到持久目录；`git restore --source=HEAD` 取回新版；拿 HEAD 与备份逐行 difflib 比对，只把真正新增的手改补回（别拿更早的提交当基准，会把已收进 HEAD 的旧手改当新的）；残缺的手改行（删了 `师：` 前缀、朗读提示删了一半）按原格式修复后汇报。**预防**：我要连续改一份用户在 IDE 里开着的文件，开工前就请用户关掉或从磁盘重新载入，不只是提醒「先保存」。
