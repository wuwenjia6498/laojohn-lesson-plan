2026-08-20 立、当日收官。项目交接给另一位同事后两台机器并行生产。她的硬盘拷贝**带 `.git`**，两边本就是同一私有仓库 `wuwenjia6498/laojohn-lesson-plan` 的两份克隆——**不必新建同步机制，缺的只是权限与纪律**。分工是**接力**：一人写粗稿、另一人审核优化。

## 现行方案（判据只有一条）

**引擎重渲得出来吗？渲得出来的不进仓库、各自本地重渲；渲不出来的一律入 git。**

据此：源文件、项目记忆 `.claude\memory\`、以及**三类曾被 gitignore 的大件**（`读书会原书插图\`、`写作课教材插图\`、`写作课件PPT输出\`，合计 79.5MB）全部入库；docx/pdf/pptx/jpg 等产物不入库。

**大件入库推翻了原「扫描件永不入库」规定**——仓库本就私有、仅两人可访问，而 git 是这条链路上唯一已跑通的通道。三条连带：
- ⚠ **「换机器后报『缺图待补』是预期行为」这条已作废**：新克隆自带全部插图，**再报缺图就是真出问题**（多半是文件名与 `_图单.md` 对不上，或 `【图位:插-NN】` 编号写错）。旧稿里凡见此说法以新口径为准。
- **git 只进不出**：入库即永久留在历史，撤销须 filter-repo 重写历史 + 双方重新 clone。故别往这三个目录放与备课无关的东西。
- 推大二进制慢（73MB 曾 10 分钟未完成），须 `git config http.postBuffer 524288000` 并**分批提交、后台推**。

## 记忆联接（仍是现行做法）

记忆原在 `C:\Users\<用户>\.claude\projects\<路径编码>\memory\`，完全在 git 之外、双机必然分叉——而记忆正是跨课次通则的载体，分叉＝两人各自把同一个坑重踩一遍。现事实源＝仓库 `.claude\memory\`，用户目录那份是 `mklink /J` 目录联接（不需管理员权限）。

- **`<路径编码>` 随盘符变**（D 盘＝`D--laojohn-lesson-plan`）；对方接入时须先 `robocopy /XC /XN /XO` 把她新增的记忆并进来**再**建联接，顺序反了会覆盖。
- **联接断了不报错**，表现只是 Claude Code「什么都不记得」；自检话术＝问「这个项目有哪些跨技能硬约束」。
- **验收要做写入穿透，探针必须用 `.md`**：`Get-Item` 看到 `ReparsePoint`／`LinkType: Junction` 只证明联接存在，不证明写进去会落到仓库；要从**用户目录那一侧**新建文件、再到仓库侧 `git status` 看认不认。⚠ **别用 `.tmp`**——`.gitignore` 里 `*.tmp` 全局忽略，`git status` 永远没反应，会误判成没通、白重建。两侧文件数一致是好旁证。

## 首次接入的两个坑（同事机器实测）

- **仓库是私有的**：未受邀者**连 `pull` 都不可用**，不只是推不上去——拿不到任何更新（包括写给她看的说明文档本身）。**这是权限问题、不是链路坏了**，别往同步机制上排查。等权限期间照常本地提交。
- **新机器没有 git 身份配置时，AI 会照着 `git log` 里的作者「补」——这是错的**。本仓历史长期只有 `honbei-dev` 一个作者，照抄的结果是两人提交全署同一个名；接力分工下**作者字段是「谁写的稿、谁审的」唯一无争议的证据**，混了找不回来。身份一律 `git config --local` + 本人 GitHub 邮箱。**未推送时订正＝一条 `--amend --reset-author`，推上去之后＝改写已发布历史**，发现即改别拖。

## 两条被否掉的方案（别再走一遍）

① **目录联接挂网盘**——`mklink /J` **只能建在 NTFS 卷上**，本项目常驻 exFAT 移动硬盘（`E:` = exFAT），在项目内建直接报 `Local NTFS volumes are required`。**记忆那条联接之所以成立，是因为它建在 C 盘、只是指向 E 盘——方向不可颠倒**，这是最容易想当然的一处，改动记忆联接时必须记得。

② **网盘 + 同步脚本**（`sync_assets.ps1`，已删）——本机 OneDrive **六年未登录成功**（`LastSignInTime` 停在 2020-02-13），进程照跑、目录照在、文件照放，**全程零报错**，放进去的 80MB 一个字节都没上云。查法＝注册表 `HKCU:\Software\Microsoft\OneDrive\Accounts\Personal` 的 `LastSignInTime` 与 `SignInErrorStateStartTimestamp`（有值即登录错误态）。由此得一条通用判据：**任何网盘通道都必须以「网页端看得到」验收，「本地有文件」永远不能证明「云端有文件」**。

## 其它
