`写作课件中间稿输出\<课次>\<题目>-页标映射.json` 的 `page` 字段**不能当页码权威源**。
详案里写 `〖PPT 第19-20页 · …〗` 这种跨页标记时，映射把它记成一页，此后每页少 1。

实测（2026-09-21）：三上一映射记 page 2–24（23 条），而详案内联页标是
`2,…,18,19-20,21,…,25`、pptx 实际 25 页 —— 末页差了整整 1 页。
**17 个已回注课次里 9 个带跨页标记**，且行为还不一致：五上一展开了（2..27 连续），
三上一没展开。说明映射的生成本身就不统一。

**Why**：与 pptx 真实页码对齐的是**详案内联页标**——它是 `plan_link` 回注链的产物，
也是 `anim.json` 工单认的那一套。映射 json 的价值只在 `kicker`/`title` 两个栏目名
（那是人工写的眉标，本就最准），不在页码。

## ⚠ 追加（0921 晚）：仓内 pptx 不一定是终稿，拿它对账会得出错结论

用 python-pptx 逐页读**仓内** pptx 与详案页标对账，17 个课次 13 个对不上，
五上二从 P7 起整整齐齐差 1 页（PPT P7 的内容被详案标成 P8，一路到底）。

当时据此判「详案页标错了」——**这个结论是错的，用户 0921 当场纠正**：
> 外部终稿会重新导入，**仓内的不一定都是终稿**。

详案页标是对着**终稿**回注的，而 `写作课件PPT输出\` 里那份可能是更早的版本。
两者对不上是**预期**，不是 bug，**更不要去批量改详案页标**。

**How to apply（这条真正的用处）**：
- 做任何按页消费 PPT 的事，**画面源要拿外部终稿**，别拿仓内那份凑合。
  这也是 `laojohn-lesson-video` 默认读 `_备课视频工作区\<课次>\source.pptx`、
  取不到就报错不静默回退的原因。
- `build_shotlist.py` 的 `check_title_match` 拿 `anim.json`（抽自 PPT）与详案页标对账：
  用**终稿**时它报的失配是真信号（需人工确认）；
  用 `--fallback-repo-pptx` 时它报的失配**多半只是版本不同**，不必当错。
- 同理，`写作课件中间稿输出\` 的页标映射 json 同样可能跟的是另一个版本。

**How to apply**：任何按页消费 PPT 的新链路，**切分一律以详案 `〖PPT 第N页 · 页型 · 眉标〗`
为准**，按标题文本去映射 json 取栏目名，并产出一份偏移差异报告让人看见。
`laojohn-lesson-video` 的 `build_shotlist.py` 就是这么做的（`pagemap_offset` 报告 +
`align_check` 三方对账）。相关：[[lesson-video-line-0921]]
