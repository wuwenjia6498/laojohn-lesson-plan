**规则**：凡本仓处理外部生成的写作课 pptx，**默认顺带清掉表头重影层**，不必等用户提。
用户此前每次都在自己那边手动删，删完动画又得重调——这活挪进本仓工序做，一次成型。

**现象与成因**：外部生成端把深蓝表头行（表格首行、并列卡片的卡头）**同时输出了两份**——
一张烧进了白字的位图 `PICTURE`，和一组同位的 `FREEFORM` 深蓝色块 ＋ 可编辑文字框。
两层文字几乎重合但字形渲染不同，投屏看就是重影。位图与色块的 top/left/width/height 四值完全相同。

**Why**：这是外部平台的毛病，不是本仓脚本的 bug（哪天对方修好，机检自然 0 命中）；
但它落在用户手上就是每份 PPT 都要手删一遍、且删完动画序列跟着变，属于本仓该兜的收尾。

**How to apply**：
- **时机：归位与详案审查之后、`animate_pptx.py` 注入之前**。先删图再注入，动画一次排好；
  反过来先注入再删，被删对象往往已绑在某一击里，整页分组要重排。
- **判据（可机检）**：同一页里某 `PICTURE` 与另一个非图片形状的 `(top,left,width,height)` 四值完全相同，
  **且该矩形内另有带文字的文本框** → 这张位图就是重影层，删它，保留色块与文字框（文字仍可编辑、可单独绑动画）。
- **只删压着文字框的那些**：同位但框内无文字的位图是纯装饰，留着别动。
  六上一《变形记》实测：15 处「图片＋同位形状」里，压着文字的是 P11／P14／P19 三张表头 ＋ P28 三张卡头。
- **删完三件事**：① 从 `-anim.json` 分组里剔除被删的 shape_id（留着会让注入时找不到 id）；
  ② 注入后照常跑回读核验 ＋ [[ppt-anim-no-upward-jump-0915]] 的回跳校验；
  ③ 用 `laojohn-ppt/tools/shot_assets.py` 截那几页比一眼，确认深蓝底没掉、白字还在。
- 首次识别：0915 六上一《变形记》P19 旁批表（用户截图指出）；那一份由用户自己处理了，本仓这份未动。
