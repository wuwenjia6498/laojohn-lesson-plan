# 老约翰课案 → 阅读指南

把一份课程详案(教案详案 `.md`)转成一张《书名》阅读指南,版式对齐老约翰品牌样张,同时输出 **PDF(交付)** 与 **HTML(可编辑源文件)**。

## 这张卡是给谁看的(最重要的定位)

这张卡面向**要读这本书的学生和家长**,不是面向上课的老师。所以:

- 它是一张**导读卡**——告诉读者这是一本什么书、读的时候关注什么、用什么方法读、读完可以再读什么。
- **丢弃**课案里所有「教学性」细节——课时安排、师生对白、PPT 换页标记、可视化工具的操作步骤、参考答案、活动设计等,统统不进卡。
- 关键动作是**降维改写**:课案是写给老师的(「训练推断策略」「让学生体会……」),指南要改写成**面向孩子的、温暖平实的说法**(「读到悬念时先猜一猜」「关注主角的变化」)。

## 整体流程

两段式:**萃取(你来做)→ 渲染(脚本来做)**。

1. 读课案,按下文规则萃取出结构化数据,写成一个 `data.json`。
2. 运行渲染脚本,得到 PDF 和 HTML。

```bash
python3 scripts/render_pdf.py <data.json> <输出文件名不含扩展名>
```

## 第一步:萃取(本 skill 的质量核心)

输出一个 JSON,固定结构。完整字段说明见 `references/data_schema.md`,**动手前先读它**。结构概览:

```
顶部固定:header_left / header_right / title / cover_image / info(信息表)
栏目固定四个:内容简介 / 阅读要点 / 阅读建议 / 拓展阅读建议
```

### 信息表(info)——事实类，优先从书籍档案取

六个字段：书名、字数、作者、页数、出版社、累计阅读。

**读取顺序（由高到低）：**

1. **先查对应书籍档案**（`<项目根目录>\读书会书籍档案\<书名>书籍档案.md`）：找到 `## 海报/指南元数据` 块，直接取 `出版社 / 字数 / 页数` 字段。值为「（待补充）」时视同缺失。
2. **再查课案**：档案没有的字段，看课案开头的提纲表是否有明确值。
3. **仍缺则留空字符串 `""`**：渲染成空白格，由用户事后回填。

**绝不联网、绝不凭记忆臆造**——填进去的必须是档案或课案明确写出的事实。

- 书名、作者通常课案开头就有；字数、页数、出版社通过书籍档案获取。
- 「累计阅读」样张里一向是空的，**固定留空**。

### 内容简介(paragraph)

取课案的【内容简介】段,降维改写成 **4–5 句、面向孩子的温暖叙述**。可以点名书中精读到的人物/情节让它具体可感,但不要堆砌教学术语。

### 阅读要点(list,2–3 条)——「这本书里看什么」

从课案的「情感价值目标 / 知识技能目标 / 核心议题 / 主题」提炼 **2–3 个主题或角色层面的关注点**,改写成「关注 X、思考 Y」的句式。每条以「序号、概念词：一句说明。」起头。

例:关注主角如何从单纯的机器人变得懂得友情;关注角色之间如何齐心协力;思考人和技术、自然的关系。

### 阅读建议(list,2–3 条)——「怎么读这本书」

从课案的「阅读策略 + 可视化工具 + 阅读方法」提炼 **2–3 条具体的阅读方法**,改写成给孩子的动作建议。例:边读边做推断、留心看插图、给人物做一张小表格、和家长同学讨论、把自己代入某个角色。

### ⚠️ 红线:阅读要点 与 阅读建议 必须分工,不许重复

这是本 skill 最重要的一条规则(防止旧模板里两栏内容完全雷同的 bug):

- **阅读要点 = 内容/主题层面**——书里有什么值得关注(角色、主题、思想)。
- **阅读建议 = 方法/行为层面**——读的时候具体怎么做(怎么读、和谁讨论、做什么动作)。

萃取完**自查**:把两栏并排看,如果有任意一条在讲同一件事,就是写错了,回去把「建议」改成纯方法。**两栏内容雷同视为不合格产出。**

### 拓展阅读建议(list,2 条为佳,必要时 3 条)

**这一栏的本分就是给出具体的延伸读物 / 影片,不泛泛而谈。** 优先**点名具体书目 / 影片**(书名号写全 + 一句"和本书哪里像、读完怎么对照看");课案里提到的关联作品优先用,课案没提时可用**广为人知、确定存在的同类名作或知名改编影视**补足。**首选 2 条,只在有第三个明显不同的角度时才写 3 条。** 每条 **40–70 字**,有理由 + 有动作即可,不要堆砌。

可选展开角度(任选 2–3 个不同方向,不要每个都用):

- **同类作品(点名书目)**:公认的同题材 / 同笔法名作,书名 + 作者写全,一句说清"和本书哪里像、读完对照看什么"(如讽刺寓言荐《动物农场》)。
- **改编影视(点名片名)**:本书的知名改编电影 / 剧集,片名 + 年份或主演,建议"看完对照原著聊聊改了什么、为什么"。
- **同作者其他作品**:点名书目 + 一句笔法 / 题材的延续关系。
- **课内外联结**:若课案提到本书选段进了某册课本,建议读完整本回头再看那篇课文。
- **从读书走向生活**:把书里"看人 / 看事"的眼睛延伸到孩子身边——访谈亲人、留意家乡、写一段回应。

约束(★真实性红线在这一栏的作用域,读前必看):
- **只写"广为人知、确定存在"的作品**:同类书的书名·作者、改编影视的片名·年份 / 主演,必须是公认确证的;**吃不准某本书 / 某部改编是否真存在、是否真同类,就不写那一条**,宁可少给,不硬凑。成品由人工校对书名 / 作者 / 年份。
- **这是"绝不凭记忆补事实"红线在本栏的唯一放行口**:放行仅限"另一部广为人知的作品"这类常识,**绝不外延到本书自身**——本书的书目信息·情节·人物·页码仍唯一锁书籍档案,不因这条放行而松动。
- 课案写了关联作品就优先用课案的;避免一条塞两个动作、三个理由——一条一意思,干净。
- **禁**回到"请老师 / 图书馆员推荐""待补由老师补充"这类**把皮球踢开的泛泛占位**——那正是本栏要治的病。

### 翻译的纪律

只从课案**明确写出**的内容提炼,**不外推全书主旨、不补课案没讲的内容**。所有冒号统一用全角「：」,说明句以句号收尾(对齐样张)。

**引号纪律**:JSON 内容字符串里引用词语 / 短句一律用全角弯引号 `“”`(嵌套内层用 `‘’`),**禁用直角引号 `「」`、禁用英文直引号 `"`**——弯引号在 JSON 里无需转义,且与详案正文口径一致(2026-07-22 统一,此前「用全角「」」的旧口径作废)。

完整萃取范例见 `evals/sushiqiren_guide.json`(由《俗世奇人》课案萃取而来)。

## 关于书封图(cover_image)

样张左上角有书封图,但课案 `.md` 里没有图片,**不要联网找书封**(易找错版本)。

### 固定约定:封面图文件夹

> ⚠ 本项目位于移动硬盘，盘符可能随挂载变动。执行前请通过 Cursor 工作区路径或 `(Get-Location).Path` 确认实际项目根目录，下方 `<项目根目录>` 代表该路径。

封面图**统一维护在项目级共用目录**（与 laojohn-course-poster 共用，新增任意一张，两个 SKILL 都能用）：

```
<项目根目录>\读书会书籍封面\<书名>.<ext>
```

- `<书名>` 用纯书名，**不带书名号《》**（例：`手斧男孩.jpg`、`俗世奇人.png`）。
- 支持的扩展名：`.jpg` / `.jpeg` / `.png` / `.webp`。

### 处理流程

每次生成阅读指南时，按这个顺序处理书封:

1. **先去封面图文件夹找**：用书名拼出预期路径 `<项目根目录>\读书会书籍封面\<书名>.<ext>`，看图是否已经存在。
   - 找到 → 把图转 base64 data URI 写进 `cover_image`（推荐 data URI，这样 HTML 自包含、可独立打开）；也可以填**相对路径**（相对于输出目录）。
   - 没找到 → 进下一步。
2. **没找到就先占位**：`cover_image` 留 `null`，渲染出来是浅灰占位框（写「书封待放」），不破版，先把文字稿交付。
3. **交付时主动提示用户**：告诉用户「封面图按 `<项目根目录>\读书会书籍封面\<书名>.jpg` 的规则放进去，发我一声就重渲染」，顺便说明也可以直接在对话里拖图给我。
4. **用户后续补图**：无论是丢路径还是直接拖图给我，都把图保存/拷到上述固定文件夹，然后改 JSON 的 `cover_image` 字段，重跑渲染。

### 不变的原则

- 绝不联网搜书封——容易抓错版本。
- 绝不凭印象编造书封链接。
- 用户没主动给图,就用占位框,不要"自作主张"找一张顶上。

## 第二步:渲染

### 固定输出目录

> ⚠ 本项目位于移动硬盘，盘符可能随挂载变动。执行前请通过 Cursor 工作区路径或 `(Get-Location).Path` 确认实际项目根目录，下方 `<项目根目录>` 代表该路径。

**所有产物统一保存到该书专属文件夹（读书会各配套物料共用一夹，目录不存在则先创建）：**

```
<项目根目录>\读书会配套输出\<书名>\
```

文件命名规则：`<书名>_阅读指南`（如 `俗世奇人_阅读指南.pdf`、`俗世奇人_阅读指南.html`、`俗世奇人_阅读指南.json`）。

---

把萃取好的 JSON **存到固定输出目录**(不要只放临时位置)——这份 JSON 是整张卡的「内容源头」,PDF 与 HTML 都由它渲染而来,用户日后调整也靠改它:

```bash
# 数据与产物都落在固定输出目录
python3 scripts/render_pdf.py "<项目根目录>\读书会配套输出\书名\书名_阅读指南.json" "<项目根目录>\读书会配套输出\书名\书名_阅读指南"
```

脚本会:
- 注入数据到 `assets/template.html`,生成自包含的 **HTML 源文件**。
- 用 Chromium 无头渲染,导出竖向 A4 **PDF**;内容超长时页面高度自适应(不截断),中文字体已嵌入(无乱码)。

渲染细节、配色变量、版式约束见 `references/rendering.md`。

最后用 `present_files` 把三个文件一并交付,顺序为 **PDF → 数据 JSON → HTML**。务必把 `data.json` 也交付,并简要说明:**这份 JSON 是内容源头,日后想改任何文字(补出版社、改某条建议、放书封),编辑它再重渲染即可;不要只改 HTML,改动不会回写到 JSON。**

## 常见问题

- **某栏文字太长撑破版面**:是某条说明写啰嗦了。回到萃取压短句子,而不是改版式。
- **课案信息严重不足**(比如没有内容简介):如实告诉用户这份课案缺哪类信息、对应栏目会偏薄,请用户确认或补充,**不要靠联网/记忆填满**。
- **想换书重做**:只需替换 `data.json` 重新萃取,模板和脚本不动。
- **用户要调整 AI 生成的内容**(补出版社、改某条、加书封等):
  - **当场改**(本次对话内):直接在已萃取的 JSON 上改对应字段,重跑渲染命令,交付更新后的三件套。
  - **事后改**(新开对话):请用户提供上次交付的 `data.json`,基于它修改后重渲染。这正是要把 JSON 作为交付物的原因。
  - 提醒用户:冒号用全角「：」;信息表缺的字段留空字符串即可,渲染成空白格。
