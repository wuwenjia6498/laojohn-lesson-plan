# 教师用 data.json 字段契约

模板：`assets/template_teacher.html`（2 页 A4：教师速览页 / 怎么讲活三色旁注）。
**教师侧不配发逐字稿**（2026-08-03 定）：这两页就是老师手上的全部纸面材料，故文案不得预设「老师手边有逐字稿」——禁写「配合逐字稿」「照着念/别照念」「稿子上第 X 步」这类指代。`delivery` 仍是「哪步必守、哪处放开、为什么」的教研旁注，只是改从**教学动作本身**说起。
本文件是「详案锚点 → 教师用字段」的唯一映射源。富文本只认 `{b}…{/b}`（无 `{hl}`）；引号纪律同学生侧（弯引号“”，禁「」、禁英文直引号、禁原始 HTML）。

## 字段总表

```jsonc
{
  "meta": {
    "kicker": "三年级上册 · 第六单元 · 习作",   // 同学生用
    "topic": "这儿真美",
    "genre": "写景状物"                        // ← 提纲表「同类习作顺序」行，缩成 2–4 字文体标签
  },

  "overview": {                                // ── 第1页：教师速览页（上课前扫一遍）
    "goal": "…",                               // 一句话目标 ← 提纲表「核心技法」+「学习目标」压缩成一句，
                                               //   {b}标关键动作；模板自带前缀"一句话目标："
    "lessons": [                               // 两节课时间轴 ← 详案 `### 环节标题（X 分钟）` 逐环节抽
      {
        "title": "第 1 节 · 作前指导（45′）",   // 节名 ← `## 第N课时 · 课型`，改口语（作前指导/当堂写作+评改）
        "steps": [
          { "min": "6′", "name": "创设情境，明确任务（明信片墙）" }
          //  min ← 环节标题括号内分钟数（"约 5 分钟"也写成 5′；忽略"｜可压缩"附注）
          //  name ← 环节标题压短（可带一个括号点睛词），顺序、数量与详案一致
        ],
        "after": "习作讲评环节（备选，逐篇深批）"  // 可选：详案「附：习作讲评指导环节」→ 挂第2节末的灰色课后行
      }
    ],
    "warns": [ "…{b}…{/b}…" ],                 // 易错点 2–4 条 ← 详案难点/自检表/评改环节的常见问题，
                                               //   句式"现象——怎么盯"；标题"最容易翻车的 N 处"由模板按条数生成
    "essay": {                                 // 示范文 ← 详案 > 【教师示范文】，一字不改（纯文本，无标记）
      "title": "…",
      "paragraphs": [ "…" ]
    },
    "materials": [ "…" ]                       // 物料清单：学生用两件（学习单 / 范文页）+ PPT +
                                               //   详案里点名的教具（照片等）。学生侧已无课后练笔，勿再列
  },

  "delivery": {                                // ── 第2页：怎么讲活（防念稿三色旁注）
    "envs": [                                  // 逐环节旁批 ← 详案环节 + workflow-engine 设计意图；
      {                                        //   第1节逐环节列，第2节可并成一条"⑥–⑧"
        "heading": "① 创设情境（明信片墙）",    // 环节序号+短名
        "rows": [
          { "type": "keep", "text": "…{b}…{/b}…" },   // 必守：做错课就散的动作
          { "type": "free", "text": "…" },            // 可放开：鼓励用教师自己的话/例子处
          { "type": "why",  "text": "…" }             // 为什么：设计意图（不必每环节三色齐全，1–3 行即可）
        ]
      }
    ],
    "nono": [ "…{b}…{/b}…" ]                   // 最容易讲僵的 2–4 处（讲死了就没戏的地方：要等学生答、
                                               //   要临场接话、要用你班的例子）；标题"这 N 处"由模板按条数生成
  }
}
```

## 详案锚点速查

| 详案锚点 | 供给字段 |
|----------|----------|
| 提纲表「同类习作顺序」行（存量稿为「文体线」） | `meta.genre` |
| 提纲表「核心技法」+「学习目标」行 | `overview.goal` |
| `## 第N课时 · 课型` + 各 `### 环节（X 分钟）` | `overview.lessons[].title/steps`（分钟数逐字取，名称压短） |
| `## 附：习作讲评指导环节` | `overview.lessons[1].after` |
| 三档自检表 / 评改环节常见问题 / 详案点名的难点 | `overview.warns` |
| `> 【教师示范文】` blockquote | `overview.essay`（一字不改） |
| 详案里点名的教具（照片/卡片等） | `overview.materials` 补充项 |
| 各环节的师话设计 + `workflow-engine.md` 设计意图 | `delivery.envs`（派生，须能回溯到详案该环节实际做法） |
| 引用课文/原文处、开放问答处、点评学生处 | `delivery` 里的真实性提醒与 `nono` 高发点（这几处最怕讲成单向输出） |

## 派生纪律

- `warns`/`envs`/`nono` 是**教研视角的派生内容**：每条都要指向详案里真实存在的环节动作，禁止写详案没有的教学步骤。
- **旁注要短**：`envs[].rows[].text` 控制在 50 字左右一行放下；第 2 页共 ≈15 行旁注，普遍两行就会超一页高（渲染自检会报）。宁可砍修饰词，别砍环节。
- 详案引课文佐证写法处，`envs` 的 why 行要带「拿不准原文就概括着说、别硬背」的真实性提醒（守伪摘录禁令）。
- 时间轴分钟数与详案一致，不自行调配；两节合计各 45′。

## 模板里的固定骨架（不在 data.json 里，禁改）

页眉 logo 与左侧用途标签（教师速览页·上课前扫一遍／「怎么讲活」旁注·备课时过一遍）、kicker 尾缀「｜　2 节 × 45 分钟连排」、「一句话目标：」前缀、区块标题（两节课时间轴/教师示范文（可投屏 / 读给学生听）/这一课要发 / 用的物料/怎么把这节课讲活）、intro 导语（下面按环节标出三件事…）、三色图例、三色标签名（必守/可放开/为什么）、警示条 ⚠/✕ 符号。
