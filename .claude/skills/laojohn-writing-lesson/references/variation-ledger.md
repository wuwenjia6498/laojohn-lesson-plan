# 反同质化台账(已用零件登记 · 查重依据)

> **这份文件是「跨篇查重」的落地载体(判断二的 B 方案)。** 生成新详案前,先查这里:本年级/邻近批次已经用过哪些场景、载体、热身、反馈游戏、开场钩子,**撞了就换**(规则见 `variation-pools.md`)。
>
> **台账的真相来源是每份详案文件尾部的「指纹块」,不是生成时的临时意图。** 因此台账**只重建、不盲目追加**:任何时候都可以扫一遍 `写作课输出\` 目录下所有 `.md` 的指纹块,重建出当前真实的占用情况。这样无论详案后来被手动改过、还是被 AI 优化过,只要改稿时同步更新了文件尾的指纹块(这是硬规则),台账重建后永远对得上成稿。

---

## 一、指纹块格式(写在每份详案 .md 的**文件最末尾**,`全课完。` 之后)

每份详案结尾追加一段 HTML 注释(不渲染、不进 docx 正文、老师看不见,但机器和重建脚本能读):

```
<!-- VARIATION-FINGERPRINT
册级: 四上
题目: 写观察日记
文体: 观察日记
场景原型: 连载追踪(给自己/同伴看的成长记录)
实体载体: 连载档案/成长本(自己留存)
热身动作: 现场观察今天的实物+翻看记录卡
主反馈游戏: 连载预告
第二层反馈: 自评一句「我最满意哪儿」
开场钩子: 实物道具式(玻璃罐)
-->
```

> **硬规则:改稿必改指纹。** 凡在「生成后的优化」阶段动了上述任何一项(换了载体、换了反馈游戏、改了开场……),**必须同步改这段指纹块**。指纹块就在同一个 .md 里,改正文时顺手改它。指纹块与正文不一致 = 台账会失真 = 下次查重出错。

> 重建动作:扫 `写作课输出\*.md` 的全部指纹块 → 解析 → 覆盖重写下表。新增一篇定稿后也走「重建」,不手动追加,避免和手动/AI 改稿脱节。

## 三、查重操作(生成新详案时,工作流第 1.5 步调用)

1. 读本表,筛出**同年级**全部行 + **同文体**全部行(跨年级也算)。
2. 对照即将生成的本篇,逐列比对场景原型/载体/热身/反馈/开场。
3. 命中规则(见 `variation-pools.md` 各池硬规则)即换:
   - 同年级最近 2–3 篇用过的,避开;
   - 同文体两篇,场景/载体/反馈必须有别;
   - 「禁止逐字复用」清单里的句子,全文比对改写。
4. 生成完成、写入指纹块后,**重建本表**(扫目录覆盖重写)。

> 若台账文件丢失或盘符变动:不慌,扫 `写作课输出\` 下所有 .md 的指纹块即可一键重建本表,不依赖任何外部状态。
