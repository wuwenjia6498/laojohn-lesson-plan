# 老约翰课案 → 书籍抢先看思维导图

把一份课程详案(教案详案 `.md`)转成一张中心放射式的「《书名》精彩抢先看」思维导图,版式对齐老约翰品牌样张,同时输出 **PDF(交付)** 与 **HTML(可编辑源文件)**。

## 这张图是给谁看的(最重要的定位)

这张图面向**要上这堂课的师生**,不是面向想了解整本书的人。因此它的边界就是**课案的边界**:

- 只呈现**书本身**的信息(它是一本什么书、写什么、好在哪、读完得到什么),**丢弃**课案里所有「教学性」内容——教学目标、阅读策略、可视化工具、课时安排、师生对白、活动设计、PPT 换页标记等,统统不进图。
- 范围**严格锁定课案**。课案精读了哪几个人物/片段、围绕哪条主线,图就只覆盖这些。课案没讲到的全书内容**不要外推补充**,那超出了这堂课的范围,反而会干扰师生。

## 整体流程

两段式:**萃取(你来做)→ 渲染(脚本来做)**。

1. 读课案,按下文规则萃取出结构化数据,写成一个 `data.json`。
2. 运行渲染脚本,得到 PDF 和 HTML。

```bash
python3 scripts/render_pdf.py <data.json> <输出文件名不含扩展名>
```

---

## 第一步:萃取(本 skill 的质量核心)

输出一个 JSON,固定五大一级分支,二级节点数量按书伸缩。结构见 `references/data_schema.md`,**动手前先读它**。

**引号纪律**:JSON 内容字符串里引用词语/短句一律用全角弯引号 `“”`(嵌套内层用 `‘’`),**禁用直角引号 `「」`、禁用英文直引号 `"`**——与详案正文及阅读指南口径一致(2026-07-22 统一,存量 4 本已改重渲)。

五大分支固定为:**书籍信息 / 书籍概述 / 书籍主题 / 书籍特色 / 阅读收获**(顺序也固定,对齐样张)。

### 各分支怎么填

**书籍信息**(事实类,3 条左右)
作者、出版社、类型/体例。这些是**书目/出版类客观事实,课案通常不收录**——应到**书籍档案**取:先打开同名档案 `<项目根目录>\书籍档案\<书名>书籍档案.md`,从其 `## 海报/指南元数据` 机读块按固定键名读「作者 / 出版社 / 类型」(值为「(待补充)」视同缺失)。档案缺、课案也没有时,**该条直接省略、不输出**(节点缺失即不列出,不写「出版社：待补」之类占位)。**绝不联网或凭记忆臆造**——联网补来的是「全书」信息,会越过这堂课的边界。

**书籍概述**(两个二级节点,各带三级)
- `背景设置`:场景(故事发生在哪)、主角(谁/什么身份)。从课案的「内容简介」段提取。
- `主要内容`:3–4 条。概括这本书写什么。**优先采用课案精读到的人物/篇目/情节**(因为那是这堂课真正会碰到的),而不是全书梗概。

**书籍主题 / 书籍特色 / 阅读收获**(理解类,这三支是「翻译活」,各 3–4 条,每条配一句简短说明)
这三支不是照抄课案,而是把课案里**教师向**的措辞,**翻译成面向读者**的说法:
- `书籍主题`:这本书在探讨什么?素材来自课案的「情感价值目标」「核心议题」「两条暗线」「课堂总结」。把「让学生体会……」改写成「这本书探讨……」。
- `书籍特色`:这本书的写法/语言奇在哪?素材来自「知识技能目标」里讲的语言风格、笔法,以及精读环节拆解的写作手法。
- `阅读收获`:读完能带走什么?素材来自「情感价值目标」和「课堂总结」里「带走两个词」这类落点。

**翻译的纪律:只从课案明确写出的内容提炼,不外推全书主旨。** 每条用「概念词：一句说明。」的格式,**冒号统一用全角「：」**,说明句以句号收尾(对齐样张)。

### 萃取范例(俗世奇人课案 → 节选)

```json
{ "name": "书籍信息", "children": [
  { "label": "作者：冯骥才" },
  { "label": "类型：短篇小说集" }
]}
```
注意:出版社/作者/类型优先到**书籍档案的 `## 海报/指南元数据` 机读块**取;此例出版社档案也缺,故**整条省略不列**(不写「出版社：待补」占位)。冒号统一用**全角「：」**。

```json
{ "name": "书籍主题", "children": [
  { "label": "绝活与规矩：手艺人靠真本事吃饭，靠死规矩立信。" },
  { "label": "人物反差：奇人多有「表面 ↔ 内里」的反差。" }
]}
```
这两条来自课案反复出现的「绝活+规矩+反差」主线和「两条暗线」,是**提炼**而非照抄,且没有引入课案未讲的全书内容。

完整范例见 `evals/sushiqiren_extracted.json`。

## 第二步:渲染

### 固定输出目录

> ⚠ 本项目位于移动硬盘，盘符可能随挂载变动。执行前请通过 Cursor 工作区路径或 `(Get-Location).Path` 确认实际项目根目录，下方 `<项目根目录>` 代表该路径。

**所有产物统一保存到：**

```
<项目根目录>\抢先看思维导图\
```

文件命名规则：`<书名>_抢先看`（如 `俗世奇人_抢先看.pdf`、`俗世奇人_抢先看.html`、`俗世奇人_抢先看.json`）。

---

把萃取好的 JSON **存到固定输出目录**(不要只放临时位置)——这份 JSON 是整张图的「内容源头」,PDF 与 HTML 都由它渲染而来,用户日后调整内容也靠改它:

```bash
# 数据与产物都落在固定输出目录
python3 scripts/render_pdf.py "<项目根目录>\抢先看思维导图\书名_抢先看.json" "<项目根目录>\抢先看思维导图\书名_抢先看"
```

脚本会:
- 注入数据到 `assets/template.html`,生成自包含的 **HTML 源文件**。
- 用 Chromium 无头渲染,**JS 实测每个节点真实坐标后再画弧线**——所以不管节点多长、多少条,连线起止点都自动对齐,无需手填坐标。
- 导出竖向 A4 **PDF**,内容超长时页面高度自适应(不会截断),中文字体已嵌入(无乱码)。

渲染细节、配色变量、排版约束见 `references/rendering.md`。

最后用 `present_files` 把三个文件一并交付,顺序为 **PDF → 数据 JSON → HTML**。务必把 `data.json` 也交付给用户,并简要说明:**这份 JSON 是内容源头,日后想改任何文字(如补出版社、改某条说明),编辑它再用上面的命令重渲染即可;不要只改 HTML,改动不会回写到 JSON。**

## 常见问题

- **某条文字太长撑破版面**:这是理解类节点写太啰嗦了。回到萃取,把说明句压短(样张里每条说明都在一行左右),而不是改版式。
- **课案信息严重不足**(比如根本没有内容简介):如实告诉用户这份课案缺哪类信息、图里对应分支会偏薄,请用户确认或补充,**不要靠联网/记忆填满**。
- **想换书重做**:只需替换 `data.json` 重新萃取,模板和脚本不动。
- **用户要调整 AI 生成的内容**(补出版社、改某条说明、删某条、改书名等):
  - **当场改**(本次对话内):直接在已萃取的 JSON 上改对应字段,重跑渲染命令,交付更新后的三件套。用户无需碰文件。
  - **事后改**(新开对话):请用户提供上次交付的 `data.json`,基于它修改后重渲染。若用户没保留 JSON,只能依据现有 PDF/HTML 重新萃取一份。这正是要把 JSON 作为交付物的原因——它让事后调整无需从头再来。
  - 提醒用户:冒号用全角「：」;删整条就删掉对应的 `{ "label": ... }` 对象,版式会自动收拢,不留空位。
