# 老约翰课案 → 教学设计思维导图

把一份课程详案(教案详案 `.md`)转成一张中心放射式的「《书名》教学思维导图」,梳理这堂课的**教学设计骨架**,版式对齐老约翰品牌样张,同时输出 **PDF(交付)**、**HTML(可编辑源文件)**、**数据 JSON(内容源头)**。

## 这张图是给谁看的(最重要的定位)

这张图面向**备课与教研的老师**,呈现的是「**怎么教这本书**」,不是「这本书写了什么」。

- 只呈现课案的**教学设计**信息——教学目标、课时流程、重点环节、阅读策略、可视化工具。书的故事内容、人物情节只在它们作为「教学素材」被提及时出现(如某环节读了哪个片段),不单独成图。
- **边界**:本 skill 只做「教学设计梳理」。如果用户要的是「这本书是什么/精彩抢先看/书籍概况」这类讲**书本身**的导图,不属于本 skill。拿不准时先问用户:你要的是「书的概况」还是「教学设计」?

## 萃取的总纪律:归纳重组允许,无中生有禁止

本 skill 允许把课案里散落的教学信号**重新组织、提炼**(例如把第二课时「介绍工具:奇人画廊表」归到「可视化工具」分支)。但红线是:

- **策略、工具、环节、目标必须在课案里真实出现过**才能进图。课案没写的阅读策略/可视化工具,绝不凭常识或同类课经验补。
- **不联网、不靠记忆补全。** 缺失的内容如实标注「待补」或从略,提示用户回填。
- 归纳是「把课案的话换种说法、合并同类项」,不是「发明课案没有的内容」。每写一条,都要能在课案里指出它的出处。

## 整体流程

两段式:**萃取(你来做)→ 渲染(脚本来做)**。

1. 读课案,按下文规则萃取出结构化数据,写成一个 `data.json`。
2. 运行渲染脚本,得到 PDF / HTML。

```bash
python scripts/render_pdf.py <data.json> <输出文件名不含扩展名>
```

## 第一步:萃取(本 skill 的质量核心)

输出一个 JSON,**固定五大一级分支,顺序固定**,对齐《荒岛机器人》样张。结构见 `references/data_schema.md`,**动手前先读它**。

**引号纪律**:JSON 内容字符串里引用词语/短句一律用全角弯引号 `“”`(嵌套内层用 `‘’`),**禁用直角引号 `「」`、禁用英文直引号 `"`**——与详案正文及阅读指南口径一致(2026-07-22 统一,存量 4 本已改重渲)。

五大分支固定为:**教学目标 / 教学流程 / 重点教学环节 / 阅读策略学习 / 可视化工具的运用**。

### 各分支怎么填

**① 教学目标**(2 层,固定 3 条)
直接取课案「教学目标(书级)」段的三维目标。三条分别以「知识与技能:」「过程与方法:」「情感态度价值观:」起头(全角冒号),各概括成一句。这是**纯提取**,不改写立意。课案若缺某维目标,填「……:待补」,不脑补。

**② 教学流程**(3 层:分支 → 各课时 → 环节要点)
- 课时数**按课案实际**(找 `## 第X课时` 标题),每课时一个二级节点,`label` 写「第一课时:导读课」这类「课时序号 + 课型」。
- 每课时下挂 3–5 个三级环节要点,**直接来自该课时的小节标题**(课案里 `### 一、xxx`、`#### (一)xxx` 这类),压成短语,如「情境导入·话题激趣」。不逐字抄长标题,去掉时长括号。
- 这一支是「教学的时间线」,只勾勒环节名称,不展开细节(细节留给「重点环节」分支)。

**③ 重点教学环节**(2 层,3–5 条)
从各课时里挑出**最核心的几个活动**平铺,每条配一句说明(做什么+怎么做)。
- 选取标准:用了核心可视化工具的环节、精读关键片段的环节、思辨高潮环节。
- 与「教学流程」的关系:流程是**全部环节的时间线**(只列名),重点环节是**少数核心活动的特写**(带说明)。允许内容重叠,但这里要写出「为什么重点」。
- 格式:`环节名：一句说明。`(全角冒号,句号收尾)

**④ 阅读策略学习**(2 层,3–5 条)
扫课案里所有策略信号:提纲「三、阅读策略」行、各课时「过程方法」目标里「训练 X 策略」、正文「——此处训练 X 策略」批注。
- 去重归纳成几条主要策略(如 预测/推断/比较/筛选重要信息/整合)。
- 每条尽量配一句**课案里这个策略具体怎么练的**实例,如「预测:读《刷子李》前预判徒弟会不会看到白点,再用原文验证。」实例必须来自课案真实环节。
- 格式:`策略名：一句实例。`(全角冒号,句号收尾)

**⑤ 可视化工具的运用**(2 层,按课案实际条数)
扫课案里所有工具信号:提纲「四、可视化教学工具」行、正文「介绍工具:XX」小节、各课时「过程方法」里点名的表/图。
- 每个工具一条,配一句**这个工具在课上拿来做什么**。
- 格式:`工具名：一句用途。`(全角冒号,句号收尾)
- **课案没出现的工具不要补**(哪怕是老约翰常用工具)。

### 萃取范例(俗世奇人课案)

完整范例见 `evals/sushiqiren_extracted.json`,生成效果已对齐样张。摘两支说明纪律:

```json
{ "name": "可视化工具的运用", "children": [
  { "label": "奇人画廊表：把多位奇人放进同一张表，多维度横向梳理人物异同。" },
  { "label": "维恩图：对比两位人物处事方式的异同。" }
]}
```
这两个工具都在课案「介绍工具」小节真实出现,用途也取自课案原话,是**提炼**而非发明。

## 第二步:渲染

### 固定输出目录

> ⚠ 路径与本机环境约定见根 `CLAUDE.md` §1：执行前用 `(Get-Location).Path` 确认实际项目根目录，下文 `<项目根目录>` 代表该路径，禁止硬编码盘符。

**所有产物统一保存到该书专属文件夹（读书会各配套物料共用一夹，目录不存在则先创建）：**

```
<项目根目录>\读书会配套输出\<书名>\
```

文件命名规则：`<书名>_教学导图`（如 `俗世奇人_教学导图.pdf`、`俗世奇人_教学导图.html`、`俗世奇人_教学导图.json`）。

把萃取好的 JSON **存到固定输出目录**(不要只放临时位置)——这份 JSON 是整张图的「内容源头」,PDF 与 HTML 都由它渲染而来,用户日后调整也靠改它:

```bash
python scripts/render_pdf.py "<项目根目录>\读书会配套输出\书名\书名_教学导图.json" "<项目根目录>\读书会配套输出\书名\书名_教学导图"
```

脚本会:
- 注入数据到 `assets/template.html`,生成自包含的 **HTML 源文件**。
- 用 Chromium 无头渲染,**JS 实测每个节点真实坐标后再画弧线**——节点多长、几级、几条,连线起止都自动对齐,无需手填坐标。「教学流程」的三层结构开箱即用。
- 导出竖向 A4 **PDF**,内容超长时页面高度自适应(不截断),中文字体已嵌入(无乱码)。

渲染细节、配色变量、排版约束见 `references/rendering.md`。

最后用 `present_files` 把三个文件一并交付,顺序为 **PDF → 数据 JSON → HTML**。务必把 `data.json` 也交付给用户,并说明:**这份 JSON 是内容源头,日后想改任何文字,编辑它再重渲染即可;不要只改 HTML,改动不会回写到 JSON。**

## 常见问题

- **某条文字太长撑破版面**:回到萃取把说明句压短(样张里每条说明都在一行左右),而不是改版式。环节/策略/工具的说明都保持一行。
- **课时很多导致竖向拥挤**:Grid 自动分布;若挤,精简每课时的环节要点条数(流程只需勾勒,不必穷尽小节)。
- **页面下半留白多**:节点偏少时的自然结果,不影响交付;内容多的书会自动填满。
- **课案信息不足**(如没有明确策略批注):如实告诉用户对应分支会偏薄,请用户确认或补充,不要靠联网/记忆填满。
- **用户分不清要哪种导图**:本 skill 出的是「教学设计」(怎么教);若用户其实想要「书籍精彩抢先看/书的概况」(书是什么),那不在本 skill 范围,先确认意图再动手。
- **用户要调整内容**(改某条说明、删某条、改书名等):
  - **当场改**:直接在已萃取的 JSON 上改对应字段,重跑渲染命令,交付更新后的三件套。
  - **事后改**:请用户提供上次的 `data.json`,基于它修改后重渲染。这正是要把 JSON 作为交付物的原因。
  - 提醒:冒号用全角「：」;删整条就删掉对应的 `{ "label": ... }` 对象,版式会自动收拢。
