# laojohn-course-feedback · 课程反馈话术生成

把一份「老约翰深度阅读」课程详案(.md)转成一份发给**家长社群**的「课后服务内容 —— 社群反馈」话术,输出品牌 .docx + 可直接粘贴的 .md 源件。

## 何时触发

用户提到:生成课程反馈话术、社群反馈、课后家长通知、家长群文案、根据课案生成家长反馈,或上传一份课案 .md 并要求「发给家长的话术 / 课后通知」。即使没说「反馈话术」四个字,只要意图是「把一份读书会课案变成发给家长的课后通知」,也应触发。

**注意区分**:本 skill 产出**面向家长**的社群通知,不是课堂讲稿、不是思维导图、不是 PPT。

## 输入

一份课程详案 `.md`(与 laojohn-lesson-plan / laojohn-lesson-mindmap 共用同一份课案),外加同名**书籍档案** `<项目根目录>\读书会书籍档案\<书名>书籍档案.md`(书目/出版类信息的来源)。

- **书级出版信息(出版社 / 页数 / 字数 / 作者 / ISBN 等):到书籍档案的 `## 海报/指南元数据` 机读块取**——课案不收录这些;值为「(待补充)」视同缺失。
- 从课案可读到:书名、L 级、内容简介、课时安排(导读课 / 阅读交流课1 节或多节 / 思辨&应用课)、每课时三维目标与师生话术、可视化工具、**阅读计划表**(每日任务的结构来源)。

## 输出(两份,同目录)

**默认输出目录**:项目根目录下该书专属的 `读书会配套输出/<书名>/`(与书目卡/海报/阅读指南/两种导图/测评共用一夹)。若目录不存在则先创建。

1. `《书名》_课程反馈话术.docx` —— 复用 `assets/template.docx`,自动继承页眉「老约翰深度阅读 / 阅读·思辨·表达」+ logo + 分隔线 + 标语样式。
2. `《书名》_课程反馈话术.md` —— 同内容纯文本源件,便于编辑 & 直接粘贴微信。

中间产物 `content.json` 也一并写入该目录,便于复核与二次渲染。

## 固定三段结构(恒定,无论课案是几课时)

输出**恒为 3 段**,段间用通栏标语「更好的协助者,成就更好的阅读者!」分隔。

| 段 | 来源课时 | 内容要点 |
|---|---|---|
| 一、导读课后: | 第一课时(导读课) | 开场回顾(开始读哪本书)+ 编号家庭任务,**必含每日阅读页数** |
| 二、交流课后: | 合并**所有**阅读交流课(交流1 + 交流2 + ……) | 课堂回顾(情节脉络/可视化工具/精读片段)+ 1 个家庭小任务 |
| 三、思辨课后: | 最后一课时(思辨&应用课) | 思辨议题回顾 + 对孩子迁移应用的期许(此段通常**无编号任务**) |

每段统一骨架:
```
小标题(一、导读课后:)
亲爱的家长:
您好!
<课堂回顾 + 任务导入正文>
1、<任务名>:<任务说明>
2、<任务名>:<任务说明>
祝小朋友大朋友阅读愉快!
```
第三段(思辨)按范例可省略「祝……愉快」收尾,改为一句对未来的期许。

## 三条硬规则(防 AI 编造)

1. **页数数据硬门**。总页数取自**书籍档案机读块的「页数」字段**;每日阅读节奏取自课案的「阅读计划表」。
   - 若档案给出总页数 + 课案给出阅读天数,可据此换算每日页数(如 263 页 ÷ 7 天 ≈ 每天 38 页),并在话术中写明换算。
   - 若课案的阅读计划表本就按「卷 / 章」而非页数编排(流式电子版常见),**照其章节安排写**,不必硬换算成页数。
   - 若页数信息缺失(档案「页数」为「(待补充)」、课案计划表也无页数):话术里**不提具体页数**——只写章节安排或「按计划读完」,**不写「【请补充…】」之类占位文字**,也**绝不**凭模型记忆杜撰页数。
2. **不伪造引文与事实**。回顾段可适度点名书中真实人物/情节(如苏七块、刷子李、泥人张),但须以课案**实际讲到**的为准;不杜撰原文引语、不编造奖项/销量/作者生平。
3. **不超纲**。只综述课案真实出现的环节(可视化工具名、精读片段、思辨议题),不添加课案未涉及的内容。

## 写作语气

- 对象是家长,口吻**温和、礼貌、平实**,像班主任在家长群发通知。
- 回顾段用概括句铺陈课堂做了什么,可点到具体人物增强代入感,但不展开成讲稿。
- 任务说明要**可执行**:有明确动作、明确范围(读哪几页 / 查什么资料 / 下节课做什么)。

## 执行流程

1. 读课案 .md,抽取:书名、总页数、阅读计划表(总天数/每日页数)、三个课时段的核心内容(导读读了哪两篇、交流课梳理了什么脉络用了什么工具、思辨课讨论了什么议题)。
2. 按「固定三段结构」+「三条硬规则」组织三段文本。页数缺失走占位规则。
3. 写出 `content.json`(结构见 `feedback_to_docx.py` 顶部 docstring)。
4. 运行渲染:
   ```bash
   python feedback_to_docx.py content.json "《书名》_课程反馈话术.docx"
   ```
5. 同步写出 `《书名》_课程反馈话术.md`(三段纯文本,段间空行 + 标语)。
6. 用 present_files 交付两份文件。

## content.json 字段

见 `feedback_to_docx.py` 顶部 docstring。关键:`segments` 为长度 3 的数组,每段含 `heading / salutation / intro / tasks[] / closing`。
