# 读书会下游物料 · 六件套通用纪律（单一源）

**适用**：`book-card`（书目卡）/ `course-poster`（招生海报）/ `reading-guide`（阅读指南）/ `lesson-mindmap`（抢先看导图）/ `teaching-mindmap`（教学导图）/ `course-feedback`（反馈话术）。

六份 SKILL.md 只写**本物料独有**的字段口径、分支填法与红线；下面这些规则六家一致——**改这里等于改六家，禁止再抄回各 SKILL.md**（这套规则此前在六份 SKILL.md 里各存一份，已于 2026-07-28 收敛至此）。

放在 `laojohn-pipeline` 下，是因为编排层本就要逐条讲这套规则。**单跑某一个物料时同样读本文件**，不必先走 pipeline。

---

## 1 路径与环境

> ⚠ 执行前用 `(Get-Location).Path` 确认实际项目根目录，下文 `<项目根目录>` 代表该路径，**禁止硬编码盘符**（项目在移动硬盘，盘符随挂载变动）。

跑任何 python 脚本：用 `python`（**不是 `python3`**，那是 Store 占位别名会 exit 49），并加 `PYTHONUTF8=1`。Playwright 浏览器路径各渲染脚本已内置本机默认回退，通常无需手动设。完整环境约定见根 `CLAUDE.md` §1。

## 2 两段式流程

**萃取（你来做）→ 渲染（脚本来做）。**

- **脚本抽骨架型**（书目卡 / 海报）：① 跑 `extract_fields.py` 得到半成品 JSON（A 类已填、B 类留空、C 类占位）→ ② 你按红线把 C 类填实 → ③ 跑渲染脚本。
- **AI 组稿型**（阅读指南 / 两种导图 / 反馈话术）：① 你按各 skill 的 schema 组出 JSON → ② 跑渲染脚本。

## 3 事实源：书目/出版信息只认书籍档案机读块

出版社 / 字数 / 页数 / ISBN / 出版年 / 译者 / 作者 / 类型 / 主题 / 获奖，**唯一固定源 = `<项目根目录>\读书会书籍档案\<书名>书籍档案.md` 的 `## 海报/指南元数据` 机读块**。

- 课案是教学文档、**不收录**这些字段，所以**绝不从课案正文猜**。
- 机读块里值为「（待补充）」**视同缺失**。
- book-card 与 course-poster 由脚本正则解析（`--profile` 传入）；其余四家由你打开档案读。

## 4 缺失怎么呈现（反编造红线）

「待补充」**只存在于书籍档案**（给人工回填看），**绝不进对外物料**。按物料形态分三种呈现：

| 形态 | 缺失时怎么办 |
|---|---|
| 信息表 / 信息栏（书目卡、海报、指南） | **栏位保留、值留空白**。不写「待补充 / 请回填」、不画占位框 |
| 列表项（导图节点、海报获奖块） | **整条隐藏**，版式自动收拢，不留空洞、不写「XX：待补」 |
| 正文（反馈话术的页数等） | **不提**这件事，不写「【请补充…】」 |

**留空白等人工，胜过编造。** 交付时要主动告诉用户哪几栏留空、按什么规则补。

## 5 绝不联网、绝不凭记忆

事实（书目信息 / 书封 / 页码 / 情节 / 人物）只来自书籍档案与课案，**不因网络搜到或模型记忆而混入**。课案信息不足时如实告诉用户对应栏目会偏薄、请其确认或补充，**不要靠联网/记忆填满**。

唯一放行口：`reading-guide` 的「拓展阅读建议」栏可点名广为人知、确定存在的**其他**作品（详见该 skill）——**绝不外延到本书自身**。

## 6 定位：丢弃教学性细节

面向读者/家长的五件物料（书目卡、海报、阅读指南、抢先看导图、反馈话术）**一律丢弃**课案里的教学性内容：课时安排、师生对白、活动设计、参考答案、PPT 换页标记、可视化工具的操作步骤等。关键动作是**降维改写**——把写给老师的话（「训练推断策略」「让学生体会……」）改写成面向读者的说法。

> **唯一例外：`teaching-mindmap`** 的本分就是梳理「怎么教」，教学目标/流程/策略/工具正是它的内容主体。

## 7 固定输出目录与命名

**所有产物统一保存到该书专属文件夹**（读书会各配套物料共用一夹，目录不存在则先创建）：

```
<项目根目录>\读书会配套输出\<书名>\
```

| 物料 | 文件命名 |
|---|---|
| 书目卡 | `<书名>_书目卡.jpg` / `.html` / `.json` |
| 招生海报 | `<书名>_海报.jpg` / `.html` / `.json` |
| 阅读指南 | `<书名>_阅读指南.pdf` / `.html` / `.json` |
| 抢先看导图 | `<书名>_抢先看.pdf` / `.html` / `.json` |
| 教学导图 | `<书名>_教学导图.pdf` / `.html` / `.json` |
| 反馈话术 | `《书名》_课程反馈话术.docx` / `.md` ＋ `<书名>_课程反馈话术_content.json` |

> 注意反馈话术是唯一**带书名号**的成品命名，其中间产物 json 又不带书名号——这是既有存量口径，勿擅自统一。

## 8 JSON 是内容源头 + 交付

把萃取好的 JSON **存到固定输出目录**（不要只放临时位置）——它是整份物料的内容源头，PDF/JPG 与 HTML 都由它渲染而来，用户日后调整也靠改它。

用 `present_files` 交付三件套，顺序 **成品（PDF 或 JPG）→ 数据 JSON → HTML**，并说明：

- **这份 JSON 是内容源头**，日后想改任何文字，编辑它再重渲染即可；**不要只改 HTML**，改动不会回写到 JSON。
- 哪几栏因缺信息而留空、按什么规则补。
- 用户要调整内容时：**当场改**（本次对话内）直接在已萃取的 JSON 上改字段、重跑渲染；**事后改**（新开对话）请用户提供上次交付的 `data.json` 再改——这正是要把 JSON 作为交付物的原因。

## 9 文字体例

- **弯引号纪律**：JSON 内容字符串里引用词语/短句一律用全角弯引号（左右双引号，嵌套内层用左右单引号），**禁用直角引号 `「」`、禁用英文直引号**——弯引号在 JSON 里无需转义，且与详案正文口径一致（2026-07-22 统一，此前用直角引号的旧口径作废，存量已改重渲）。
- **冒号统一用全角「：」**，说明句以**句号收尾**（对齐样张）。
- 理解类条目统一格式：`概念词：一句说明。`
- **语感**：平实克制，**不用营销腔**（「必读」「神作」「不可错过」「强烈推荐」一律不用）。

## 10 封面图共用目录

需要书封的三家（`book-card` / `course-poster` / `reading-guide`）共用同一个项目级目录，**新增任意一张，三家都能用**：

```
<项目根目录>\读书会书籍封面\<书名>.<ext>
```

- `<书名>` 用纯书名、**不带书名号《》**（例：`俗世奇人.png`）。支持 `.jpg` / `.jpeg` / `.png` / `.webp`。
- book-card、course-poster 的渲染脚本走 `--covers` 参数按书名匹配（自动去书名号/空格/标点容错）；reading-guide 由你把图转 base64 data URI 写进 JSON 的 `cover_image`（HTML 才能自包含）。
- **匹配不到**：海报用 `_placeholder.jpg` 占位、书目卡与指南留空白占位框，并在交付时**明确告诉用户**「封面未匹配、已用占位」，请其按上面规则放图后重渲染。
- **绝不联网找书封**（容易抓错版本），也不凭印象编造封面链接。

## 11 常见问题（六家通用）

- **某栏文字太长撑破版面**：是该条写啰嗦了——回到萃取把说明句压短（样张里每条说明都在一行左右），**而不是改版式**。
- **课案信息严重不足**：如实告诉用户缺哪类信息、对应栏目/分支会偏薄，请其确认或补充，不要填满。
- **想换书重做**：换课案/档案重跑萃取，**模板和脚本不动**。
- **产物文件被占用**（PDF 预览器/WPS 没关）：关掉再重渲。
