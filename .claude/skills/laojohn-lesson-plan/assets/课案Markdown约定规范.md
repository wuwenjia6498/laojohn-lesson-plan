# 课案 Markdown 约定规范（引擎输入格式）

> AI 生成课案详案时按本规范输出 `.md`，固定引擎 `md_to_laojohn_docx.py`
> 读取后自动套用老约翰官方样式生成 `.docx`。
> 设计原则：**全部沿用 AI 已有的自然写法**，只把几个高频骨架约定为可识别标记。
> 引擎对未识别的普通行，一律当作正文段处理，不会报错或丢内容。

---

## 标记速查表

| Markdown 写法 | 渲染为 | 官方样式 |
|---------------|--------|----------|
| `# 标题` | 文档主标题 | 16pt 加粗居中 |
| `## 第X课时 · 课型` | 课时标题 | 14pt 加粗居中黑色 |
| `### 一、环节名（X分钟）` | 节内大标题 | 12pt 加粗左对齐 |
| `**文本**` 单独成行（如 `**知识与技能**`） | 加粗小标题 | 12pt 加粗 |
| `师：……` | 师话 | 整段 12pt 加粗 |
| `参考：……` | 参考 | “参考：”加粗领起，内容不加粗 |
| `学生互动分享` / `学生自由分享` | 学生分享提示 | 12pt 常规 |
| `【知识技能】……`（行首方括号标签） | 三维目标条 | 标签加粗，内容常规 |
| `> 引用文字` | 原文摘录 / 宣传语 | 12pt 左右缩进 |
| `【图位:插-01｜图注】` 单独成行 | 原书插图占位 | 无图版原样印出(＝一条可读的备课提示);配图版由 `insert_images_docx.py` 换成真图+灰色小字图注,详见下文「原书插图」一节 |
| ~~`【PPT换页-PXX】`~~ | **已废弃·新稿不写** | 引擎仍渲染橙色(向后兼容旧 docx),但新详案不再产出换页点 |
| `本课完。` / `全课完。` | 收尾 | 右对齐加粗 |
| 标准 Markdown 表格（`\|` 分隔） | 表格 | Table Grid + 米色表头 |
| `- 项` / `1. 项` 列表 | （**不要用**）正文段 | 引擎会剥掉 `-`/`数字.` 标记，但**列举一律改用顿号或分行正文**，详见下文“列表”一节 |
| 其它任意行 | 正文段 | 12pt 常规，行距 1.5 |

## 详细约定

### 1. 标题层级
```
# 四年级《手斧男孩》整本书教学设计

| 教案提纲 |  |
| --- | --- |
| 一、文本分析 | 作品和作者 |
| …（七行，见 style-and-format.md） |  |

## 第一课时 · 导读课

### 一、情境导入·话题激趣（15 分钟）
```
- 阅读（整本书）详案的文档主标题固定 `# <年级>《<书名>》整本书教学设计`（年级用中文，不写 L4/L5）；**标题后直接接「教案提纲」表格，不加副标题/元信息行**。（写作课详案的标题/字段另见 `laojohn-writing-lesson` SKILL。）
- 「教案提纲」表头写 `| 教案提纲 |  |`（第二列留空），引擎自动把表头合并为横跨全表的居中单元格——读写两类详案通用。
- `#` 只用一次（文档主标题）。
- `##` 用于每个课时标题。
- `###` 用于课时内 “一、二、三…” 环节标题。

### 2. 师生话术
```
师：亲爱的同学们大家好。今天我们要打开一本"野外"的书。
学生互动分享
参考：最担心的可能是没有食物、没有水、遇到野兽……
```
- 行首是 `师：`（中文冒号，半角 `师:` 也兼容）→ 师话，整段加粗。
- 行首是 `参考：`（或 `参考:`）→ 参考段。
- 整行等于 `学生互动分享` / `学生自由分享` / `学生分享` / `学生分组汇报` 等 → 学生分享提示。

### 3. 三维目标
```
**本节三维目标**
【知识技能】认识作者与"手斧男孩"系列；通过封面封底获取关键信息。
【过程方法】训练预测、提问、联结三项策略。
【情感价值】激发"我能否独自生存54天"的代入式思考。
```
- `**xxx**` 单独成行 → 加粗小标题。
- 行首 `【标签】内容` → 三维目标条（标签加粗、内容常规）。

### 4. PPT 换页点（已废弃）

> **新详案不再写 `【PPT换页-PXX】`。** 分页权已交给下游 `laojohn-ppt-draft`，由它按"教学节拍"自行切页，详案只需保留 `## 第N课时` / `### 一、xx` 的课时与环节结构。
>
> docx 引擎仍保留对换页点的橙色渲染（向后兼容历史 docx），但生成新详案时不应产出换页点。

### 5. 原文摘录 / 宣传语（引用块）
```
> “这是一个十三岁男孩独自在荒野中生存五十四天的故事。”
```
- 用 Markdown 引用 `> ` 开头 → 缩进引用样式。
- **占位规则不变**：无真实原文时仍写
  `（教师朗读【待补：第X章……以实际版本为准】）`，作为普通正文行即可，不要用 `>`。

### 6. 表格（标准 Markdown 表格）
```
| 我猜会发生的事 | 我的依据是…… | 读完是否被证实 |
|---|---|---|
| 例：布莱恩会砍出避难所 | 书名叫《手斧男孩》 |  |
|  |  |  |
|  |  |  |
```
- 第一行 = 表头（渲染米色底、加粗）。
- 第二行是 `---` 分隔行（标准 Markdown，引擎自动跳过）。
- 空单元格留空即可（用于学生填写的空白阅读单）。
- 单元格内如需换行，用 `<br>`。

### 7. 引号

**一律使用中文弯引号，严禁 ASCII 直引号。**

| 用途 | 正确写法 | 错误写法 |
|------|----------|----------|
| 双引号（普通引用、术语） | `"内容"` | `"内容"` |
| 单引号（嵌套在双引号内） | `"他说'不行'"` | `"他说'不行'"` |

- 双引号：`"` (U+201C) 开、`"` (U+201D) 闭。
- 单引号：`'` (U+2018) 开、`'` (U+2019) 闭；仅用于双引号内嵌套。
- **交付前自检**：对 `.md` 全文检索 ASCII 直引号 `"`(U+0022) 与 `'`(U+0027)（Markdown 语法/代码除外），命中即就地改为弯引号；弯引号与直引号不可混用。
- `md_to_laojohn_docx.py` 内置安全网会在转 docx 时对**整篇**文本一次性补转 ASCII 直引号（不可逐行，否则跨行引用块/长台词的闭引号会被误判为开引号），但**源 `.md` 本身就应写正确，不依赖安全网**。
- 若源文件含**奇数个** ASCII 引号，交替转换的左右方向可能判反，脚本会额外警告——此时必须回到源 `.md` 核对，不可只看 docx 以为已正确。

### 8. 列表（避免使用）

引擎**不把 Markdown 列表当列表渲染**：`- 项` / `1. 项` 这类行会被当普通正文，引擎只剥掉行首的 `- ` 或 `1. ` 标记，剩下文字平铺成段。所以列表越用越乱（多项会挤成一段或一行一行无层次）。

**规则**：详案里凡是“列举”，一律改写成下面两种之一，不要写 Markdown 列表——

- ❌ 不要：
  ```
  本节训练：
  - 预测
  - 提问
  - 联结
  ```
- ✅ 顿号铺平（短列举）：`本节训练预测、提问、联结三项策略。`
- ✅ 分行正文（每项较长、需独立成段时）：每项单独成一行普通正文，行首不加 `-`/数字，必要时用“第一，…／第二，…”或“①…②…”自然语序领起。

> 真正需要“表格化”的并列内容（阅读单、对照维度、可视化工具骨架），用第 6 节的 Markdown 表格，不要用列表。

### 9. 收尾
```
本课完。
```
- 每课时末写 `本课完。`，全文末写 `全课完。` → 右对齐加粗。

### 10. 原书插图（可选；只在确需画面支撑时才写）

低段（L1/L2）等确需直观支撑的课，可把**原书插图**回插进详案 docx，供老师备课时一眼对上"这一环节对应书上哪幅画"。

**图片落点**（跨链路共享的输入资产，不是某个 skill 的产物）：

```
读书会原书插图\<书名>\插-01.png     # 书名不带书名号，与 读书会书籍封面\ 同口径；也认 .jpg/.jpeg
读书会原书插图\<书名>\_图单.md      # 每张图的出处/画面描述/拟用环节；入库
```

- 编号 `插-NN` 两位、**全书连号**（不按课时重起号）、**半角**连字符（全角 `插—01` 会静默插 0 张）。
- **扫描件本身不入 git**（版权材料，根 `.gitignore` 已挡）；`_图单.md` 入库，是唯一可追溯凭据。
- **书籍封面继续留在 `读书会书籍封面\<书名>.png`，绝不挪进这个新目录**——引擎找不到封面是**静默跳过**，一挪就丢封面页且不报错。

**正文写法**：

```
师：马良给村里人画水车这一幕，书里就有一幅画。请翻到《神笔马良》中间几页，找到画着水车的那一幅。（稍停顿）画里围过来的这些人，在做什么？

【图位:插-01｜《神笔马良》马良给村里人画水车】
```

- **指图的师话是给学生的课堂指令，不是解说腔**。学生手上有书、图是让他们自己翻到看的（回插的图只是教师详案里的对照），所以一句话说完三件事：① 书里有画（一句带过）→ ② 怎么找到（篇名/位置 + 一眼能认的画面特征）→ ③ 看什么（具体观察问题）。
  - 禁 `书上也画出来了`／`这一幕书上也有画`／`书上其实都画着呢`／`正好有一幅画`——这是旁白式口播，不是老师的话；同一份详案多处指图也别连用同一个字（三处都写"也"即为重复）。
  - 找图指令别写成谜语：`找到有一大朵云、云里站着个白胡子老人的那一幅` → `找到画着一朵大云的那一幅`（长串定语让学生猜画面，课堂上会卡住）。
  - **说"都有画"前先数清真有几张对得上**：参考答案只能对上 4 步，就不能写"这五步书上都画着呢"（学生照话去找会找不齐）；写"有好几步书里配了画……找到几幅算几幅"。
- 占位**单独成行**，紧跟触发它出图的那句师话。
- 全角 `｜` 之后是图注，渲染为图下方一行灰色小字（10.5pt）。图注只交代**哪一幕/原书哪一篇哪个场景**，**不复述师话原句**，也**不以「书上这一幕」「书里这一幕」这类前缀开头**（图注就印在图片下方给教师看，"书上"是废话，直接写画面）。
- **每个环节最多 2 张**；插图要服务具体教学动作（"看画面说说"/"回顾时重走故事线"），**不做装饰性配图**。可参照 `references\lesson-templates.md` 的「阅读回顾：借插图/关键画面带学生重走故事线」。
- 行内写法（占位跟在师话尾部）机制上也支持——图会另起一段落在师话下方、师话不会被吞——但本规范一律要求独占一行。

**禁止 `![alt](path)`**：引擎不解析 Markdown 图片语法，会把叹号方括号连路径**一字不差印进 Word**。详案里图片的唯一写法就是上面的占位。

**出配图版**（只有跑这条命令才会出图；**无图版 docx 永不被覆盖**）：

```
PYTHONUTF8=1 python .claude/skills/laojohn-lesson-plan/assets/insert_images_docx.py \
    "读书会详案输出/<书名>-课案详案.md" --profile lesson
```

产出 `<书名>-课案详案-配图.docx`。交付前先加 `--check-only` 跑一次，核对「正文占位 / 目录真图 / `_图单.md` 登记」三方无缺口；有灰字「待补」提示的 docx 不得当成品交付。

**预埋提醒**：下游物料（PPT 中间稿、阅读单、反馈话术等）一律读 `.md` 源，会把 `【图位:…】` 行当普通正文吃进去。目前只有详案 docx 这一条链路认这个占位；将来若给读书会铺开插图，各下游解析侧需相应加一条"忽略 `【图位:…】` 行"的过滤。

## 附:引擎自动版式(改 `md_to_laojohn_docx.py` 前必读;生成 .md 时无需了解)

> 本节自 style-and-format.md 移入:这些全是引擎导出时的自动行为,与"怎么写 .md"无关,仅供改引擎/调封面时查阅。

- **封面页(第1页)**:导出 docx 时自动在正文最前插入一页品牌封面,**全部是原生可编辑元素(非整图)**——浮动图片 + wps 文本框 + 形状,在 Word 里可单独点选/移动/改字/换图。版式对齐品牌样张:右上圆形 logo + 其下 navy「阅读·思辨·表达」(单独文本框,右对齐到 logo 右边缘) / 竖排「老约翰深度阅读」(墨色粗体,上移靠近副标、右对齐到同一右边缘)+左列《书名》「教学设计」(竖排框,《》Word 自动竖排形;书名与教学设计间无空格) / 左侧书封(略小) / 书封**下方**获奖语(★前缀,自动去源串多余前缀,不与书封重叠) / 右下角珊瑚粉 **贴角 1/4 圆**(整圆圆心置于纸张右下角、被页边裁出 1/4,弧朝页内)+年级。数据源:书名取自 H1《》;级别与获奖取自 `读书会书籍档案/<书名>书籍档案.md` 机读块的 `等级`/`获奖`(短字段,空则隐藏,见 CLAUDE.md §2);书封取自 `读书会书籍封面/`;logo 取自 `品牌资产/logo-01.jpg`(圆形徽标,**不含「阅读·思辨·表达」**——该副标由文本框单独画;缺失回退 `logo.png`)。所有元素**锚定到「页面」**(`relativeFrom=page`),与页边距无关即可贴边。**封面独立分节·零页边距**:封面是 `sections[0]`(A4、零边距)→ Word「显示文字边界」的四角标记被挤到纸角/几乎不可见(那本是视图辅助、不打印);正文另起一节(正常边距、页眉只在正文节、页码从1)。无书封则整页跳过(如写作课,全文单节)。坐标/字号/配色为常量,集中在 `render_cover_page()`,需微调改那里。
  - **几个已踩坑(改封面前必读)**:① **文本框用 wps DrawingML**(`_add_textbox`),**不要用 VML**——VML 文本框在交互式 Word 里会错位堆到左上角(导出 PDF 却正常,易误判)。② **贴角 1/4 圆徽标用整圆(`prstGeom=ellipse`)**:把圆心放在纸张右下角 (x=21-d/2, y=29.7-d/2)、被页边自然裁出左上 1/4——比 `pie` 角度可靠(`pie` 的 `adj2=21600000`(360°)会被钳位、角度方向也反直觉,放弃)。③ logo 必须用 `logo-01.jpg`(干净),早期的 `logo-emblem.png` 自带「阅读·思辨·表达」栅格,会和文本框副标重叠出"灰色幽灵"。④ 验证封面用 Word COM 导 PDF 再渲染(`WINWORD.EXE` SaveAs 17 + PyMuPDF)。
- **文本介绍处书封**:`### 一、文本介绍` 标题下方另插入一张书籍封面(同一取图规则);找不到则静默跳过。
- **正文插图不归本引擎**:引擎自身的图片能力**只有上面两处封面**,正文里的原书插图由二段式后处理层 `insert_images_docx.py`(同目录,跨技能共享件,见 CLAUDE.md §3)承担——先调本引擎出基础 docx(占位原样印为文字),再用 python-docx 把 `【图位:编号】` 换成真图。**故引擎侧无需、也不应新增 `![](…)` 解析分支**(那会牵动全部 5 个消费者一起回归)。课型差异收在该件顶部 `PROFILES` 表。
- **间距**:主标题↔教案提纲表、表↔文本介绍、三个书级章节之间、【内容简介】↔【作者介绍】之间,均自动空一行。
- **教案提纲表**:合并表头居中、第一列窄(1.6cm)、单元格垂直居中、行高加大——均由引擎处理。
