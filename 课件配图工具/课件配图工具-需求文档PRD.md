# 课件配图生成工具 · 需求文档（PRD）

> 版本：v1.0 草案
> 交付形态：内网/公网可访问的 Web 应用，团队多人使用
> 开发方式：Claude Code 开发，部署到公司服务器或云主机
> 生图通道：豆包 Seedream API（火山方舟）
> 文本智能通道：Claude API（详案解析与画面清单生成）

---

## 1. 项目概述

### 1.1 背景

老约翰同步习作/深度阅读的课件制作中，为每页 PPT 生成与文案匹配、风格统一的插画占了大量工时。已通过《猜猜他是谁》课件完成一次逆向打样，验证了"详案 → 画面清单 → prompt 包 → 生图 → 验收"的流程可行。现将该流程产品化，让内容团队同事无需懂 prompt 工程即可自助产出课件配图。

### 1.2 目标

- 同事上传一份课案详案（或逐页粘贴文案），工具自动产出该课件的风格基调卡、主角色定妆和逐页画面清单
- 每页画面一键生成、对照"必现细节"勾验、不满意可改可重跑
- 同一课件内所有图片风格与人物统一；不同课件相互独立
- 成图按规范命名打包导出，直接可插入 PPT

### 1.3 非目标（明确不做）

- 不做 PPT 排版/自动插图到 PPT（图片导出为止）
- 不做跨课件的固定角色班底（人物统一以单课件为边界）
- 不处理版权 IP 形象的生成（此类画面标记"人工素材位"，由人另行处理）
- V1 不做手机端适配（桌面浏览器优先）

## 2. 用户与角色

| 角色 | 人群 | 权限 |
|---|---|---|
| 管理员 | 文佳 | 全部功能 + 规则库配置 + 用户管理 + 用量/成本查看 |
| 制作者 | 内容团队同事 | 创建/编辑自己的课件项目、生成与验收图片、导出 |

- 登录方式：账号密码即可（人数少，不需要接微信/OA）。管理员后台建账号。
- 项目默认仅创建者和管理员可见，可选"团队可见"。

## 3. 核心工作流（产品主线）

```
① 建项目 → ② 上传详案/录入逐页文案 → ③ AI 生成风格基调卡（可编辑）
→ ④ 生成主角色定妆 →【人工验收闸门 1】
→ ⑤ AI 生成逐页画面清单（可编辑）
→ ⑥ 生成风格锚图 →【人工验收闸门 2】
→ ⑦ 逐页批量/单页生成 → ⑧ 对照必现细节勾验、改写重跑
→ ⑨ 导出成图包
```

设计原则（沿用既有工作方法论）：

- **两道人工闸门不可跳过**：定妆图未验收不得进入批量生成；风格锚未验收不得生成其余全彩页。闸门即"不可逆节点设人工判断"原则的产品化。
- **AI 产出全部可编辑**：风格卡、画面清单、prompt 均为草稿态，人改完才是生效态。
- **严禁编造**：详案解析抽不出的信息留空并标注"待补充"，不允许 AI 自行脑补页面内容。

## 4. 核心概念与数据模型

| 实体 | 关键字段 | 说明 |
|---|---|---|
| 课件项目 Project | 名称、年级、单元、课题、状态、创建人 | 风格与人物统一性的边界 |
| 风格基调卡 StyleCard | 画风档、色板、人物年龄设定、场景基调、概念母题、通用风格前缀、通用禁区 | 每项目一张；前缀文本即生图时自动拼接的第一段 |
| 角色 Character | 类型（主角色/内容角色）、定妆图（正面标准像/动态姿势）、剪影转制图、验收状态 | 主角色定妆图作为参考图跨页挂载 |
| 画面条目 SlideImage | 页码、用途类型（情境/示例配图/装饰/道具/IP另处理）、画幅比例、角色类别、必现细节清单[]、prompt 正文、挂载参考图[]、状态 | 一页可有多条 |
| 生成任务 GenTask | 所属条目、完整 prompt、参考图、模型参数、返回图、耗时、费用估算 | 每次生成留档，形成版本历史 |
| 规则库 RuleSet | 规则文本、启用开关、适用范围 | 管理员可配置，见 §7 |

**状态机（画面条目）**：`草稿 → 待生成 → 生成中 → 待验收 → 已通过 / 需重跑`。
必现细节逐条勾选，全勾才能标"已通过"；有未勾项标"需重跑"并要求填一句原因（原因沉淀为规则库素材）。

## 5. 功能需求

### FR-1 项目管理
- 新建/复制/归档课件项目；列表展示进度（已通过 x/总条目 y）
- 复制项目时可选择"仅复制风格卡与规则"（用于同年级系列课的风格延续）

### FR-2 详案解析（Claude API）
- 支持上传 .docx / .md / 粘贴纯文本；也支持跳过详案、手动逐页录入文案
- 解析输出：① 风格基调卡草稿（含从课题提炼的概念母题建议）② 逐页画面清单草稿
- 清单每条必须给出：画面用途类型、必现细节（**逐条标注来源原文句**，点击可溯源）、建议画幅、建议角色类别
- 检测到真人影视形象/版权角色（如超人）时自动标记〔IP另处理〕并给出替代建议，不进生成管线

### FR-3 风格卡与定妆
- 风格卡表单化编辑；修改通用前缀后，所有未生成条目自动继承新前缀，已通过条目不受影响
- 主角色定妆：一键生成"正面标准像 + 动态姿势"两张 → 验收界面（通过/重跑，重跑可改描述）
- 定妆通过后一键生成剪影转制版（走豆包图像编辑能力：参考定妆图 + "转为深蓝色纯剪影"指令）

### FR-4 画面清单编辑器（工具的主工作台）
- 表格视图：页码 / 类型 / 画幅 / 必现细节 / prompt / 挂载 / 状态 / 缩略图
- prompt 编辑区自动展示"将实际发送的完整内容"预览 = 通用前缀 + 条目正文（同事所见即所发，不需要理解拼接逻辑）
- 挂载栏为可勾选项：定妆 A / 定妆 B / 风格锚 / 自定义上传参考图（≤ 豆包上限）
- 支持新增条目、删除条目、从别页复制条目

### FR-5 生成引擎（豆包 Seedream API）
- 单条生成 / 按状态批量生成（仅生成"待生成"态且闸门已过的条目）
- 每次生成默认出 2 张候选供挑选（可配 1–4）
- 画幅比例映射到 API 尺寸参数：1:1 / 3:4 / 4:3 / 16:9 预设 + 自定义
- 任务队列串行或低并发执行（默认并发 2），失败自动重试 1 次，仍失败标红并保留错误信息
- 生成历史完整留档：同一条目的历次结果可翻看、可回滚选用旧图

### FR-6 验收与重跑
- 验收界面左图右单：左侧大图，右侧必现细节 checkbox 逐条勾验
- "重跑"提供两条路径：① 改 prompt 重生成 ② 走豆包**图像编辑**通道对已有图做局部修改（形状/风格类改动优先走编辑，省 token 且保住已通过的部分）

### FR-7 导出
- 打包 zip，命名规范：`课名-P页码-用途-序号.png`（如 `猜猜他是谁-P16-示例配图-01.png`）
- 附一份导出清单（csv）：文件名 / 页码 / 画幅 / 验收人 / 时间

### FR-8 规则库配置（管理员）
- 规则以条目形式管理，可启停，分三类：
  ① **前缀级**（拼入所有 prompt，如头身比、画风描述）
  ② **组装级**（prompt 生成规则，如"数量用'画面中恰好 N 个'正向表述"）
  ③ **校验级**（清单质量检查，如"情境类条目必现细节 ≥ 3 条方可进入待生成"）
- 规则修改仅影响其后新建/重生成的条目

### FR-9 用量与成本
- 管理员面板：按项目/按人统计生成次数与费用估算；可设每项目/每日生成上限，超限提示找管理员

## 6. 外部接口

### 6.1 豆包 Seedream（火山方舟）
- 接入实际已开通的模型版本（Seedream 4.x/5.x 系列，统一生成-编辑架构），API Key 只存服务端环境变量，前端永不接触
- 需要用到的能力：文生图、参考生图（多参考图：定妆 + 风格锚）、图像编辑（剪影转制、局部修改）、比例/尺寸控制
- 组图/序列生成能力 V1 不用（每条目独立生成，保证与清单一一对应）

### 6.2 Claude API
- 用于：详案解析、风格卡草稿、画面清单草稿、prompt 正文草稿、重跑时的 prompt 改写建议
- 解析提示词内置"严禁编造、留空标注待补充、必现细节须溯源原文"约束

## 7. 关键风险与首周验证清单（开发前置）

既有经验规则是在 Gemini 上验证的，**迁移到豆包前必须逐条重验**，验证结果写入规则库：

| 待验证项 | Gemini 结论 | 豆包待验 |
|---|---|---|
| 头身比控制 | prompt 文本无效，靠参考图 | ？ |
| 禁止式表述 | 无效，只认正向数值 | ？ |
| 局部编辑可靠性 | 形状/风格可靠、数量不可靠 | ？（豆包编辑能力更强，边界可能不同） |
| 画面内中文 | 不可靠，一律版式层承担 | ？（豆包中文渲染强，或可放开部分场景，如书封；建议仍默认关闭、规则库开关控制） |
| 多参考图权重 | — | 定妆图与风格锚同挂时谁主导、如何用文字指定"人物参考第 1 张、风格参考第 2 张" |

验证方式：拿《猜猜他是谁》打样清单的最小验证集（定妆 A、P6 跨页一致性、P16 文案细节锁定、剪影转制）在豆包上重跑一遍，作为开发首周任务。

其他风险：
- **详案格式不一**：同事的详案未必都是标准 SKILL 产出格式 → 解析层按"能抽多少抽多少 + 缺口标注待补充"设计，不追求全自动
- **成本失控**：批量重跑叠加多候选图 → FR-9 限额 + 默认候选 2 张
- **审美验收标准不一**：必现细节 checkbox 把验收从"感觉"变成"勾单"，但风格观感仍需管理员在闸门 1、2 把关——建议 V1 阶段两道闸门的验收权限仅开放给管理员

## 8. 非功能需求

- **部署**：Docker 单机部署（公司服务器或火山引擎 ECS 均可，豆包 API 国内直连无出海问题）；数据库 SQLite/Postgres 皆可（并发低）；图片存本地盘或对象存储，按项目分目录
- **安全**：全部 API Key 服务端持有；登录态 session；导出包仅项目成员可下载
- **可靠性**：生成任务异步队列，浏览器关闭不中断；所有 AI 调用记录完整请求与响应日志（排查"为什么生成成这样"时可回放）
- **性能**：非高并发场景，单课件 15–20 条画面、2 候选、串行生成在 10 分钟量级可接受

## 9. 里程碑建议

**MVP（先跑通主线）**
项目管理 + 手动录入逐页文案 + 风格卡编辑 + 定妆生成与闸门 + 画面清单编辑器 + 单条生成 + 勾验 + 导出。
（详案自动解析可后置——MVP 阶段清单由人工按模板填，等于把打样清单搬进网页）

**V1（全自动主线）**
详案上传解析（Claude API）+ 批量生成 + 生成历史/回滚 + 剪影转制 + 图像编辑重跑通道

**V1.1（团队化）**
账号权限 + 用量成本面板 + 规则库配置界面 + 项目复制

## 10. 验收标准（整体）

1. 一名未接受过 prompt 培训的同事，拿一份详案在 1 小时内独立产出一套通过验收的课件配图（不含排队生成时间）
2. 同一课件内主角色在所有出现页目检为"同一个孩子"（发型/镜框/服装三要素一致）
3. 任一"示例配图"类画面，其必现细节可 100% 溯源到详案原文句
4. IP 版权形象零生成（全部落在"人工素材位"）
5. 管理员可查任意一张成图的完整生成链路（prompt 全文、参考图、参数、历次版本）
