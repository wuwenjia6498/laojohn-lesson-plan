# 课件配图工具 · 本地单机版

跑在自己电脑上，浏览器开 `http://127.0.0.1:8848`。

```bash
pip install -r 课件配图工具/web/requirements.txt
PYTHONUTF8=1 python 课件配图工具/web/server/main.py
```

密钥读 `课件配图工具/.env`（与 CLI 同一份），右上角会显示当前通道与模型；
缺密钥时那里变红并说明原因，不会静默进假数据。

## 它和命令行是同一套东西

数据全部落在既有文件布局上，**没有另建数据库**：

| 存什么 | 落在哪 |
|---|---|
| 项目（风格卡 + 角色件 + 画面清单） | `课件项目/<项目>.json` |
| 定妆件 / 页目图 | `课件产出/<项目>/<通道>/角色·页目/` |
| 验收记录 | `课件产出/<项目>/<通道>/_验收记录.json` |
| 拆解中间产物 | `拆解底稿/` |

所以 **CLI 跑的项目 Web 能打开，Web 建的项目 CLI 能接着跑**。这是有意的：
命令行仍是排查问题最快的路子，产品化不该把它废掉。

服务端不含任何判据，拆解/生图/验收/导出全部 importlib 载入 `scripts/` 下那四个脚本；
规则库唯一源是 `拆解规则.md`，网页上只读展示。

## 两道闸门：定妆硬、页目软

- **定妆未验收 → 拒绝批量生成页目**（HTTP 409）。定妆图是后面每一页的人物基准，
  它错了这一批全得重来，这道门挡住的是成批的浪费。
- **页目验收不拦生成，拦导出**。生成随时可跑、可改可重出；但往外交付要有人签字。
- 验收一律要填姓名 —— 没有名字的验收等于没验收。

清单里的勾验框是给人自己对账用的，**机器不看**：比喻拆没拆、必现细节准不准、
画面对不对，程序判不了。

## 新建项目要传两份

**课件 pptx** 决定哪页要图、什么画幅（`extract_deck.py` 按面积占比量出来的，是事实）；
**教学详案** 决定画什么。少了 pptx 就只能让模型猜页码 —— 实测手抄清单错位 1–3 页。

详案带页标回注（`〖PPT 第6页 · …〗`）时会自动按页切段喂给模型，`来源` 字段就是照着抄；
没有页标则整篇喂，退化但不报错。

## 已知边界

- 单进程、任务状态在内存：**服务重启后正在跑的任务会丢**，重新发起即可（图已生成的不会重复扣费）。
- 没有登录、没有多用户。要给同事用得先加对象存储 + 数据库 + 账号，不是本版范围。
- 生图 30–60 秒一张，一律后台跑 + 轮询，界面显示逐条日志。
