# 同步习作批改助手 · 网页应用（Phase 3）

老师课后连拍全班稿纸，按**本课详案抽出的三条判据**逐份出批语与家长点评卡，
再看一份班级共性诊断。定位是**教师草稿与服务凭证**，不是自动打分机。

## 批的是哪几层

**三条判据是主判据，档位只由它们定**——那是学生当堂听过的话，也是这工具相对通用 AI
批改的唯一护城河。但只看这三条，三十篇会批出三十条一个样，所以另有三层：

| 层 | 干什么 | 进不进档位 |
|---|---|---|
| 三条判据 | 这次课教的学会没有 | **是**，档位只由它定 |
| 整篇三项（完整性／顺序／读不读得通） | 更底下的地基。半截停住、前后跳、句子绕不出来 | 否，给老师参考 |
| 亮点（他自己写得好的） | 用得准的词、有意思的句式、别人想不到的观察 | 否，是点评卡的原料 |
| focus（这一篇最值得说的一件事） | 决定点评卡从哪儿切入 | 否 |

三条约束别改掉：**亮点允许一条都没有**（硬凑就是假话，家长看得出）；**整篇三项不要直接
跟家长说**（"你孩子逻辑乱"不是能发到群里的话）；**点评卡只说 focus 那一件事**，
不因为多了维度就往里塞——面面俱到本身就是另一种模式化。

判断规则的措辞在 `作文批改工具/build_prompt.py` 的 `judging_rules()` 与
`parent_card_rules()`，**Phase 0 的提示词模板和这里的服务端共用同一份**。

## 选课页为什么按数量变形

写作课线规划 **63 课、8 个年级册**，但批改标准包是一课一课铺的（现在 14 课、5 个年级册）。
所以选课页**按课次数量自动切形态**，而不是写死一种：

| 条件 | 形态 |
|---|---|
| ≤ 6 课，或只有一个年级册 | 平铺，跟没做分组时一样 |
| 更多 | 按年级册折叠，默认只展开一册 |
| ≥ 8 课 | 显示搜索框 |
| 搜索中 | 平铺显示命中结果，不分组 |

两课还摆个折叠面板是给自己加戏；六十课平铺则每次批作业都要滚半天。逻辑在
`app.js` 的 `renderLessons()`，改阈值改那几个数字即可。

**最近用过**置顶（`localStorage`，最多 3 条）——老师批一个班是同一课，连着几天多半
还是它。这里只存 lesson_id，是本地偏好、常驻不过期；学生数据走另一条路——见下面
「本机暂存」一节，那份 24 小时自动清。两者生命周期不同，别混进同一个 key。
⚠ 从批改页返回时**必须重渲选课列表**，否则刚选的那一课要等下次冷启动才进最近区。

**排序不要用文件名。** `load_packs()` 按 `grade_of()` 解析出的 (年级, 上下册, 单元)
三元组排。按文件名字符串排会让「第十单元」排到「第二单元」前面，册次顺序也不保证——
两课看不出来，课次一多就乱。`lesson_id`（`3a-u1-…`）本身带着可排序数值，解析不出的
退回 `meta.grade_volume`，再不行就丢到最后、不打乱前面。

**只显示有标准包的课。** 不要从 course-map 读全部 63 课再标记「是否已接入」——老师
打开工具看到 63 课、其中 61 课点不动，是糟糕的体验。标准包铺到哪儿就显示到哪儿。

## 引用为什么能保证一字不差

这是整个产品可信度的地基：老师会拿着点评卡对稿纸看，**引错一个字，他就再也不信这个
工具了**。而 0820 实测发现，`gemini-2.5-flash` 与 `gpt-4o` **都会**在复述时不自觉改写
原句——漏字（「可是过了一会儿」→「可是一会儿」）、加字（「说：」→「他说：」）、
全角逗号写成半角、用省略号把相隔很远的两处拼成一句。**提示词按不住，这是模型的复述本能。**

所以改成程序保证：模型先输出整篇 `transcript`，服务端的 `fix_quotes()` 拿它当基准，
把每处引用对回原文——

| 情况 | 处理 |
|---|---|
| 逐字找得到 | 原样留 |
| 去掉标点后找得到 | 用 transcript 里的真实片段**替换**模型写的版本 |
| 漏字改字（总匹配率 ≥85%、区间不超长） | 同上，替换 |
| 省略号跨接（区间远长于引用本身） | **拒绝**，标 `_suspect` |
| 查无此句 | **拒绝**，标 `_suspect` |

标了 `_suspect` 的，前端显红并提示「与原文对不上，核一下」；点评卡引的那句若可疑，
详情页顶部直接拦一条警告。**宁可标可疑，也不能错误校正成原文里的另一处**——所以
`_locate_fuzzy` 的两个门槛（`cover` / `span`）偏保守，别为了少几个红标去放宽。

`transcript` 只用于校验，**不下发给前端**——老师手上有原稿，不需要看打字版。

## 回归测试

改提示词、换模型之后必须跑：

```bash
PYTHONUTF8=1 python 作文批改工具/web/server/make_test_sheets.py   # 生成三张基准稿纸
PYTHONUTF8=1 python 作文批改工具/web/server/run_regression.py      # 用 config 里的模型
PYTHONUTF8=1 python 作文批改工具/web/server/run_regression.py gpt-4o  # 或指定模型
```

三篇基准是**刻意设计的三种形态**（并列罗列／有特点无画面／特点＋画面），判断层能不能
把它们区分开，就是这个工具可不可用的分水岭。脚本自动核五件：引用逐字、判据方向、
`depends_on` 有没有被遵守、点评卡起头撞不撞、有没有越界提错别字。

**素材里埋了两处错别字「经长」**——模型必然读成「经常」，这正是「错别字层不做」的
由来；脚本的 `TYPO_READ` 会先把原文规范化再比对，别把这个预期行为当成 bug 去修。

## 模型选型（0820 实测）

`grade_model` 定为 **`gpt-4o`**。同样三篇基准各跑一轮：

| | gemini-2.5-flash | gpt-4o |
|---|---|---|
| 引用准确 | 转写会漏字、标点半角 | 明显更准 |
| 点评卡口气 | 对着学生说话、起头雷同 | 对家长说，起头各不同 |
| 姓名 | 3/3 | 2/3（读错过一个） |

flash 唯一强项是姓名，但**姓名前端可以手改，引用错不了才是要紧的**。
换模型只改 `config.json` 一行、不动代码，**但换完必须重跑 `run_regression.py`**。

## 六条别改坏的

1. **密钥只在服务端。** 前端不接触 api_key、不直连模型网关。
2. **服务端不落盘。** 学生作文原图与全文不写文件、不进日志，收到即用、用完即弃。
   **前端另说**：批语与压缩图存进老师手机的 IndexedDB，**不回传服务端**。
   两种寿命：**批语永久留**（历史，老师自己删），**图只留一天**（暂存，
   为了「批一半被打断能接着批」；一份批完时立刻丢）。存的是压缩图不是原图。
   这两层必须分开讲，别混成一句「什么都不存」——嘴上说不存、手机里躺着三十张
   稿纸，比不做这个功能更糟。详见下面「本机暂存」一节。
3. **判据与判断规则的唯一源都在 `build_prompt.py`。** `main.py` importlib 载入它的
   `render_pack()`（课次判据）、`judging_rules()`（怎么判）、`parent_card_rules()`
   （点评卡要求），**与 Phase 0 的提示词模板共用同一份措辞**。要改判据去改
   `标准包/*.json`，改规则去改那三个函数——**别在 `main.py` 里另写一套**，
   两处各写一份必然分叉，且分叉不报错，只会让加盟商手上那份和线上判得不一样。
4. **逐份串行，且把已生成的点评卡开头传给下一份**（`prev_heads`）。一个班
   二三十份发同一个家长群，句式撞车这工具就废了——改成并发这道防线即失效。
5. **必带频率限制**（`_rate_ok`，按 IP 计时）。防的是密钥被盗刷。
   上线前应换成按校区账号计，内存计数重启即清、多进程不共享。
6. **不注册 service worker。** 离线对批改无意义，而它的缓存会让老师一直看到
   旧版本，恰好撞上频繁改文案的上线初期。要补随时能补。

## 本机存档（IndexedDB）

**一份数据，两种寿命** —— 这是理解这一段的关键：

| | 存什么 | 留多久 | 为什么 |
|---|---|---|---|
| **历史** | 批语（`result`） | **永久**，老师自己在「以前批过的」里删 | 过几天还要能翻出来看、重出点评卡 |
| **暂存** | 压缩图（`blob`） | **一天**（`BLOB_TTL`），且一份批完就立刻丢 | 只为扛住「批一半被打断」；图是占空间的大头 |

所以历史里**看不到学生原稿**，只有批语——这是有意的：图只对「重批」和缩略图有用，
而重批只对 `err` 项开放，隔天再批也没意义。一课的历史只有几十 KB，几十课不到 1MB。

**不存**：原图（存的是 `shrink()` 后那张，200–500KB）；`createObjectURL` 的 url
（document 生命周期的，存下来刷新即成死链、只会让缩略图变裂图）。

**存在老师自己手机的浏览器沙盒里，不回传服务端，换手机就没有。** 服务端那条
「不落盘」红线不受影响——两层是分开的，别混成一句「什么都不存」。

### 结构

```
DB "lj_draft" v2
  items  keyPath:"key"  index "by_sid"   {key: sid+"#"+id, sid, id, status, result, error, blob?, ts}
  meta   keyPath:"k"    {k:"__cur", sid}          ← 当前是哪一课
                        {k:<sid>, sid, lesson_id, lesson_label, mock, created, updated, total, done}
```

### 五个不显然的设计

1. **主键是 `sid + "#" + id`。** `id` 不全局唯一（每开一课 `S.seq` 归零）。更要紧的是
   **记录自带身份**——认不出的残留可以无条件删，不依赖上次清理有没有跑完。
2. **`meta` 里 `__cur` 与各课并存。** 一条指针 + 每课一条，历史列表就是把 `__cur`
   滤掉之后按 `updated` 倒序。
3. **打开历史前必须校验 `mock`。** `makeCard()` 读的是**当前** `S.mock`：拿演示模式
   批的东西在真实模式下出图，点评卡会少掉「非真实批改」水印却带着品牌落款——
   那是能发进家长群的对外事故。对不上就不给开，只让删。
4. **`S.seq` 恢复时取 `max(id)`，不能用 `length`。** 无图的幽灵项会被丢弃，length
   小于最大 id，新拍的照片就会拿到已存在的 id；`renderQueue` 用 `data-id` 反查，
   撞了会**点开另一个学生的批语**，然后老师把 A 的点评卡发给 B 的家长。
5. **启动时只为「还批得动的」弹框**（没批完 + 图还在）。已经批完的那些进历史，
   老师想看自己会去点，不该一开就弹。而且「先不批」**不删任何东西**。

### 失败一律静默退化

存档是锦上添花，**任何时候都不能挡住批改**。

- **可用性探测不能只判 `"indexedDB" in window`**。微信内置浏览器（WKWebView）的
  失败形态是**挂住不返回**，所以每步都带超时。超时取 3 秒而不是 1.5 秒：页面刚
  加载时事件循环最忙，太紧会把「慢」误判成「坏」（`idb-probe.html` 实测过，
  1.5 秒会误杀本机 Chrome）。
- 探测失败记进 `localStorage`，但**只认 7 天且 UA 要对得上**——老师从微信切到
  Safari、或系统升级了，都该重新给一次机会，不能因为一天不顺就把设备永久拉黑。
- **配额两级降级**：第一次撞 `QuotaExceededError` 只停存照片、批语继续存；再撞才
  全停。⚠ 配额错误落在 `tx.onabort` / `tx.error` 上、**不是同步抛的**，只 catch
  同步异常会让配额满变成「静默什么都没存」，连降级都不触发。
- 所有 IDB 错误收敛在 `idbTx()` 一处 try/catch，各写入点一个 try 都不写。

**想知道某台手机能不能用，打开 `/idb-probe.html`**——独立的诊断页，测真实往返
（含「写得进读不出」这种坏 WebView 的典型症状），在微信里打开即可。

**0821 实测（iPhone · iOS 26.2 · 微信 8.0.75 内置浏览器）：六步全过，全流程 21ms**
（打开库 15ms、写 16ms、删 18ms、存取一张 300KB 的图 21ms）。原先担心的
「微信 WKWebView 的 IDB 有 bug」在这个组合上不成立。
⚠ 两点没被这次实测覆盖：**安卓微信用的是 X5 内核**（不是 WKWebView），结果不能外推；
以及 **iOS 的 `navigator.storage.estimate()` 问不到配额**——所以配额只能靠
`QuotaExceededError` 被动发现，那两级降级不是保险、是必需的。
