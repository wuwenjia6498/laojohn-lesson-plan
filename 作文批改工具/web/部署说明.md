# 部署说明 · 同步习作批改助手

写给要把这个服务放到线上的人。本机怎么跑见 `README.md`，这份只讲部署。

**现行部署方式是 Vercel，直接看第七节。**前六节讲的是自己拿一台服务器跑，两种方式的密钥、限额、检查口径通用，但**限额那一节在 Vercel 上结论是反的**（第四节末尾有说明），别照着配。

---

## 一、跑起来

```bash
pip install -r 作文批改工具/web/requirements.txt

export AIHUBMIX_API_KEY=sk-...        # 密钥只从环境变量进，别写进仓库
export LJ_ENV=prod                    # 生产模式，见下面第二节
export PORT=8000                      # 可选，默认 8000
python 作文批改工具/web/server/main.py
```

服务把前端静态文件挂在 `/`（`main.py` 末尾的 `app.mount`），所以**一个进程同时供前端和 API**，不需要单独部署前端。

host 硬编码 `0.0.0.0`，只有端口能配（`PORT` 环境变量）。

**必须单进程跑。** 见第四节。

---

## 二、`LJ_ENV=prod` 是必须设的，别省

不设的话，**没配密钥服务照样起得来**，接口返回结构完整的**假批语**（mock 模式），日志里只有一行提示，前端毫无异样——老师会把假批语当真的转给家长。

设了 `LJ_ENV=prod` 之后，无密钥直接拒绝启动并打清楚的原因。本地开发不设这个变量，行为跟以前完全一样（无密钥自动 mock，方便点流程）。

判断当前模式：`curl -s http://<host>/api/health` 看 `"mock"` 字段，`false` 才是真在打模型。

---

## 三、密钥怎么进

优先级从低到高：

1. `main.py` 里的代码默认值（空）
2. `server/config.json`（**已 gitignore，永不入库**）
3. 环境变量 `AIHUBMIX_API_KEY` ← 最高

线上**用环境变量**，不要往服务器上放 `config.json`。仓里的 `config.example.json` 是模板，可入库，里面没有真密钥。

其余可配项（都在 `config.json` 或代码默认值里，没有对应的环境变量）：

| 键 | 默认 | 说明 |
|---|---|---|
| `base_url` | `https://aihubmix.com/v1` | 模型网关 |
| `grade_model` | `gpt-4o` | 0820 实测选定，换模型要重跑 `run_regression.py` |
| `rate_limit_per_hour` | 120 | 见第四节 |
| `max_image_mb` | 8 | 超过直接 413，不进模型 |
| `trust_proxy` | `false` | 见第四节 |

## 四、限额：内存版，所以只能单进程

`_rate_ok()` 用的是模块级的 `defaultdict(deque)`：

- **重启即清**——服务一重启，所有人的额度都归零；
- **多进程不共享**——开 4 个 worker 就等于额度变成 4 倍，形同虚设。

所以**现在只能单进程跑**（`uvicorn.run` 没有 `workers` 参数，别自己加）。要横向扩容，得先把限额换成外部存储（Redis 之类）或按账号计。

限额挂在 `/api/grade` 和 `/api/diagnose` 两条上，**共用同一个桶**（两条都是真实模型调用）。

### ⚠ 在 Vercel（Serverless）上这个限额等于没有

上面说的「单进程」在 Vercel 上根本不成立：每个请求可能落到不同的函数实例，
每个实例一个自己的桶，冷启动即清零。**打一次换一个实例，累计不起来。**

所以 Vercel 部署靠的不是它，而是**访问口令**（`LJ_ACCESS_CODE`，见第七节）——
挡的是「链接被转发出去，谁拿到谁能烧我们的模型额度」。内存桶留着当聊胜于无的兜底。

真要精确限额（按校区出账单那种），得换成外部存储（Redis/Vercel KV）或按账号计，
那是另一轮开发，见第五节。

### 上了反向代理，必须开 `trust_proxy`

不开的话，`request.client.host` 拿到的是**反代自己的 IP**，全站共用一个桶——一个校区批到 120 份，全国老师都被挡在门外。

开了之后取 `X-Forwarded-For` 的**最左一跳**（最初的客户端）。

⚠ **没有反代就不要开**：这个头客户端能随便伪造，开了等于把限额敞开——每次请求换一个伪造 IP 就绕过去了。默认关是有意的。

配置方式：`config.json` 里加 `"trust_proxy": true`。

反代那边要把这两个头传下来：

```nginx
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header Host $host;
```

## 五、这个版本明确没做的事

| 没做的 | 后果 | 什么时候必须做 |
|---|---|---|
| **按校区账号计额度** | 现在只按 IP 计。同一校区共用出口 IP 会互相挤占；换个网络就重置 | 一旦按校区收费或要出用量账单 |
| 账号体系、登录 | 谁都能打开就用 | 同上 |
| 历史记录、成绩单 | 关掉页面批改结果就没了 | 老师提出要回看时 |
| 限额持久化 | 重启即清 | 要多进程或多机部署时 |

前三条是 MVP 阶段有意不做的（见 `README.md`），第四条是上一节说的那个约束。

## 六、上线前的检查

```bash
# 0. 看哪些包已人工确认——只有已确认的会被打包上线（闸门口径见下面 ⚠）
PYTHONUTF8=1 python 作文批改工具/confirm_pack.py --list

# 1. 标准包全过（一个包 JSON 坏掉，整个服务起不来）
PYTHONUTF8=1 python 作文批改工具/validate_packs.py

# 2. 起服务后确认不是 mock
curl -s http://<host>/api/health
#    期望 "mock": false，"lessons" 是你预期的课次数

# 3. 确认限额真的在
#    连打超过 rate_limit_per_hour 次 /api/grade，应返回 429

# 4. 拿一张真稿纸打一次，看批语像不像话
PYTHONUTF8=1 python 作文批改工具/web/server/smoke_real.py <稿纸.jpg> [lesson_id]
```

第 4 步机器只核四件（判据齐整／点评卡真引了原句／卡字数／姓名留空是对的），**判得准不准要人读**。

⚠ **上线闸门（2026-09-07 起）**：`build_deploy.py` 只打包 `source.verified_by_human` 为 `true` 的标准包，**未确认的不上线，已在线的也会随下次部署下线**。`true` 的含义是「判据已人工逐句对着详案核过，且允许上线」——判据抄错一句，那个班的批语会整批跟着错，而且从产出上看不出来。确认动作只走一条命令：

```bash
PYTHONUTF8=1 python 作文批改工具/confirm_pack.py <包名或lesson_id> --by <确认人>   # 确认
PYTHONUTF8=1 python 作文批改工具/confirm_pack.py <包名> --revoke                    # 撤销（下次部署即下线）
```

它会先查 `作文批改工具/标准包核对清单/` 里有没有这课的凭据、再对这个包跑 `validate_packs.py` 到 0 FAIL（详案改过之后判据「查无此句」就是 FAIL，包没跟上详案不许上线），都过了才写入确认人与日期。手改 JSON 翻 `true` 而不带确认人/日期，validate E26 会拦。**不想上线的课，不确认即可**，不需要另立清单。

## 七、部署到 Vercel（现行方案）

### 7.1 一次性准备

```bash
npm i -g vercel        # 本机已装 Vercel CLI 56.5.0
vercel login           # 已登录 wuwenjia6498
```

### 7.2 每次部署（三步，顺序不能换）

```bash
cd 作文批改工具/web

# ① 确认：要上线的包逐个确认过（见第六节 ⚠），看一眼状态
PYTHONUTF8=1 python ../confirm_pack.py --list

# ② 打包：只收已确认的包；会列出「本次新上线 / 本次下线 / 内容有改动」，敲 y 才写盘
#    （0 个包已确认时拒绝出空包；--dry-run 只看清单；被脚本调用时须 --yes）
PYTHONUTF8=1 python build_deploy.py

# ③ 上传
vercel --prod
```

**第 ② 步漏掉不会报错**——线上会继续用上一次打包的标准包，你改的判据一个字都没上去。
改完标准包或 `build_prompt.py`，必须重跑一次再部署。

### 7.3 为什么要打包这一步

线上部署根是 `web/`，够不到上一级的 `../标准包/` 和 `../build_prompt.py`。
而且标准包文件名里有中文和全角引号（`小小“动物园”.json`、`我和＿＿过一天.json`），
要经 git → Vercel 构建机 → Lambda zip 三道手，任何一道对非 ASCII 文件名处理不一致
就静默少一课。所以合并成单个 `_bundle/_packs.json`，**线上不依赖任何中文文件名**。

### 7.4 入口为什么必须是 `web/index.py`，不能放 `api/`

Vercel 的 Python 预设认「部署根下的 `index.py` 里的顶层 `app`」，认出来之后
**把所有请求都路由给它**——API 和前端静态都走这一个函数，和本机
`python server/main.py` 的行为完全一致。所以不需要 `rewrites`，`vercel.json` 里
只配 `functions.index.py.maxDuration`。

⚠ **别把入口放进 `api/` 目录**。那个目录名在 Vercel 上是另一套语义：
「一个文件一个端点」的旧式文件路由。2026-08-24 第一次部署就踩了这个坑——
入口放在 `api/index.py`、再用 `rewrites` 把 `/api/(.*)` 指过去，结果**所有
`/api/*` 请求的路径都塌缩成 `/api/index`**，FastAPI 一个路由都匹配不上，
表现是：首页正常、`/api/health` 却返回 401（中间件看到的路径不是 `/api/health`），
带对口令的 `/api/lessons` 返回 `{"detail":"Not Found"}`。
打包目录同理避开这个名字，叫 `_bundle/`。

`index.py` 只是把 `server/main.py` 导进来的薄壳。**别往它里面写逻辑**，
否则本地跑和线上跑成了两套代码，而且只有线上会坏。

### 7.5 环境变量（在 Vercel 项目设置里配，三个都要）

| 变量 | 值 | 漏配的后果 |
|---|---|---|
| `AIHUBMIX_API_KEY` | 密钥 | 配合下一条会拒绝启动（这是好事） |
| `LJ_ENV` | `prod` | **漏了最危险**：无密钥时静默发假批语，前端毫无异样 |
| `LJ_ACCESS_CODE` | 自定口令 | 链接一转发，谁都能用、烧我们的额度 |

⚠ **不要在服务器上放 `config.json`**。它已在 `.vercelignore` 里挡掉了——
注意 vercel CLI **不看 `.gitignore`**，只看 `.vercelignore`，这行删了密钥就会进部署包。

### 7.6 平台限制（已经按这些值配好，别乱改）

| 限制 | 值 | 我们的情况 |
|---|---|---|
| 函数最长执行 | Hobby 300s（默认即最大） | 实测一次批改约 60s，够 |
| 请求体 | 4.5MB 硬限 | 前端压到长边 1600 约 300KB；`max_image_mb` 已从 8 调到 4 |
| 部署包 | Python 500MB | 我们几 MB |

`max_image_mb` 别再调回 8：超过 4.5MB 在平台层就被挡，函数根本不会被调起，
我们自己那句「请在手机上压一压」的提示永远轮不到显示。

### 7.7 域名与 Cloudflare

1. Vercel 项目 → Settings → Domains，加你的域名
2. **记录值以 Vercel 项目页 Domains → `View DNS configuration` 给出的为准**，
   那里给的是**项目专属 CNAME**（形如 `cac041b57669b9da.vercel-dns-017.com`），
   Proxy 选 Disabled（灰云）。
   ⚠ **别用 CLI `vercel domains inspect` 给的 `A 76.76.21.21`**——CLI 文案比网页端旧，
   Vercel 网页端明说「We're expanding our IP range」，`76.76.21.21` 与
   `cname.vercel-dns.com` 都属 legacy（仍可用、但项目页会一直挂黄色
   `DNS Change Recommended` 警告，且 Vercel 扩 IP 段时要你手动跟进）。
   2026-08-24 首次配域名就是先配了 A、再按网页端建议换成 CNAME 的。
3. **Cloudflare 的 SSL/TLS 模式必须是 Full 或 Full(strict)**——Flexible 会和 Vercel 的
   强制 HTTPS 打架，表现为无限重定向
4. 如果开橙云（代理），要把 `LJ_TRUST_PROXY=1` 也配上，否则日志里看到的全是代理 IP

⚠ **国内访问是这套方案的最大风险**：`*.vercel.app` 在国内基本打不开，
挂了自定义域名也只是能打开、不保证快，Cloudflare 国内节点同样慢。
加盟商反馈「转圈/打不开」时，先怀疑这里，不是代码问题。

### 7.8 上线后必查

```bash
curl -s https://<你的域名>/api/health
```

期望：`"mock": false`（真在打模型）、`"auth": true`（口令生效）、`"lessons": 14`。

**`"mock": true` 就立刻停掉**——那说明密钥没读到，老师会拿到假批语。

然后手机上开一次，确认弹口令框、输对能进、拿一张真稿纸批一份看批语像不像话。
