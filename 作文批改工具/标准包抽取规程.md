# 标准包抽取规程

把一篇写作课详案变成一份 `标准包/<年级册>-第N单元-<题目>.json`。

**这份规程管判断，`validate_packs.py` 管格式。** 脚本只回答「你填的这句话是不是详案里的原话」，不回答「你填的是不是该填的那句」——后者只能靠人，凭据是每课一份的核对清单。

抽完必须：`PYTHONUTF8=1 python 作文批改工具/validate_packs.py` 跑到 **0 失败**。

---

## 零、一条会反复咬人的纪律

`PACKS = load_packs()` 是 `main.py:108` 模块加载时的**快照**，而 `uvicorn --reload` 只监听 `.py`、**不监听 `.json`**。改完标准包不重启服务，页面显示的永远是旧数据**且毫无提示**。

固定流程：**改 JSON → 跑 validate → 重启服务 → 看 `/api/health` 的 `lessons` 数字对不对**。

还有一条连带事实：`load_packs()` 遇到语法坏掉的 JSON 是**直接抛异常**，不是跳过那一个包——**一个包写坏，整个服务起不来**，不是只丢那一课。`validate_packs.py` 会先把每个包单独解析一遍再载服务端，所以它能告诉你是哪个包坏了；**别跳过 validate 直接重启**，那时你只会看到一堆 traceback。

## 一、三条判据怎么定位（本规程最难的一处）

### 先破一个想当然

「三条」在不同详案里指的**不是同一样东西**。实读九篇：

| 详案里的原话 | 「三条」实指 |
|---|---|
| 猜猜他是谁：改之前，我们先看三条：第一，…；第二，… | 判据（分号列举） |
| 续写故事：心里装着三条：接住前文没有，往下想得合不合理，… | 判据（**无序号、逗号并列**） |
| 我来编童话：对着三个问题过一遍：…第三，冒号、引号用对没有？ | 判据，**但第③条是标点** |
| 这儿真美：对照三条标准，自己改自己的稿 | **三档表格**，本课无独立判据 |
| 小小动物园 · 写观察日记：参照三条标准，重点修改**三处内容** | 三条标准＝档位；**三处才是判据** |
| 我和＿＿过一天：对着这三条看看走到哪一步 | 档位；后面的 bullet 是修改动作**不是判据** |

固定串「先看三条」只有《猜猜他是谁》命中，其余全为 0。关键词「三条」噪音极大（每组说满三条、添波折路子有三条、三条推荐理由）。

**所以：不要搜关键词，要通读第2课时。**

### 三级定位阶梯（逐课在 `notes` 记明用了哪一级）

**Tier A —— 老师当堂说的自查问句串。** 首选。两个锚点，先看第一个：

- **锚点一（修改收束）**：找 `〖PPT 第N页 · 修改收束` 这一行，往下 1–8 行内的 `师：` 段。串首标志词 `三条 / 三点 / 三个问题 / 三处内容`。
- **锚点二（自由写作前）**：找 `〖PPT 第N页 · 自由写作` 这一行下的「盯住这三件事／留意三点／盯住这两样」类师话（2026-08-21 补，《写观察日记》《我和＿＿过一天》两课都取自这里）。**四上各课的修改收束多半写成动作式或条件式，这个锚点反而更好用**——学生动笔前刚听过，且是正面陈述。
- 切分：优先按 `第一，…；第二，…；第三，…` 切；无序号时按顿号逗号并列切。
- **尾部的修改动作要砍掉**——「缺了补上」「就用忽然添个麻烦」是*怎么改*，不是*判什么*。判据必须是可回答是/否的判断项。

**⚠ 方向必须三条一致（2026-08-21 立 · 四上三课连撞）。** 四上多篇的修改收束写成**反面条件式**：

> 第二，**如果**段落里存在和动物特质不相契合的内容，可以直接删去……

砍掉动作后剩下「存在不相契合的内容」——**达成这条反而是坏事**，与其余两条方向相反，模型极易判反。遇到这种，**去详案里另找同义的正面原话**（锚点二、第1课时教师总结、示范文环节的核心要求，都是常见出处），反面表述转写进 `anti_patterns` 与该条 `judge_by` 的反例段，判定内容不会丢。**notes 与核对清单必须写明换了来源、来自哪一行、为什么换。**

**Tier B —— 该环节档位表的「自检的话」一列。** Tier A 缺失，或 Tier A 只有祈使动作时用。

- 这一列是第一人称、投屏给学生看过的，仍属「学生当堂听过的原话」，可用。
- **取「良好达标」那一档，按并列成分切三条**（2026-08-21《这儿真美》实操定）。理由：它正是达标线，且这一档往往把核心技法几项说全了；基础档太粗（只说「有几样景物」），优秀档掺进了「3–4 样」「用上好词或比喻」这类超出技法的加分项，拿它当判据会把达标线抬高。
- **第一人称的「我」字保留**，删了就不是原话了。
- 副作用：`three_checks` 会与 `bands` 的良好达标档文字重复——因为判据就是从那一档切出来的。这是固有结果不是抄错，`notes` 必须记明，并写清两者用途不同：`judge_by` 判**单条**（未达成／部分达成／达成），`bands` 判**整篇**落在哪一档；一篇可以三条全是部分达成，整篇仍落基础档。

**⚠ 取良好达标档这个缺省做法有边界（2026-08-21《我和＿＿过一天》撞出）。** 先切一遍看两件事：**每条够不够 6 字**（不够 validate 的 B9 直接 FAIL），**覆盖不覆盖得住核心技法各项**。那一课切出来是「他的动作／他说的一句话／我心里的想法」——三条都太短，且只覆盖技法第二项，漏掉了本课的灵魂（非他不可的事）。

这时**不要硬用**，改成挑着组：判据要与核心技法各项一一对应，来源可以跨档、跨环节，只要每条都是详案里老师说过的原话。那一课最后是第①②条取自由写作前的师话、第③条取档位表基础档——三条对齐了技法，且只有一条与 `bands` 重复。**核对清单里要把这个组合过程写清楚，这是最需要人复核的一处。**

**Tier C —— 提纲表「核心技法」按顿号破折号拆成 2–3 个并列成分。** A、B 都不成立时才用。

- `notes` 必须写明「本课详案无当堂三条，判据由核心技法拆出」。
- 核对清单里列为**红色必核项**。

### ⚠ 自查表给的条数不是 3 条时（2026-08-26《我的家人》立）

`three_checks` 硬性 3 条（B9 是 FAIL 级），但详案的自查表不保证正好三条——《我的家人》给的是**四条**。

**别急着砍。先把每一条读一遍，分辨它说的是「验什么」还是「怎么验」。**

那一课的第四条「能不能认出这个人／把开头那句话盖住，只读事情也能看出人物特点」——它不是与前三条并列的判断项，而是判第①条「有没有一件完整的小事」写没写足的**办法**。这正是 judge_by 第一段「怎么找证据」要的东西，**并进去，不单列**，技法一项不丢。

反过来说，如果四条真是四个互不相容的判断项，那就只能取三条并在 `notes` 与核对清单里写明**放弃了哪一条、为什么它最可省**——这时按 §八 ① 的覆盖度自问倒查一遍：放弃的那条若对应着核心技法某一项，就不能放弃，得换一条让位。

## 二、judge_by 怎么写

`three_checks[].text` 是**逐字铁律**（学生当堂听过，批语可直接引原话，改一个字就不是原话了）。
`judge_by` 相反——它是给模型看的操作化说明，**必须自己写**，且必须量化。

来源是实测教训：《猜猜他是谁》第②条原先只问「有没有画面」，gpt-4o 与 gemini-flash **都**把「只有一处、一两句带过」判成达成。

**三段模板，缺一不可：**

```
① 怎么找证据：<数什么／看哪里>
② 三级门槛：一处也没有／通篇是结论句 → 未达成；
            只有一处且一两句带过 → 部分达成；
            两处以上、或一处写透 → 达成
③ 什么不算：<举一个最容易被误当成达成的反例>
```

没有「几处／几段／几件／两处以上」这类可数说法，或没有「什么不算」的反例，**这条 judge_by 就是没写完**。`validate_packs.py` 的 B12 会提醒，但它只报 WARN——措辞千变万化，机器判不死。

### ⚠ 放宽条款必须前置到判定最开头（2026-08-21 实测立）

**「这种情况不扣分／不算数／不在本条范围」这类条款，写在末尾的「什么不算」段里，模型读不到——它读到中间的三级门槛就已经下判断了。**

《写观察日记》第②条实测：judge_by 末尾明写「第一则没有对比对象，把初始样子写清楚就算达成，不要按缺对比扣它」，模型照样判「第一则中没有明确指出之前的状态对比」。把同一句话提到判定最前面、写成独立分支后，同一张稿纸重跑，模型改口成「第二则和第三则……」，**第一则不再被提及**。

写法：

```
**判之前先排除<某种情形>**：<为什么它不该扣>，**它不参与下面的扣分，
也不许写成“<模型最可能写出的那句错话>”**——那是详案要求的正确写法，扣它就是误判。
其余各则：<正常的三级门槛>
**什么不算**：<收紧类反例照旧放末尾>
```

**分清两类，别一锅端**：
- **收紧类**（「X 不算达成」）放末尾没问题，模型判完还会回头对一遍；
- **放宽类**（「X 不扣分／不在本条范围」）必须前置——它改变的是判定对象本身，晚了就来不及。

### ⚠ 判「逐项齐不齐」时，先让模型把各项抄出来再数

同一次实测：第①条判日期／星期／天气三样齐不齐，模型笼统地答「第一则和第二则没有标明天气」——**而第一则明明写着「晴」**。这条错直接进了家长点评卡（「这次有两则日记少了天气」）。

把 judge_by 开头改成「**先把三则的头一行各自原样抄下来**，再逐则数……要指名道姓说第几则缺哪一样，不许笼统说有几则没写全」，重跑即准确。

**凡是判据形如「每一段／每一则都要有 X」，都照此写**：先枚举、后判定。笼统判断出的事实错误，比判错档位更伤——档位错老师看得出，事实错会被当成真的转给家长。

### 当 text 逐字受限、判不全技法时，用 judge_by 补

`text` 不能改，但它有时候只说了技法的一半。**这时不要去改 text，把口径补在 judge_by 里，并在 notes 写明补了什么、依据是详案哪一行。**

实例（《这儿真美》第③条）：text 逐字是「写了景物的颜色、形状」，而本课核心技法要的是**五感**。若只按字面判颜色形状，写了颜色却毫无声音气味的稿子会被判成达成——这是漏判。故 judge_by 按课上那三步（看清—凑近—加感觉）把判定口径扩展到声音、气味、触感，依据是详案里三步原文与旁批表六行。

**这正是 text 逐字、judge_by 可撰写的分工意义**：前者保证批语能引原话，后者保证判得准。

> **存量待办**：现有两包有 3 条 judge_by 缺反例段（B12 会报）。**Phase 0 反馈回来之前不要动它们**——judge_by 直接改变模型判定行为，改了就等于换了一把尺子，而 Phase 0 试用正是在测这把尺子。反馈回来后统一补。

### depends_on 逐课判断，禁默认

《猜猜他是谁》②依①（主特点都没抓住，「围绕它写具体」无从判起，记不适用）；《写日记》三条各自独立。**有或没有都要在 `notes` 写明理由**。

## 四、lesson_id 构造

```
<年级数字><a|b>-u<单元数字>-<题目拼音-小写-连字符分词>
```

| 课次 | lesson_id |
|---|---|
| 三上·三 续写故事 | `3a-u3-xuxie-gushi` |
| 三上·四 我来编童话 | `3a-u4-wolai-bian-tonghua` |
| 三上·六 这儿真美 | `3a-u6-zher-zhen-mei` |
| 四上·一 推荐一个好地方 | `4a-u1-tuijian-yige-haodifang` |
| 四上·二 小小动物园 | `4a-u2-xiaoxiao-dongwuyuan` |
| 四上·三 写观察日记 | `4a-u3-xie-guancha-riji` |
| 四上·四 我和＿＿过一天 | `4a-u4-wo-he-guo-yitian` |

拼音段只是人类可读标签，`grade_of()` 不看它；但仍须 `[a-z0-9-]+`，混入中文或大写日后做 URL／文件名会踩坑。

**排序完全靠 `<年级><册>-u<单元>` 这一段**，绝不靠文件名——`sorted(glob)` 会让「第十单元」排到「第二单元」前面。

⚠ **既有两包不追溯改名**。`3a-u2-xieriji` 的分词风格与本规则不一致，但 `lesson_id` 是前端 localStorage「最近用过」的键、也进了已发出的 Phase0 试用包文件名，改名会静默清掉老师本地的记录。新包按规则、旧包不动。

## 五、bands 键名归一化

**`bands` 的三个键统一写 `基础过关` / `良好达标` / `优秀进阶`，档位文字照抄详案。**

为什么必须统一：前端两处用**精确匹配** `bands.indexOf(r.band)` —— `app.js:357` 徽章配色（对不上回落蓝色）、`app.js:541` 汇总页三档计数（**对不上则三档全部计为 0**）。模型把「写得让人想去」输出成「让人想去」少两个字极常见，`indexOf` 返回 -1，**页面照常渲染、不报错、不报警**，老师看到的是「优秀 0 人 / 良好 0 人 / 过关 0 人」。

为什么可以统一（它不违反逐字铁律）：`bands` 是详案自己标明「教师掌握、不必念给学生」的**内部参考档位**，学生没听过、批语也不会引它的原话——逐字铁律的前提在这里不成立。而三上第三单元本来就没有档名（散文式「这是过关／…这就很出色了」），无论如何都得自拟；老师是跨课次批一整个学期的，档位名每课一变则汇总页读不成。

**原档位名记进 `notes` 与核对清单**，信息不丢。四上各课的自创档名（写成了／写好了／写得让人想去、基础完成／细节达标／人设贴合）都按此处理。

`validate_packs.py` 的 B11 是 FAIL 级硬校验。

## 六、not_in_scope 冲突处置

工具默认不判错别字、标点占格、开头空两格、卷面书写（识别手写稿时模型会自动纠正错别字，这一层判不准）。但**有的课，格式本身就是本课要教的东西**：

| 课次 | 冲突的判据 | 需要的 exceptions |
|---|---|---|
| 我来编童话 | 第③条「冒号、引号用对没有」 | 对话处的冒号、引号 |
| 写观察日记 | 第①条「补上缺失的日期、星期、天气」 | 第一行的日期／星期／天气 |

**判据照留**（那是本课教的东西），在 `not_in_scope.exceptions[]` 写一条豁免，句式照抄《写日记》既有先例：

> 对话处的冒号、引号——这是本课要教的对话写法，属三条判据之一，必须判。

其余五课无此冲突。

## 七、notes 必写项

1. 每个留空字段一条：`<字段名> 留空，因为<详案里没有这一项>`
2. `three_checks` 的 Tier 归属，及切分时砍掉了什么
3. `bands` 键名归一化：原档位名是什么
4. `depends_on` 的判断理由（有或没有都要写）
5. 详案里带「示范文为拟写、请老师换成自己的」类授课提示 → 必须记（决定 `model_essay_anchor_sentences` 能不能当全班共同背景引用，《写日记》有此先例）

`notes` **不进提示词**（`render_pack` 不消费它），是纯内部备注——但仍守全仓弯引号铁律，禁直角引号。

## 八、每课产出四项

1. `标准包/<年级册>-第N单元-<题目>.json`
2. `标准包核对清单/<年级册>-第N单元-<题目>-核对清单.md`，固定六节：
   - **① 覆盖度自问（第一项，必填）**：把三条 text 念一遍，回答「这三条判完，本课核心技法算不算判过了？」——**用核心技法反查判据，不是拿判据去凑**。方向反了就查不出遗漏。
   - ② 三条判据逐句核对：pack 值｜详案行号｜详案原文｜Tier
   - ③ bands 归一化对照：原档位名 → 标准键
   - ④ depends_on 判断与理由
   - ⑤ exceptions 与留空字段清单
   - ⑥ `validate_packs.py` 该包输出原样粘贴
3. 该课 validate **0 失败**
4. （按需）跑 `build_prompt.py` 出 Phase0 试用包——只在要给加盟商试用时做，不必每课都出

核对清单目录**不放进 `标准包/`**：`load_packs()` 只 glob `*.json` 不会误读 md，但保持 `PACK_DIR` 纯净，免得日后有人把 glob 改宽。

**`verified_by_human` 一律留 `false`。** 发给加盟商前须人工逐句核对——判据抄错一句，全班批语跟着错，且看不出来。

## 十、同一单元并存新旧两套教材题目时（2026-08-26 立 · 四上·二首例）

2026 秋统编四上第二单元习作由《小小“动物园”》换成《我的家人》。旧课全套产物按用户拍板**原地保留**，旧包也**留在线上**（还在教旧题的加盟商仍要用），于是同一年级同一单元下并列两个包。

**两个包各加一个 `edition` 对象**（其余课次没有此字段，前端不渲染徽章）：

```jsonc
"edition": { "status": "current", "note": "现行 · 2026 秋起" }   // 新题
"edition": { "status": "legacy",  "note": "旧版 · 2026 秋前" }   // 旧题
```

**`status` 与 `note` 是有意分开的**：`status` 供排序与配色（`main.py:sort_key`、`.tag.edition.old`），`note` 只是显示文案——改文案不会动到排序和样式。

### ⚠ 三条不可推断的

1. **版本标注绝不能塞进 `meta.topic` 或 `label`。** 那两个会经 `app.js` 的 canvas 画进**发给家长的点评卡**（`c.fillText(... l.label ...)`），家长会看到「《小小“动物园”》（旧版）」。徽章只走 `edition`、只出现在选课页。
2. **必须补排序键，否则新旧顺序不可控。** `grade_of` 返回 (年级, 册, 单元) 三元组，两个包完全相同，`ds.sort` 稳定排序就退化成 glob 顺序（本地）/ `_packs.json` 数组顺序（线上）——**旧题会排在现行题前面，且不报错**。故 `load_packs` 改用 `sort_key`＝三元组 ＋ 版本序（current/无标注 0、legacy 1）。
3. **不进提示词。** `build_prompt.render_pack` 不消费 `edition`，批改行为与不标注时逐字相同（已实测比对）。

落地涉及四处：两个包 JSON ／ `main.py`（`sort_key` ＋ `public_view` 下发）／ `frontend/app.js`（`lessonCard`）／`frontend/style.css`（`.tag.edition`）。改完照 §零 的固定流程走：validate → `build_deploy.py` → 重启/部署。
