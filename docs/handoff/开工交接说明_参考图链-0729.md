## 三、已确定的条件（不必重新验证）

### 3.1 已验证的措辞

小试二实测 2.79 头身，条件为：参考图 = `妆-01_小虎.png`，画风锁定。措辞主干：

> 沿用参考图的画风，与这个角色的身份特征——脸型、发型、主色、〔辨识锚〕。
> 身体比例不要跟随参考图，按下方文字为准。
>
> 【比例】头顶到下巴约占全身高的 25%，六七岁一年级新生模样；圆脸、脸颊有肉。

⚠ **25% 是控制输入，不是对画面的描述。实测输出约 35.8%。**
不要为"让文档自洽"把它改成 35%——会滑回 2.5。
落差不是固定偏移，是模型向自身先验（约 36~40% 占比）回拉：写入值离先验越远、落差越大。
不可按差值反推写入值。详见 `小试结论_头身比收口-0729.md` §三。

### 3.2 脚本现状（CC 已查证，附行号）

主图分支只有两条路（main() 1028–1040）：

| 条件 | ref 图 | ref_instr |
|---|---|---|
| `anchor_png` 存在且 ≠ 本格自己（＝组图非首格） | 本课 `主-01.png` | None → `generate_one` 缺省 → `_STYLE_REF_INSTR` |
| 其余（单主图课／组首格／重跑已存在的主-01） | `global_anchor` | `_ANCHOR_REF_INSTR`（1038 行） |

- 链路：1038 → `process_strict(ref_instr=…)`(755) → `generate_one`(329/338) → `_gen_gemini`(203) → 214 行 `prompt + (ref_instr or _STYLE_REF_INSTR)`
- 986–992：`anchor_png` 取第一个 `is_main` 的 spec，其 png 已存在就用它，然后**无条件 break**
- 三个 ref_instr 取值**全在代码里硬绑**（1036/1038/391 行），无 CLI 参数、无配置键。`load_config` 会把 json 任意键塞进 cfg，但无读取点
- `cfg['style_anchor']` → `anchor_ref()`(186–200) → `global_anchor`(980) → 全脚本仅 1038 行一个使用点
- 1047 行：练笔图恒走 `_STYLE_REF_INSTR`

**两条现存常量各废一半**（已确认，不必复测）：

- `_ANCHOR_REF_INSTR`：明说「不要沿用参考图中的角色」→ 用定妆图当参考时，角色跟不上
- `_STYLE_REF_INSTR`（161 行）：明令沿用「…**人物造型比例**与脸部画法…」→ 会把参考图的比例一起灌进来

### 3.3 参考图副本规格

- 母版 `assets/角色册/` **一个字节不动**
- 喂图用副本：长边缩至 1500 + 转 RGB（alpha 全不透明，整通道空转）
- 副本为**无损衍生**，不含内容修改。PS 改比例方案已否决，见负面清单

## 四、待设计：三级参考图链

三类参考图可能同时存在，需定优先级与组合规则：

| 级 | 参考图 | 承担 | 现有指令 |
|---|---|---|---|
| A | 画风锚图（`global_anchor`） | 画风基调 | `_ANCHOR_REF_INSTR`（明拒角色） |

**要答的问题**

1. 三者同时可用时谁压谁？是否允许多图同传？

   （C 的现有实现会把首格的一切连比例一起传下去；首格若已 2.8，组内一致，但组间是否一致未验证）
3. 动物角色（元宝／芝麻）无头身比，是否走同一条链？
4. `_CHAR_REF_INSTR` 落在哪一级、与 A/C 两条常量如何并存或替换
