- **`:982` 的「全期风格锚图已启用」也不打印**（`if global_anchor` 为假）。

**两条都不响 ＝ 静默停用。** 排查锚图相关问题时不要以日志无异常作为「锚图在工作」的依据。


`global_anchor` 为假 → `instr` 同为 `None`，**`_ANCHOR_REF_INSTR` 根本没被取出来**。

## 二、多格课 `anchor_png` 的取值与传递

### 2.1 赋值点有两处，不是一处

`:986-992` 只负责**开跑前的预置**；多格课真正的赋值来源是 **`:1042-1045`**：

```python
# :1042-1045，主图落盘之后
if anchor_png is None:
    cand = ip.image_path(args.md_path, s.code)
    if os.path.isfile(cand):
        anchor_png = cand
```

《开工交接说明》§3.2 只写了 `:986-992` 的「无条件 break」，**漏了这一处**。只看 `:986-992` 会得出
「冷启动时 `anchor_png` 恒为 None、组内后续格拿不到参考图」的错误结论。

### 2.2 四格课冷启动的完整走法

| 阶段 | `anchor_png` | 命中分支 | ref / ref_instr |
|---|---|---|---|
| `:986-992` 预置 | 取 `specs` 里**第一个** `is_main`（＝主-01，md 顺序）；其 png 不存在 → 保持 `None`，**随即无条件 `break`**，不会去看主-02 | — | — |
| 主-01 生成 | `None` | `:1035` 假 → `:1038` | `(None, None)` → 无参考图 |
| 主-01 落盘后 | `:1042-1045` 赋值为 `图位/主-01.png` | — | — |
| 主-02/03/04 | `主-01.png ≠ 本格路径` | **`:1035-1036` 成立** | `(主-01.png, None)` → `:214` 兜底 `_STYLE_REF_INSTR` |
| 练-01 | 同上 | `:1047` | `style_ref=主-01.png`，`ref_instr` 用默认 `None` → `_STYLE_REF_INSTR` |
| 备-0N | 同上 | `:1049` `process_alt` | 同上 |

### 2.3 三个补充事实

- **`targets` 排序稳定**：`:960-962` `sorted` 按 role 排（主图 0 ／ 练笔图 1 ／ 备选图 2），同 role 内保持 md 顺序。
  所以主图组恒按 主-01 → 主-02 → … 走，**基准固定为第一格、不随后续格漂移**（`:1041` 注释即此意）。
- **重跑已存在的主-01 会静默退回无参考图**：此时 `:986-992` 已把 `anchor_png` 置为主-01 自身，
  `:1035` 的 `!=` 守卫判假 → 落到 `:1038` → `(None, None)`。这是 `:1032-1034` 注释描述的情形。
- **`--only 主-02` 单跑仍拿得到参考图**：`:987` 遍历的是 `specs` 全集，**不是**被 `--only` 过滤后的 `targets`。

### 2.4 跨课共享：零

`anchor_png` 全部由 `ip.image_path(args.md_path, code)` 派生，落点是 `imgspec_parser.py:283-287` 的
`<详案目录>/<详案stem>/图位/`——**按详案分目录**，且一次调用只吃一个 `md_path`。

唯一的跨课机制是 `global_anchor`，而它当前为 `None`（§一）。
**结论：今天跨课之间没有任何画风或角色传递。**
