# 双人协作 · 同步说明

两台电脑、一个工作台。这份说明只讲**怎么让两边的内容始终对得上**，生产流程本身见 `README.md`。

---

## 一、第一次接入（只做一次）

新机器上第一次用这个工作台，按顺序走完这一节。**日常流程从第二节开始，这节做完就不用再看了。**

### 1. 先配 git 身份 —— 别照抄历史作者

新机器上没有 git 身份配置，提交会直接失败。这时候**不要照着 `git log` 里已有的作者去补**——那是另一个人的身份，补上去的结果是**你的提交全都署了对方的名**，`git log` 里再也分不清哪份稿是谁写的、谁审的。

配在**仓库局部**就行，不动你的全局配置：

```powershell
cd D:\laojohn-lesson-plan          # 换成你的实际路径

git config --local user.name  "<你的名字>"
git config --local user.email "<你注册 GitHub 用的邮箱>"

# 确认
git config --local user.name
git config --local user.email
```

邮箱**用你注册 GitHub 的那个**，一步到位。以后换邮箱会在历史里留下两个身份，很难收拾。

**如果配之前已经用错误身份提交过**：趁还没推上去，改回来只要一条命令——

```powershell
git commit --amend --reset-author --no-edit     # 只改最近一个提交
git log -1 --format="%an <%ae>  %s"             # 确认
```

> 错误身份的提交**不止一个**时，别自己动手，先说一声。改多个提交要重写历史，跟改一个完全是两回事。
> **推上去之后再改更麻烦**，所以这件事要趁早。

### 2. 拿仓库权限（在此之前 pull 和 push 都用不了）

**这是私有仓库**，没被邀请就什么都拉不动、推不上去——不是工具坏了。

1. 注册 GitHub 账号（用上面那个邮箱）。
2. 让仓库主人在 Settings → Collaborators 里邀请你，权限选 **Write**。
3. 去邮箱点接受。
4. 配认证，浏览器点两下即可：

```powershell
winget install GitHub.cli
gh auth login
```

> **等权限的这段时间照常干活。** 本地写、本地提交都没问题，攒着就行，权限一到一次性推上去。

### 3. 第一次同步 —— 先拉后推，顺序不能反

你手上这份是拷贝过来的快照，对方那边多半已经往前走了几个提交。**直接 push 会被拒**，必须先把自己的提交垫到对方的上面：

```powershell
git pull --rebase
git push
```

`git pull --rebase` 报冲突，八成撞在 `.gitignore` 或 `README.md` 上（这两个文件对方改过）——**取对方的版本**，那边更新。搞不定就把冲突信息整段贴给 Claude Code。

推完之后你才第一次拥有完整的仓库内容，包括这份说明的最新版和 `.claude\memory\`。接着做第四节的记忆联接，就算接入完成了。

**⚠ 这一步可能报「untracked working tree files would be overwritten」**，后面跟一长串插图/PPT 的文件名。原因不是出错，而是：`读书会原书插图\`、`写作课教材插图\`、`写作课件PPT输出\` 这三个目录**2026-08-20 才入库**，而你硬盘上那份拷贝里早就有同名文件了。git 不肯用仓库版本覆盖它不认识的文件，于是整次 pull 都停下。

内容完全一致的话 git 认得出来、会直接放行；报错就说明**至少有一张不一样**（你改过，或者你有仓库里没有的）。这么处理，不会丢东西：

```powershell
cd D:\laojohn-lesson-plan

# 1. 三个目录整体改名留底（不要删）
Rename-Item "读书会原书插图"   "读书会原书插图_bak"
Rename-Item "写作课教材插图"   "写作课教材插图_bak"
Rename-Item "写作课件PPT输出" "写作课件PPT输出_bak"

# 2. 现在没有冲突了，正常拉
git pull --rebase

# 3. 看看留底里有没有仓库里没有的文件（/L = 只列不动手）
robocopy "读书会原书插图_bak" "读书会原书插图" /E /L /XX /NJH /NJS
```

第 3 步列出来的就是**只有你有、仓库没有**的文件。一个都没有 → 直接删掉三个 `_bak`。有 → 说明那是你新增的图，把它们复制回正式目录，然后 `git add` 提交推上去，这样对方也能拿到。

> 三个目录的名字都要照上面改，不然换个目录又会撞一次。

## 二、每天就两条命令

```powershell
# 开工第一件事，雷打不动
git pull --rebase

# ……干活……

# 收工，或者要把稿子交给对方之前
git add -A

```

不确定该不该提交时，先跑 `git status --short` 看一眼。**输出里不该出现 docx / pdf / pptx / jpg**——那些是渲染产物，不进仓库（见第四节）。

> 记不住命令没关系：在 Claude Code 里直接说「拉一下最新的」「把今天的活提交推送」，它会代跑。

## 三、项目记忆（`memory`）：已自动同步，但要配一次

`memory` 里是 180 多份踩坑笔记——「机构课学生手边没有课本」「教师自拟例子的四条判据」这类跨课次通则。它是 Claude Code 每次开工都会读的东西，**分叉了就等于两人各自把同一个坑重踩一遍**。

现在它已经搬进仓库的 `.claude\memory\`，随 git 自动双向流动。但 Claude Code 只认用户目录下的固定位置，所以每台机器要把那个位置**换成指向仓库的目录联接**，配一次，此后再不用管。

```powershell
# 1. 先把本机已有的记忆并进仓库（只补仓库里没有的，绝不覆盖）
robocopy "C:\Users\<你的用户名>\.claude\projects\<路径编码>\memory" `
         "D:\laojohn-lesson-plan\.claude\memory" /E /XC /XN /XO

cd D:\laojohn-lesson-plan
git add .claude/memory
git commit -m "并入本机新增记忆"
git push

# 2. 原位置改名留底，换成目录联接
Rename-Item "C:\Users\<你的用户名>\.claude\projects\<路径编码>\memory" "memory_backup"
cmd /c mklink /J "C:\Users\<你的用户名>\.claude\projects\<路径编码>\memory" `
                 "D:\laojohn-lesson-plan\.claude\memory"
```

`<路径编码>` 由项目所在路径换算：**盘符的冒号和反斜杠都换成短横线**。项目放 `D:\laojohn-lesson-plan`，编码就是 `D--laojohn-lesson-plan`。

`mklink /J` 建的是目录联接，**不需要管理员权限**。确认第二步之后 `memory` 目录里能看到 `MEMORY.md`，就说明通了，`memory_backup` 可以删。

**怎么确认它真的通了**（`memory` 目录里能看到 `MEMORY.md` 只说明目录在，不说明写进去的东西会落到仓库）：

```powershell
# 1. 看它是不是联接、指向哪
Get-Item "C:\Users\<你的用户名>\.claude\projects\<路径编码>\memory" -Force |
  Select-Object Attributes, LinkType, Target
#    Attributes 里要有 ReparsePoint、LinkType 是 Junction、Target 指向项目里的 .claude\memory

# 2. 写入穿透测试：从用户目录这一侧写一个文件，看仓库那一侧认不认
New-Item "C:\Users\<你的用户名>\.claude\projects\<路径编码>\memory\_link_probe.md" -ItemType File
cd D:\laojohn-lesson-plan
git status --short .claude/memory      # 应报 ?? .claude/memory/_link_probe.md
# 测完把 _link_probe.md 删掉
```

> ⚠ **探针文件必须用 `.md`，不能用 `.tmp`**——`.gitignore` 里 `*.tmp` 是全局忽略的，
> 用 `.tmp` 做测试 `git status` 永远没反应，会让你误判成联接没通、白重建一次。

两侧文件数一致（而不是各算各的）也是个好旁证。确认无误后 `memory_backup` 可以删。

**两个坑：**

- **联接断了不报错**，表现只是 Claude Code「什么都不记得」。自检话术：问一句「这个项目有哪些跨技能硬约束」，答得出就是通的。
- **`MEMORY.md` 是唯一的高频冲突点**（两人都会往索引里加行）。冲突了**不要选边**，两边新增的行都留下，按现有分区归位就行。

## 四、什么走 git、什么不走

判据只有一条：**这东西引擎重渲得出来吗？** 渲得出来的不进仓库，渲不出来的一律进。

| 内容 | 通道 | 要不要管 |
|------|------|---------|
| 详案 md、书籍档案、各类 json、skill 规则、脚本、封面、图位 png | **git** | pull / push |
| 项目记忆 `memory\` | **git**（经目录联接） | 配一次，此后不用管 |
| 版权插图（`读书会原书插图\`、`写作课教材插图\`）、外部生成的 `写作课件PPT输出\` | **git** | pull / push，不用额外操作 |
| 渲染产物：docx / pdf / pptx / jpg / 渲染 html | **哪边都不走，各自本地重渲** | 见下 |

**产物为什么不同步**：它们都能从 md/json 源加引擎脚本重新渲染，塞进仓库只会让仓库膨胀、还容易出现两份不一致的成品。

**那三类大件为什么反而要进**：它们**重渲不出来**——两类是版权扫描件、一类是外部平台生成的 pptx。不进仓库就等于 git 覆盖不到，两台机器会静默分叉。2026-08-20 起改为直接入库（仓库是私有的，合计仅 80 MB）。**所以你不用配任何网盘，`git pull` 就带下来了。**

**这条会实际影响你**：对方审核修改的是详案 `.md`，你 pull 到的也只是 md。**要拿到最新 docx，得自己重渲一次**：

```powershell
$env:PYTHONUTF8=1
python .claude\skills\laojohn-lesson-plan\assets\md_to_laojohn_docx.py `
  "写作课详案输出\五上-第三单元-我想对您说-写作课详案.md" `
  --header-left "老约翰·同步习作" --header-right "写清楚·写生动·有章法"
```

> `--header-left` / `--header-right` **每次都必须带**。漏传会静默回落成读书会页眉，不报错。三条线各自的页眉值见 `CLAUDE.md` §3。

## 五、大件（版权插图 / 外部 PPT）：不用管，跟着 git 走

`读书会原书插图\`、`写作课教材插图\`、`写作课件PPT输出\` 这三个目录**已经在仓库里**，`git pull` 就带下来了，**不需要网盘、不需要跑任何脚本**。

新增了插图或外部 PPT，跟提交详案一样：

```powershell
git add -A
git commit -m "《XX》原书插图 12 张"
git push
```

**两条纪律：**

- **git 只进不出**——提交进去就永久留在历史里，撤销要重写全部历史、两台机器都得重新 clone。所以**别往这三个目录里放与备课无关的东西**，也别放临时试验的废图（返工的废版按 `.gitignore` 规则留本地即可）。
- **`_图单.md` 是取图凭据**，插图改名、增删都要同步改它，否则详案里的 `【图位:插-NN】` 会对不上。

> 旧版本的这一节讲的是「网盘 + `sync_assets.ps1` 同步脚本」。那套方案已于 2026-08-20 作废、脚本已删除——先后卡在 exFAT 移动硬盘建不了目录联接、以及本机 OneDrive 六年未登录成功且静默不同步。缘由记在 `CLAUDE.md` §8/§9，这里不重复。

## 六、出岔子了怎么办

**`git pull --rebase` 报冲突** —— 说明两人改了同一个文件的同一处。八成是 `MEMORY.md`，按「两边的行都保留」处理。要是撞在详案正文上，先在群里说一声确认谁的版本是新的，别闷头改。搞不定就把冲突信息整段贴给 Claude Code。

**push 被拒（`rejected`）** —— 对方先推了。先 `git pull --rebase` 再 `git push`。

**Claude Code 突然「什么都不记得」** —— 记忆联接断了。回第三节重建一次。

**配图版详案报「缺图待补」** —— 插图现在随 git 走，所以**先 `git pull` 一下**。拉完还报，就是真出问题了，**别当成正常现象放过去**：多半是图的文件名与该书 `_图单.md` 对不上，或者详案里 `【图位:插-NN】` 的编号写错。（旧口径说「换机器后报缺图是预期行为」，那是插图还没入库时的说法，**已作废**。）

**push 卡很久不动** —— 插图/PPT 这类二进制推起来慢，几十 MB 可能要十几分钟，属正常。真断了就重跑 `git push`，git 会从断点续传已有的对象、不会重来一遍。

**不小心把产物提交了** —— 别慌，说一声，让 Claude Code 用 `git rm --cached` 撤出来再补 ignore 规则。**不要用 `git add -f` 把产物强推回仓库**。

## 装机步骤：新克隆后必做两条（2026-09-20 立 · 每台机器各跑一次）

```bash
git config --local core.hooksPath .githooks                        # ① 大文件闸门
git config --local --add remote.origin.fetch '^refs/heads/backup/*'  # ② 挡住备份支
```

**两条都是 per-clone 的本地配置，不随仓库走**——换机器、重新 clone 都要重跑。

**② 为什么必须装**：远端挂着 `backup/pre-filter-20260920`（重写前的完整旧历史，观察期到 2026-10-04）。默认 fetch refspec `+refs/heads/*:refs/remotes/origin/*` 会把它整支拉到本地，**一次普通 `git pull` 就能把仓库从 301 MiB 撑回 635 MiB**（2026-09-20 B 机实测）。负向 refspec 需要 git ≥2.29。
装完自验：`git fetch origin` 后 `git for-each-ref refs/remotes/` 应只有 `origin/main`，`git count-objects -vH` 不变。
⚠ 负向 refspec **只管默认 fetch**，命令行显式写的 refspec 一律绕过它——要看备份支内容请用 `git ls-remote` 或另开临时 clone。

### ① 大文件闸门细则

**必须手动配**：`.git/hooks/` 不入库、换机器即失效，所以钩子放在入库的 `.githooks/`，靠 `core.hooksPath` 指过去。**新克隆仓库后第一件事就是跑这条**，否则闸门形同虚设。

`.githooks/pre-commit` 拦三类：

| 类型 | 规则 |
|---|---|
| 按名 | 路径含 `_历史/ _已失效 _作废 _废弃 _已删除`，或 `.zip/.rar/.7z` |
| 硬拦 | 暂存内容 ≥20MB，无例外（外部 pptx 终稿 13~22MB 按交付边界不回本仓） |
| 软拦 | 5–20MB，白名单外拦。白名单＝`读书会原书插图/`、`写作课教材插图/`、`写作课件PPT输出/`、`看图写话详案输出/**/图位/*.png` |

**为什么要它**：`.gitignore` 对**已跟踪文件不生效**，也拦不住 `git add -f`。0920 瘦身查出的 93MB 作废图，正是 0728 补了 `_历史/` 规则但文件早已入库，规则空转了两个月。钩子补的就是这个缺口。

逃生口（会在终端留痕，慎用）：`SKIP_BIGFILE=1 git commit ...`

自测：造个 25MB 临时文件 `git add -f` 后 commit，应被拦，再 `git reset`。
