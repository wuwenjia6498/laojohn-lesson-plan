# 双人协作 · 同步说明

两台电脑、一个工作台。这份说明只讲**怎么让两边的内容始终对得上**，生产流程本身见 `README.md`。

---

## 一、第一次接入（只做一次）

新机器上第一次用这个工作台，按顺序走完这一节。**日常流程从第二节开始，这节做完就不用再看了。**

### 1. 先配 git 身份 —— 别照抄历史作者

新机器上没有 git 身份配置，提交会直接失败。这时候**不要照着 `git log` 里已有的作者去补**——那是另一个人的身份，补上去的结果是**你的提交全都署了对方的名**，`git log` 里再也分不清哪份稿是谁写的、谁审的。

配在**仓库局部**就行，不动你的全局配置：

```powershell
cd D:\laojohn-lesson-plan          # 换成你的实际路径

git config --local user.name  "<你的名字>"
git config --local user.email "<你注册 GitHub 用的邮箱>"

# 确认
git config --local user.name
git config --local user.email
```

邮箱**用你注册 GitHub 的那个**，一步到位。以后换邮箱会在历史里留下两个身份，很难收拾。

**如果配之前已经用错误身份提交过**：趁还没推上去，改回来只要一条命令——

```powershell
git commit --amend --reset-author --no-edit     # 只改最近一个提交
git log -1 --format="%an <%ae>  %s"             # 确认
```

> 错误身份的提交**不止一个**时，别自己动手，先说一声。改多个提交要重写历史，跟改一个完全是两回事。
> **推上去之后再改更麻烦**，所以这件事要趁早。

### 2. 拿仓库权限（在此之前 pull 和 push 都用不了）

**这是私有仓库**，没被邀请就什么都拉不动、推不上去——不是工具坏了。

1. 注册 GitHub 账号（用上面那个邮箱）。
2. 让仓库主人在 Settings → Collaborators 里邀请你，权限选 **Write**。
3. 去邮箱点接受。
4. 配认证，浏览器点两下即可：

```powershell
winget install GitHub.cli
gh auth login
```

> **等权限的这段时间照常干活。** 本地写、本地提交都没问题，攒着就行，权限一到一次性推上去。

### 3. 第一次同步 —— 先拉后推，顺序不能反

你手上这份是拷贝过来的快照，对方那边多半已经往前走了几个提交。**直接 push 会被拒**，必须先把自己的提交垫到对方的上面：

```powershell
git pull --rebase
git push
```

`git pull --rebase` 报冲突，八成撞在 `.gitignore` 或 `README.md` 上（这两个文件对方改过）——**取对方的版本**，那边更新。搞不定就把冲突信息整段贴给 Claude Code。

推完之后你才第一次拥有完整的仓库内容，包括这份说明的最新版和 `.claude\memory\`。接着做第四节的记忆联接，就算接入完成了。

## 二、每天就两条命令

```powershell
# 开工第一件事，雷打不动
git pull --rebase

# ……干活……

# 收工，或者要把稿子交给对方之前
git add -A
git commit -m "[稿] 五上第三单元《我想对您说》详案粗稿，待审"
git push
```

不确定该不该提交时，先跑 `git status --short` 看一眼。**输出里不该出现 docx / pdf / pptx / jpg**——那些是渲染产物，不进仓库（见第五节）。

> 记不住命令没关系：在 Claude Code 里直接说「拉一下最新的」「把今天的活提交推送」，它会代跑。

---

## 三、交球：两件事

我们是**接力**——一人写粗稿，另一人审核优化。同一份稿子不会两人同时改，所以几乎不会冲突，但**必须让对方知道球在谁手上**。

**1. commit message 带前缀**

| 前缀 | 什么时候用 |
|------|-----------|
| `[稿]` | 粗稿写完，交给对方审 |
| `[审]` | 审核优化完成，交回原作者 |
| `[定]` | 定稿，成品齐了可以交付 |

**2. 改一行 `协作看板.md`**

仓库根目录那张表，写清条目、状态、球在谁手上。交球之前顺手改，一次十秒。

**这两件事都做了，对方 `git pull` 之后就知道该干什么了。**

## 四、项目记忆（`memory`）：已自动同步，但要配一次

`memory` 里是 180 多份踩坑笔记——「机构课学生手边没有课本」「教师自拟例子的四条判据」这类跨课次通则。它是 Claude Code 每次开工都会读的东西，**分叉了就等于两人各自把同一个坑重踩一遍**。

现在它已经搬进仓库的 `.claude\memory\`，随 git 自动双向流动。但 Claude Code 只认用户目录下的固定位置，所以每台机器要把那个位置**换成指向仓库的目录联接**，配一次，此后再不用管。

```powershell
# 1. 先把本机已有的记忆并进仓库（只补仓库里没有的，绝不覆盖）
robocopy "C:\Users\<你的用户名>\.claude\projects\<路径编码>\memory" `
         "D:\laojohn-lesson-plan\.claude\memory" /E /XC /XN /XO

cd D:\laojohn-lesson-plan
git add .claude/memory
git commit -m "并入本机新增记忆"
git push

# 2. 原位置改名留底，换成目录联接
Rename-Item "C:\Users\<你的用户名>\.claude\projects\<路径编码>\memory" "memory_backup"
cmd /c mklink /J "C:\Users\<你的用户名>\.claude\projects\<路径编码>\memory" `
                 "D:\laojohn-lesson-plan\.claude\memory"
```

`<路径编码>` 由项目所在路径换算：**盘符的冒号和反斜杠都换成短横线**。项目放 `D:\laojohn-lesson-plan`，编码就是 `D--laojohn-lesson-plan`。

`mklink /J` 建的是目录联接，**不需要管理员权限**。确认第二步之后 `memory` 目录里能看到 `MEMORY.md`，就说明通了，`memory_backup` 可以删。

**怎么确认它真的通了**（`memory` 目录里能看到 `MEMORY.md` 只说明目录在，不说明写进去的东西会落到仓库）：

```powershell
# 1. 看它是不是联接、指向哪
Get-Item "C:\Users\<你的用户名>\.claude\projects\<路径编码>\memory" -Force |
  Select-Object Attributes, LinkType, Target
#    Attributes 里要有 ReparsePoint、LinkType 是 Junction、Target 指向项目里的 .claude\memory

# 2. 写入穿透测试：从用户目录这一侧写一个文件，看仓库那一侧认不认
New-Item "C:\Users\<你的用户名>\.claude\projects\<路径编码>\memory\_link_probe.md" -ItemType File
cd D:\laojohn-lesson-plan
git status --short .claude/memory      # 应报 ?? .claude/memory/_link_probe.md
# 测完把 _link_probe.md 删掉
```

> ⚠ **探针文件必须用 `.md`，不能用 `.tmp`**——`.gitignore` 里 `*.tmp` 是全局忽略的，
> 用 `.tmp` 做测试 `git status` 永远没反应，会让你误判成联接没通、白重建一次。

两侧文件数一致（而不是各算各的）也是个好旁证。确认无误后 `memory_backup` 可以删。

**两个坑：**

- **联接断了不报错**，表现只是 Claude Code「什么都不记得」。自检话术：问一句「这个项目有哪些跨技能硬约束」，答得出就是通的。
- **`MEMORY.md` 是唯一的高频冲突点**（两人都会往索引里加行）。冲突了**不要选边**，两边新增的行都留下，按现有分区归位就行。

## 五、什么走 git、什么不走

| 内容 | 通道 | 要不要管 |
|------|------|---------|
| 详案 md、书籍档案、各类 json、skill 规则、脚本、封面、图位 png | **git** | pull / push |
| 项目记忆 `memory\` | **git**（经目录联接） | 配一次，此后不用管 |
| 版权插图（`读书会原书插图\`、`写作课教材插图\`）、外部生成的 `写作课件PPT输出\` | **网盘**（经目录联接） | 配一次，网盘后台自动同步 |
| 渲染产物：docx / pdf / pptx / jpg / 渲染 html | **哪边都不走，各自本地重渲** | 见下 |

**产物为什么不同步**：它们都能从 md/json 源加引擎脚本重新渲染，塞进仓库只会让仓库膨胀、还容易出现两份不一致的成品。

**这条会实际影响你**：对方审核修改的是详案 `.md`，你 pull 到的也只是 md。**要拿到最新 docx，得自己重渲一次**：

```powershell
$env:PYTHONUTF8=1
python .claude\skills\laojohn-lesson-plan\assets\md_to_laojohn_docx.py `
  "写作课详案输出\五上-第三单元-我想对您说-写作课详案.md" `
  --header-left "老约翰·同步习作" --header-right "写清楚·写生动·有章法"
```

> `--header-left` / `--header-right` **每次都必须带**。漏传会静默回落成读书会页眉，不报错。三条线各自的页眉值见 `CLAUDE.md` §3。

## 六、大件：网盘 + 目录联接

三个目录 git 管不了——两个是版权扫描件（不能进公开仓库），一个是外部平台生成的 PPT（本仓渲不出来）。它们走网盘共享文件夹，然后**在项目里挂成目录联接**，这样路径不变，所有脚本照常找得到：

```powershell
cd D:\laojohn-lesson-plan
Rename-Item "读书会原书插图" "读书会原书插图_backup"
cmd /c mklink /J "D:\laojohn-lesson-plan\读书会原书插图" `
                 "C:\Users\<你的用户名>\<网盘同步目录>\laojohn-共享大件\读书会原书插图"
```

`写作课教材插图`、`写作课件PPT输出` 同法。确认能正常渲染出配图版详案之后，再删 `_backup`。

**网盘两条纪律：**

- 各自只往**自己负责的书/课次**的子目录里放文件，避免网盘客户端生成「冲突副本」。
- 版权材料仅限内部备课，**不再行转发**。

## 七、出岔子了怎么办

**`git pull --rebase` 报冲突** —— 说明两人改了同一个文件的同一处。八成是 `MEMORY.md` 或 `协作看板.md`，这两个都按「两边的行都保留」处理。要是撞在详案正文上，先在群里说一声确认谁的版本是新的，别闷头改。搞不定就把冲突信息整段贴给 Claude Code。

**push 被拒（`rejected`）** —— 对方先推了。先 `git pull --rebase` 再 `git push`。

**Claude Code 突然「什么都不记得」** —— 记忆联接断了。回第四节重建一次。

**配图版详案报「缺图待补」** —— 网盘还没同步完，或者大件联接没生效／断了。回第六节检查。

**不小心把产物提交了** —— 别慌，说一声，让 Claude Code 用 `git rm --cached` 撤出来再补 ignore 规则。**不要用 `git add -f` 把产物强推回仓库**。
